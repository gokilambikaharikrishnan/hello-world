Q01 · Address vs Value — What a Pointer Actually Is

Background

Imagine a city of millions of houses. A house contains furniture (data). The house's street address is a pointer. When you give someone your address, you are not handing them your furniture — you are handing them a number that tells them where to find the furniture. A C pointer is exactly that: a variable that stores a memory address rather than the data itself.

Every variable the program creates occupies some bytes in RAM. The compiler assigns each variable a numeric address — the position of its first byte in memory. An int* stores one such address. Dereferencing the pointer (*p) means "go to that address and read/write the bytes there". The pointer type (int* vs char*) tells the CPU how many bytes to touch.

Without pointers, functions can only receive copies of data; with pointers they can reach back into the caller's memory and modify the original. This is the foundation of every pass-by-reference pattern in C.

Where You See This Passing large structs to functions without copying. A pointer is 4 or 8 bytes; copying a 200-byte struct is expensive. Returning multiple values from a function. C has one return value; pass extra output locations as pointers. Embedded: locating a peripheral at a fixed MMIO address. The UART data register lives at 0x40013804 — you need a pointer to reach it. Dynamic allocation with malloc. malloc returns the address of heap memory; you hold it in a pointer.
Building the Logic from Scratch
A pointer IS a number — just an integer that happens to represent a RAM address.
RAM (simplified 32-bit system): Address Value ------- ----- 0x2000 42 <-- int x = 42; lives here 0x2004 0x2000 <-- int *p = &x; lives here (holds address of x) int x = 42; /* x occupies bytes at address 0x2000 */ int *p = &x; /* p holds the number 0x2000 */ printf("%d", *p); /* go to 0x2000, read 4 bytes -> 42 */ *p = 99; /* go to 0x2000, write 4 bytes 99 */ /* x is now 99 */ On a 64-bit system p would be 8 bytes wide; on a 32-bit MCU 4 bytes.

The ampersand operator & computes the address of any variable. The star operator * follows an address to the data. These two operators are exact inverses: *(&x) == x always.


#include <stdio.h>

int main(void) {
    int x = 42;          /* compiler allocates 4 bytes for x somewhere in RAM  */
    int *p = &x;         /* &x = address-of x; p now holds that address        */

    printf("x     = %d\n",  x);   /* 42                           */
    printf("&x    = %p\n",  (void*)&x); /* e.g. 0x7ffc2000        */
    printf("p     = %p\n",  (void*)p);  /* same address as &x      */
    printf("*p    = %d\n",  *p);  /* follow pointer -> 42         */

    *p = 99;             /* write through the pointer -- changes x directly    */
    printf("x now = %d\n",  x);   /* 99 -- x changed via *p       */
    return 0;
}
Dry Run 
x stored at (say) 0x2000, value = 42
p stored at (say) 0x2004, value = 0x2000

printf x        -> reads 0x2000 -> 42
printf &x       -> computes address -> 0x2000
printf p        -> reads 0x2004 -> 0x2000
printf *p       -> reads address stored in p (0x2000) -> 42
*p = 99         -> writes 99 to address 0x2000
printf x        -> reads 0x2000 -> 99   (changed!)
Gotcha

Never dereference an uninitialized pointer. int *p; *p = 5; writes to whatever random address happens to be in p — instant undefined behavior, crash, or silent data corruption. Always initialize: int *p = &x; or int *p = NULL; then check before use.

  3. What does &(*p) evaluate to, and why?
Variable holds address, not data -> it's a pointer. Dereference with * to reach the data.
  • Need to modify caller's variable -> pass pointer &var
  • Need to reach a fixed MMIO address -> cast that address to a typed pointer
  • malloc returns void* -> assign to correct pointer type

Q02 · Dereferencing — Reading and Writing Through a Pointer

Background

Dereferencing is the act of following a pointer to the memory it points to. Think of it like a treasure map: the pointer is the map (it tells you where the treasure is), and dereferencing is the act of going to that location and picking up (or placing) the treasure. The unary * operator is used both to declare a pointer variable and to dereference it — context determines which meaning applies.

When you write int *p in a declaration, the * means "p is a pointer to int". When you write *p in an expression, the * means "go to the address stored in p and access the int there". This dual use is one of C's most confusing syntax choices for beginners.

In embedded C, dereferencing is how you read a sensor register or set a GPIO output. The hardware peripheral's register is just RAM at a fixed address — you dereference a pointer to that address to interact with the hardware.

Where You See This Reading a hardware register: uint32_t val = *GPIOA_IDR; The register lives at a fixed address; dereference reads the current pin states. Modifying a struct field through a pointer: (*node).val = 5; or node->val = 5; Arrow operator is syntactic sugar for dereference + field access. Swap via pointers: passing addresses to a swap function. Without dereferencing, the swap would only affect local copies.
Building the Logic from Scratch
In declaration: * means "pointer to". In expression: * means "go to the address and access the data".
int x = 10, y = 20; int *p = &x; /* declaration: p is a pointer-to-int */ READ: int v = *p; /* expression: follow p, read 4 bytes -> 10 */ WRITE: *p = 99; /* expression: follow p, write 4 bytes 99 */ /* x is now 99 */ REASSIGN POINTER: p = &y; /* p now points to y (0x2004), NOT writing through */ *p = 77; /* now writes to y; y becomes 77 */ ARROW SUGAR: struct Node { int val; struct Node *next; }; struct Node n = {5, NULL}; struct Node *np = &n; (*np).val == np->val /* identical; arrow is just cleaner */

A read dereference (int v = *p) is a load instruction. A write dereference (*p = v) is a store instruction. In embedded development with volatile pointers, both generate actual memory bus transactions — the optimizer cannot cache the value in a register.


#include <stdio.h>

/* swap via pointer dereference -- classic interview question */
void swap(int *a, int *b) {
    int tmp = *a;  /* read through a                */
    *a = *b;       /* write through a from b's value */
    *b = tmp;      /* write through b from saved tmp */
}

int main(void) {
    int x = 3, y = 7;
    printf("before: x=%d y=%d\n", x, y);
    swap(&x, &y);  /* pass addresses, not values    */
    printf("after:  x=%d y=%d\n", x, y);
    return 0;
}
Dry Run — swap(&x, &y) where x=3, y=7 
a = 0x2000 (address of x), b = 0x2004 (address of y)
tmp = *a  -> read 0x2000 -> tmp = 3
*a  = *b  -> read 0x2004 (7), write to 0x2000 -> x = 7
*b  = tmp -> write 3 to 0x2004 -> y = 3
return: x=7, y=3
Gotcha

p = &y changes where p points — it does NOT write through p. Only *p = &y (which is a type error anyway) or *p = y writes through the pointer. This distinction trips up nearly every C beginner.

Confidence Check
  1. After int x=5; int *p=&x; p++; what does *p read? Is this safe?
  2. Why does swap(x, y) (without &) fail to exchange x and y?
  3. What is the difference between *p = 0 and p = 0?
Need to read/write the data AT an address -> dereference with *. Need to change WHERE the pointer points -> assign the pointer itself.
  • Read register -> val = *REG_ADDR
  • Modify via pointer -> *ptr = new_val
  • Struct through pointer -> ptr->field (same as (*ptr).field)

Q03 · Pointer Arithmetic — Why ptr+1 Moves by sizeof(*ptr)

Background

Imagine a street where all houses are 4 metres wide and numbered consecutively. "House 3" means the house whose left edge is at position 3*4 = 12 metres from the start. When you say "next house" (house 3+1 = house 4), you physically move 4 metres, not 1 metre. C pointer arithmetic works exactly the same way: adding 1 to a pointer moves it forward by one element, not one byte. The size of that element is the sizeof the pointed-to type.

This scaling is automatic and intentional. It lets you walk arrays with ptr++ regardless of element size: incrementing an int* moves 4 bytes, a double* moves 8 bytes, a struct SensorReading* moves sizeof(struct SensorReading) bytes. The compiler multiplies your offset by the element size every time.

In embedded systems, pointer arithmetic is how memcpy and DMA buffer code walks through byte arrays with uint8_t* pointers. Understanding it is essential for any low-level C work.

Where You See This Walking an array: for (int *p = arr; p < arr+n; p++) p++ advances by sizeof(int) bytes each iteration, hitting each element exactly. memcpy inner loop: while (n--) *dst++ = *src++; Both pointers advance one byte at a time (uint8_t*), copying each byte. Accessing a struct array by pointer: structs[i] vs *(structs+i) Both compile to the same: start + i*sizeof(struct) bytes offset.
Building the Logic from Scratch
ptr + n in C means: byte address = (byte address of ptr) + n * sizeof(*ptr). The compiler inserts the multiply automatically.
int arr[4] = {10, 20, 30, 40}; /* On a system where sizeof(int)=4: */ Address: 0x100 0x104 0x108 0x10C Value: [ 10 ] [ 20 ] [ 30 ] [ 40 ] arr arr+1 arr+2 arr+3 int *p = arr; /* p = 0x100 */ p + 1 /* 0x100 + 1*4 = 0x104 (points to 20) */ p + 2 /* 0x100 + 2*4 = 0x108 (points to 30) */ *(p + 2) /* go to 0x108 -> 30 */ p++ /* p = 0x104 now */ char *cp = (char*)arr; /* same base address 0x100 */ cp + 1 /* 0x100 + 1*1 = 0x101 (one BYTE forward) */ /* char arithmetic moves 1 byte; int arithmetic moves 4 bytes */

You can also subtract two pointers of the same type to get the number of elements between them (see Q09). You cannot add two pointers together — that is undefined behavior.


#include <stdio.h>

int main(void) {
    int arr[] = {10, 20, 30, 40, 50};
    int *p = arr;          /* points to arr[0] = 10             */

    printf("%d\n", *p);    /* 10 */
    printf("%d\n", *(p+1));/* 20 -- moves 4 bytes forward       */
    printf("%d\n", *(p+4));/* 50 -- moves 16 bytes forward      */

    /* walk with pointer increment */
    for (int *q = arr; q < arr + 5; q++) {
        printf("%d ", *q); /* 10 20 30 40 50                    */
    }
    printf("\n");

    /* pointer arithmetic on different types */
    double darr[] = {1.1, 2.2, 3.3};
    double *dp = darr;
    printf("dp+1 offset: %td bytes\n",
           (char*)(dp+1) - (char*)dp);  /* 8 (sizeof double)   */
    return 0;
}
Dry Run — walking int arr[5] 
arr at 0x1000, sizeof(int)=4
q=0x1000: *q=10
q=0x1004: *q=20
q=0x1008: *q=30
q=0x100C: *q=40
q=0x1010: *q=50
q=0x1014: loop ends (0x1014 == arr+5)
Gotcha

Only pointer arithmetic within (or one-past-the-end of) the same array is defined. int x; int *p = &x; p+1; is undefined behavior — there is no array, so there is no valid "next" element. Also, void* arithmetic is illegal in standard C (GCC allows it as an extension, treating void* like char*).

Confidence Check
  1. If double *p sits at address 0x200, what is the byte address of p+3?
  2. Why is arr[i] exactly equivalent to *(arr+i) at the compiler level?
  3. A uint8_t *dst increments by how many bytes per dst++ step? Why is uint8_t* used for byte-level copies?
ptr + n skips n *elements*, not n bytes. The compiler multiplies by sizeof(*ptr) automatically.
  • Walk an array without index -> for (T *p = arr; p < arr+n; p++)
  • Byte-level walk -> cast to uint8_t* first
  • Jump to element k -> *(ptr + k) or ptr[k] (identical)

Q04 · Array Decay to Pointer — arr[i] == *(arr+i)

Background

In C, an array name is not a pointer — but it "decays" to one in almost every context. Think of an array like a building: the array name is the address of the front door (the first element). The moment you use the array name in an expression (other than as the operand of sizeof, &, or as a string-literal initializer), C automatically converts it to a pointer to its first element.

This decay is why arr[i] and *(arr+i) compile to identical machine code — the compiler rewrites the subscript operator as pointer addition followed by a dereference. It also explains why passing an array to a function actually passes a pointer: the array decays at the call site, and all size information disappears. This "size loss" is one of the most common sources of bugs for C beginners and a key interview question.

Where You See This Passing an array to a function: void f(int *arr, int n) The array decays to a pointer; you must pass the length separately. String literals decay: "hello" becomes const char* pointing to 'h'. char* s = "hello" works because the literal decays to a pointer. Embedded: passing a buffer to a UART transmit function. uint8_t buf[64] decays to uint8_t* — HAL_UART_Transmit receives a pointer.
Building the Logic from Scratch
arr[i] is defined as *(arr+i). The [] operator is syntactic sugar for pointer arithmetic + dereference. This is true everywhere in C without exception.
int arr[4] = {10, 20, 30, 40}; arr decays to: int* pointing to arr[0] arr[2] == *(arr+2) == *(2+arr) == 2[arr] (all identical!) pointer arith commutative weird but legal sizeof(arr) = 4 * sizeof(int) = 16 (full array size -- no decay here) sizeof(&arr) = sizeof(int*) = 8 (pointer size -- different!) void f(int *p, int n) { sizeof(p) /* = 8: size of pointer, NOT array */ } f(arr, 4); /* arr decays to int*, size info GONE */

The one place decay does NOT happen: sizeof(arr) gives the full array size. And &arr gives a pointer-to-array (int (*)[4]), not a pointer-to-int — they have the same numerical address but different types and therefore different pointer arithmetic behaviour.


#include <stdio.h>

/* arr decays to int* here -- n is the element count we pass explicitly */
int sum(int *arr, int n) {
    int total = 0;
    for (int i = 0; i < n; i++) total += arr[i]; /* arr[i] == *(arr+i) */
    return total;
}

int main(void) {
    int data[5] = {1, 2, 3, 4, 5};

    printf("sizeof data in main: %zu\n", sizeof(data));  /* 20 bytes */

    /* decay in action: data becomes int* at the call site */
    int s = sum(data, 5);
    printf("sum = %d\n", s); /* 15 */

    /* arr[i] == *(arr+i): demonstrate they're identical */
    printf("%d %d %d\n", data[2], *(data+2), 2[data]); /* 3 3 3 */
    return 0;
}
Dry Run — sum(data, 5) 
arr = pointer to data[0] = 0x1000
n   = 5
i=0: arr[0] = *(0x1000) = 1, total=1
i=1: arr[1] = *(0x1004) = 2, total=3
i=2: arr[2] = *(0x1008) = 3, total=6
i=3: arr[3] = *(0x100C) = 4, total=10
i=4: arr[4] = *(0x1010) = 5, total=15
return 15
Gotcha

Inside a function, sizeof(arr) gives the pointer size (4 or 8 bytes), NOT the array size. You cannot recover the array length from a decayed pointer. Always pass the length as a separate parameter or use a sentinel value (like the null terminator for strings).

  3. You have int arr[10];. What is the type of &arr? What is the byte difference between &arr+1 and &arr?
Array name in expression -> decays to pointer to first element. arr[i] == *(arr+i), always.
  • Pass array to function -> pass pointer + length explicitly
  • sizeof inside function -> gives pointer size, not array size
  • Keep array size -> use sizeof at declaration site or a #define/constant

Q05 · Double Pointer — Modifying a Pointer from a Function

Background

If a regular pointer is a street address (telling you where a house is), then a double pointer is the address of a sticky note that has a street address written on it. To change which house someone goes to, you don't need to rebuild the house — you just need the address of their sticky note so you can rewrite the address on it.

In C, when you want a function to modify a variable, you pass a pointer to it. When you want a function to modify a pointer itself (not just the data it points to), you must pass a pointer to that pointer — a **. This comes up constantly in linked list operations (insert at head), dynamic memory allocation wrappers, and any function that needs to "return" a new pointer to the caller via an out-parameter.

In embedded development, double pointers appear in device driver APIs where an output handle is filled in by an initialisation function: uart_init(&uart_handle) takes a uart_handle_t ** or a uart_handle_t * depending on the pattern used.

Where You See This Linked list: inserting a node at the head modifies the head pointer itself. The function needs Node **head to change where head points. Safe malloc wrapper: void safe_alloc(void **out, size_t sz) The function writes the newly allocated address into *out. argv in main: char **argv — array of string pointers. Each argv[i] is a char* pointing to a command-line argument string.
Building the Logic from Scratch
To modify X from a function: pass &X. X is an int -> pass int*. X is an int* -> pass int**.
MEMORY Addr Content Meaning 0x2000 42 int x = 42 0x2004 0x2000 int *p = &x (p holds address of x) 0x2008 0x2004 int **pp = &p (pp holds address of p) *pp = 0x2004 -> read the pointer p **pp = 42 -> follow p, then read x *pp = 0x3000 -> CHANGES p to point somewhere new (does not touch x) **pp = 99 -> writes 99 to wherever p currently points void set_ptr(int **pp, int *new_target) { *pp = new_target; /* change what p points to */ } int y = 99; set_ptr(&p, &y); /* p now points to y */

The golden rule: to modify something, pass its address. The "something" here is a pointer, so we pass the address of the pointer — which is a pointer to a pointer.


#include <stdio.h>
#include <stdlib.h>

/* allocate n ints and return via double pointer */
void alloc_array(int **out, int n) {
    *out = malloc(n * sizeof(int));   /* write the new address into *out */
    if (*out == NULL) return;
    for (int i = 0; i < n; i++) (*out)[i] = i * 10;
}

/* insert node at head of linked list */
typedef struct Node { int val; struct Node *next; } Node;

void push(Node **head, int val) {
    Node *node = malloc(sizeof(Node)); /* create new node                */
    node->val  = val;
    node->next = *head;                /* new node points to old head    */
    *head      = node;                 /* update caller's head pointer   */
}

int main(void) {
    int *arr = NULL;
    alloc_array(&arr, 5);             /* &arr is int** */
    for (int i = 0; i < 5; i++) printf("%d ", arr[i]); /* 0 10 20 30 40 */
    printf("\n");
    free(arr);

    Node *head = NULL;
    push(&head, 3); push(&head, 2); push(&head, 1);
    for (Node *n = head; n; n = n->next) printf("%d ", n->val); /* 1 2 3 */
    printf("\n");
    return 0;
}
Dry Run — push(&head, 1) when head already points to {val=2} 
head at 0x3000, value = 0x4000 (address of node{val=2})
*head = 0x4000

push receives: head_pp = 0x3000 (address of head variable)
node = malloc() -> 0x5000, node->val=1, node->next = *head_pp = 0x4000
*head_pp = 0x5000    <- writes 0x5000 into address 0x3000
now head (at 0x3000) = 0x5000 -> node{val=1} -> node{val=2}
Gotcha

Passing head (a Node*) instead of &head (a Node**) to push means the function modifies a local copy of the pointer and the caller's head is unchanged. The new node is allocated and immediately leaked. Always use ** when the function must change which object a pointer references.

Q06 · Function Pointers — Storing and Calling Functions by Address

Background

Every function you write is compiled into machine code stored somewhere in flash or RAM. That storage location has an address, just like any variable. A function pointer holds that address and lets you call the function indirectly — you call whatever function the pointer currently points to, not a function name fixed at compile time.

Think of a function pointer like a phone number on a speed-dial button. The button does not know or care whose phone it dials; you can reprogram it to reach a different person. In C, this enables callbacks (pass a sort comparator into qsort), dispatch tables (jump to the right handler for a protocol message), and plug-in architectures (swap implementations at runtime).

In embedded firmware, function pointer dispatch tables are the standard pattern for state machines and command parsers. Instead of a long if-else chain, an array of function pointers indexed by state or opcode calls the right handler in O(1) — covered in depth in Q20.

Where You See This qsort comparator: qsort(arr, n, sizeof(int), cmp_int); qsort takes a function pointer to your comparator so it can sort any type. Embedded ISR registration: register_isr(IRQ_UART, uart_handler); The vector table is an array of function pointers; registration writes a new address. State machine dispatch: state_fn[current_state](); One array lookup + indirect call replaces a switch with N cases. Plugin / strategy pattern: swap a hash function or codec at runtime. Different function pointers point to different implementations of the same signature.
Building the Logic from Scratch
Function pointer syntax: return_type (*name)(param_types). The parentheses around *name are mandatory — without them it would be a function returning a pointer.
int add(int a, int b) { return a + b; } int sub(int a, int b) { return a - b; } /* Declare a pointer to function taking (int,int) returning int */ int (*op)(int, int); op = add; /* store address of add (no & needed for functions) */ op(3, 4); /* call add(3,4) -> 7 (no * needed to call) */ op = sub; /* now points to sub */ op(10, 3); /* call sub(10,3) -> 7 */ /* typedef makes it readable */ typedef int (*BinOp)(int, int); BinOp table[] = { add, sub }; table[0](5, 2); /* 7 */ table[1](5, 2); /* 3 */

You can call a function pointer with or without the explicit dereference: (*op)(3,4) and op(3,4) are identical. Modern style omits the *. The & when assigning is also optional for function names but required for everything else.


#include <stdio.h>
#include <stdlib.h>

/* a simple integer comparator for qsort */
int cmp_asc(const void *a, const void *b) {
    return *(int*)a - *(int*)b;   /* ascending */
}
int cmp_desc(const void *a, const void *b) {
    return *(int*)b - *(int*)a;   /* descending */
}

int main(void) {
    int arr[] = {5, 2, 8, 1, 9, 3};
    int n = 6;

    /* pass function pointer to qsort */
    qsort(arr, n, sizeof(int), cmp_asc);
    for (int i = 0; i < n; i++) printf("%d ", arr[i]); /* 1 2 3 5 8 9 */
    printf("\n");

    qsort(arr, n, sizeof(int), cmp_desc);
    for (int i = 0; i < n; i++) printf("%d ", arr[i]); /* 9 8 5 3 2 1 */
    printf("\n");

    /* store and call via pointer */
    typedef int (*CmpFn)(const void*, const void*);
    CmpFn chosen = cmp_asc;
    qsort(arr, n, sizeof(int), chosen);
    printf("first: %d\n", arr[0]);  /* 1 */
    return 0;
}
Dry Run — dispatch table 
typedef void (*Handler)(void);
void on_idle(void)  { puts("idle");  }
void on_run(void)   { puts("run");   }
void on_stop(void)  { puts("stop");  }

Handler table[3] = { on_idle, on_run, on_stop };
int state = 1;
table[state]();    /* looks up table[1] = on_run, calls it -> "run" */
state = 2;
table[state]();    /* calls on_stop -> "stop" */
Gotcha

The parentheses in the declaration are essential. int *f(int) is a function that returns int*. int (*f)(int) is a pointer to a function taking int and returning int. These are completely different types. When in doubt, use a typedef to avoid the syntax trap.

Q07 · void* — The Generic Pointer and How memcpy Uses It

Background

A void* is a pointer that has been stripped of its type information. Think of it like a locker key with the tag removed — it still opens a locker (reaches valid memory), but you have no idea whether the locker contains clothes, books, or electronics until you cast it back to a typed pointer. The C standard library functions memcpy, malloc, and qsort all use void* so they can work with any data type.

malloc returns void* because it has no idea what type you intend to store. memcpy accepts void* for both source and destination because it works at the byte level — type does not matter when you are just copying raw bytes. Inside memcpy, the implementation casts both pointers to uint8_t* or similar and walks them byte by byte.

In embedded C, void* appears in DMA buffer descriptors, generic ring-buffer implementations, and FreeRTOS task parameters — anywhere a function needs to accept arbitrary data without knowing its type at design time.

Where You See This void *malloc(size_t n) — returns untyped heap pointer. Q08 · const Pointer Variations — const int* vs int* const vs const int* const

Background

The const keyword applied to pointers creates three distinct meanings depending on where it appears relative to the *. Think of a pointer as a sign on a road pointing to a house. You can make the house immutable (you can look at the furniture but not move it), make the sign post immutable (the sign always points to this house, never another), or make both immutable.

Getting this right is essential in embedded C. Read-only flash strings must be const char*; hardware register definitions use volatile uint32_t * const (the address is fixed but the value changes). Passing a buffer you don't intend to modify as const uint8_t* signals intent to the compiler and the reader, and enables optimisations — the compiler knows it doesn't have to re-read the buffer in case you wrote to it.

Q09 · Pointer Subtraction — Counting Elements Between Two Pointers

Background

If pointer arithmetic addition moves a pointer forward by n elements, then subtraction works in reverse — subtracting two pointers of the same type gives the number of elements between them, not bytes. The result type is ptrdiff_t, a signed integer large enough to hold any valid element offset on the platform.

Think of pointers as mile markers on a highway. If marker B is at mile 80 and marker A is at mile 60, B minus A is 20 miles — the distance between them in the same units. Pointer subtraction gives distance in elements, not bytes. The compiler divides the raw byte difference by sizeof(*ptr) automatically.

This is used in standard library idioms like computing the length of a string without strlen (end - start after scanning to the null), in sprintf return value handling, and in any algorithm that needs to know how many elements a pointer has advanced.

Where You See This String length without strlen: scan to '\0' then subtract start pointer. The write pointer minus the base pointer gives characters written. Building the Logic from Scratch

Q10 · Fast/Slow — Cycle Detection (Floyd's Algorithm)

Background

Imagine two runners on a circular track. One runs at 1 lap/minute, the other at 2 laps/minute. If the track is truly circular, the faster runner will always lap the slower one — they will be at the same point eventually. If the track is not circular (it has a definite end), the faster runner hits the end first and they never meet. Floyd's cycle detection algorithm applies this insight to linked structures: advance one pointer by one step (slow) and another by two steps (fast); if they ever point to the same node, there is a cycle.

This runs in O(n) time and O(1) space — no hash set needed to track visited nodes. It works on any structure where you can advance a pointer: linked lists, implicit sequences (like x → f(x) in number theory), and even array index chains.

Where You See This Detect cycle in a singly linked list. Classic interview question; O(1) space vs O(n) hash-set approach. Detect cycle in an implicit sequence: x, f(x), f(f(x)), ... Used in "Happy Number" and rho factorisation problems. Embedded: detect runaway pointer in a linked buffer descriptor ring. If head catches tail when it shouldn't, there is a corrupt link.
Building the Logic from Scratch
slow moves 1 step, fast moves 2 steps. If fast or fast->next becomes NULL: no cycle. If slow == fast: cycle detected.
List: 1 -> 2 -> 3 -> 4 -> 5 ^ | +-------- + (5->next = 3, cycle!) Step slow fast 0 1 1 1 2 3 2 3 5 3 4 3 (fast wrapped: 5->next=3, then 3->next=4 but fast does 2 steps: 3->4->5... wait) let's be precise: fast = fast->next->next step3: slow=4, fast: was at 5, fast->next=3, fast->next->next=4 => fast=4 slow==fast => CYCLE DETECTED at node 4

The key invariant: in a cycle of length C, after at most C steps the two pointers are at the same node. The fast pointer gains one step on slow per iteration inside the cycle.


#include <stdio.h>
#include <stdlib.h>

typedef struct Node { int val; struct Node *next; } Node;

Node *make(int v) { Node *n = malloc(sizeof(Node)); n->val=v; n->next=NULL; return n; }

int has_cycle(Node *head) {
    Node *slow = head, *fast = head;
    while (fast && fast->next) {       /* fast hits NULL -> no cycle  */
        slow = slow->next;              /* 1 step                      */
        fast = fast->next->next;        /* 2 steps                     */
        if (slow == fast) return 1;     /* same node -> cycle          */
    }
    return 0;
}

int main(void) {
    Node *a=make(1), *b=make(2), *c=make(3), *d=make(4);
    a->next=b; b->next=c; c->next=d;

    printf("no cycle: %d\n", has_cycle(a));  /* 0 */

    d->next = b;  /* create cycle: d -> b */
    printf("cycle:    %d\n", has_cycle(a));  /* 1 */
    d->next = NULL;  /* break cycle before free */
    free(a); free(b); free(c); free(d);
    return 0;
}

Q11 · Fast/Slow — Find Cycle Entry Point (Floyd Phase 2)

Background

Once Floyd's algorithm detects a meeting point inside a cycle, a beautiful mathematical property lets you find exactly where the cycle begins. Reset one pointer to the head of the list. Leave the other at the meeting point. Now advance both pointers one step at a time. The step where they meet again is the cycle entry node.

The proof relies on the relationship between the distance from head to the cycle entry (call it F), the distance from entry to the meeting point (call it a), and the cycle length (C). At the meeting point: F = C - a (mod C), which means advancing from head F steps and from the meeting point F steps lands both pointers at the entry simultaneously. You do not need to know F, C, or a — just apply the two-pointer walk.

Where You See This Find the node where a linked list begins looping. Phase 2 of Floyd gives O(1) space solution vs O(n) hash set. Find the duplicate number in an array where values are 1..n (array as implicit linked list). The duplicate is the cycle entry in the implicit sequence index[i] -> arr[i].
Building the Logic from Scratch
After phase 1 detection: reset slow to head. Advance both slow and fast one step at a time. Where they meet = cycle entry.
List: head -> A -> B -> C -> D | | cycle entry E | ^ | +-- F -- + Phase 1: slow and fast meet somewhere inside cycle (call it M). Phase 2: slow reset to head. Both advance 1 step at a time. They meet exactly at E (cycle entry). Why? Mathematical proof: dist(head -> E) = F dist(E -> M) = a (inside cycle) At meeting: fast travelled 2*(F+a), slow travelled F+a => fast did extra full cycles: 2(F+a) = F+a + k*C => F = k*C - a = C - a (for k=1) => from M, advancing C-a = F steps reaches E => from head, advancing F steps reaches E => they meet at E

#include <stdio.h>
#include <stdlib.h>

typedef struct Node { int val; struct Node *next; } Node;
Node *make(int v) { Node *n=malloc(sizeof(Node)); n->val=v; n->next=NULL; return n; }

Node *cycle_entry(Node *head) {
    Node *slow = head, *fast = head;

    /* Phase 1: detect cycle */
    while (fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) break;
    }
    if (!fast || !fast->next) return NULL; /* no cycle */

    /* Phase 2: find entry */
    slow = head;                    /* reset slow to head         */
    while (slow != fast) {          /* advance both 1 step        */
        slow = slow->next;
        fast = fast->next;
    }
    return slow;                    /* meeting point = entry node */
}

int main(void) {
    Node *n1=make(1),*n2=make(2),*n3=make(3),*n4=make(4),*n5=make(5);
    n1->next=n2; n2->next=n3; n3->next=n4; n4->next=n5;
    n5->next = n3;  /* cycle enters at n3 */

    Node *entry = cycle_entry(n1);
    printf("cycle entry val: %d\n", entry->val);  /* 3 */
    n5->next = NULL;
    free(n1); free(n2); free(n3); free(n4); free(n5);
    return 0;
}

Q12 · Fast/Slow — Find Midpoint of a Sequence

Background

When fast reaches the end, slow is at the middle. This is the simplest fast/slow application: no cycle, no phase 2 — just use the speed difference as a ruler. Because fast moves twice as fast as slow, when fast has walked the full list slow has walked exactly half of it.

Q13 · Read/Write Pointers — In-Place Compaction

Background

Imagine a conveyor belt carrying items — some good, some defective. One worker (the read pointer) picks up every item and inspects it. A second worker (the write pointer) only places items on the output belt when they pass inspection. The read pointer always moves forward; the write pointer only advances when it places something. At the end, the write pointer's position tells you how many good items there were.

This read/write pointer pattern does compaction (filtering) in-place with O(1) extra space. It is the core of remove_if in C++, the in-place string filter (Q13 in strings.html), "remove duplicates from sorted array", and countless array manipulation problems in interviews and embedded pre-processing pipelines.

Where You See This Remove all occurrences of value v from an array in-place. Read scans all, write copies only non-v elements. No extra array needed. Remove duplicates from sorted array. Read advances freely; write advances only when value changes. Embedded: strip corrupt bytes from a received UART buffer before parsing. Same pattern: read every byte, write only valid ones to the same buffer.
Building the Logic from Scratch
Invariant: everything at indices [0, w) is the compacted output. r scans [0, n); w only advances when it writes. At end, w = count of kept elements.
Remove all 0s from [3, 0, 1, 0, 2, 0, 4]: r=0 w=0: arr[0]=3 (keep) -> arr[w]=3, w=1, r=1 r=1 w=1: arr[1]=0 (skip) -> r=2 r=2 w=1: arr[2]=1 (keep) -> arr[w]=1, w=2, r=3 r=3 w=2: arr[3]=0 (skip) -> r=4 r=4 w=2: arr[4]=2 (keep) -> arr[2]=2, w=3, r=5 r=5 w=3: arr[5]=0 (skip) -> r=6 r=6 w=3: arr[6]=4 (keep) -> arr[3]=4, w=4, r=7 result: [3,1,2,4, ...] first w=4 elements are valid ^ r==w when element kept -> no actual move needed

#include <stdio.h>

/* remove all occurrences of val; return new length */
int compact(int *arr, int n, int val) {
    int w = 0;                          /* write pointer (index)   */
    for (int r = 0; r < n; r++) {       /* read pointer scans all  */
        if (arr[r] != val)
            arr[w++] = arr[r];          /* keep: copy and advance w */
    }
    return w;                           /* new logical length       */
}

int main(void) {
    int a[] = {3, 0, 1, 0, 2, 0, 4};
    int n = compact(a, 7, 0);
    printf("len=%d: ", n);              /* 4 */
    for (int i = 0; i < n; i++) printf("%d ", a[i]); /* 3 1 2 4 */
    printf("\n");

    /* remove duplicates from sorted array */
    int b[] = {1, 1, 2, 3, 3, 4};
    int w = 0;
    for (int r = 0; r < 6; r++) {
        if (w == 0 || b[r] != b[w-1])  /* new value: keep */
            b[w++] = b[r];
    }
    printf("dedup len=%d: ", w);        /* 4 */
    for (int i = 0; i < w; i++) printf("%d ", b[i]); /* 1 2 3 4 */
    printf("\n");
    return 0;
}

Background

Q15 · Hardware Register — volatile uint32_t* at Fixed Address

Background

On a microcontroller like the STM32, peripherals (UART, GPIO, timers, ADC) are not accessed through function calls to a driver chip — they are memory-mapped hardware. The chip designer allocates a fixed range of the 32-bit address space to each peripheral's registers. Writing to address 0x40020C14 sets GPIO port A's output data; reading address 0x40013804 retrieves the UART receive buffer.

To access these registers in C, you cast the numeric address to a pointer of the correct width and dereference it. The critical qualifier is volatile — without it, the compiler is allowed to cache the register value in a CPU register and never re-read it from RAM, or to eliminate a "redundant" write entirely. Hardware registers change for reasons the compiler cannot see (an interrupt fires, a DMA transfer completes, a button is pressed), so every access must generate a real bus transaction.

This is the most fundamental embedded C pattern. Every CMSIS header, every ST HAL macro, and every bare-metal driver ultimately reduces to this: cast address → volatile pointer → dereference.

Where You See This Set a GPIO pin high: *GPIOA_ODR |= (1u << 5); Reads current output register, sets bit 5, writes back — one read-modify-write. Wait for UART TX ready: while (!(*USART1_SR & (1u<<7))); volatile ensures the register is re-read every loop iteration, not cached. Clear a DMA transfer-complete flag: *DMA_IFCR = (1u << 5); Write-to-clear registers must be written; without volatile the write may be dropped. Read an ADC result: uint16_t raw = (uint16_t)(*ADC1_DR); The data register holds the latest conversion result; read it after EOC flag.

Background

Q17 · Circular Buffer with Head/Tail Pointer Wrap

Background

A circular buffer (ring buffer) is a fixed-size array that behaves as if the end connects back to the beginning. Imagine a conveyor belt that loops around: items are added at one end (the write pointer / head) and consumed at the other end (the read pointer / tail). When either pointer reaches the end of the underlying array, it wraps back to index 0 — hence "circular".

Ring buffers are the dominant data structure for producer-consumer communication in embedded systems: UART receive ISR writes bytes into the ring; the main loop reads them out. DMA ping-pong buffers, audio sample queues, and CAN message FIFOs all use this pattern. The key properties: fixed memory (no dynamic allocation), O(1) push and pop, and safe use in interrupt contexts when only one side writes and one reads (single-producer single-consumer).

The usual implementation uses indices (integers) rather than actual pointers, because pointer comparison across the buffer boundary is trickier to get right than modulo arithmetic. The "is full" condition uses (head+1) % size == tail; "is empty" uses head == tail.

Where You See This UART ISR writes received bytes into a ring; main loop reads and parses. ISR can run at any time; ring buffer lets it push without blocking. Audio codec DMA: double-buffer / ping-pong fills audio frames in order. Ring of two or more buffers; head/tail track which is being filled vs consumed. Logging system: circular log wraps oldest entries when full. Always have the N most recent log entries without dynamic allocation.
Building the Logic from Scratch
head = next write slot, tail = next read slot. Empty: head==tail. Full: (head+1)%SIZE == tail. Advance either index with (idx+1)%SIZE.

#include <stddef.h>

    volatile uint16_t tail;   /* read  index -- written by main  */

    return ((rb->head + 1) % RB_SIZE) == rb->tail;
}
static inline int rb_empty(const RingBuf *rb) {
    return rb->head == rb->tail;
}

/* Called from ISR -- push one byte */

    if (rb_full(rb)) return -1;             /* drop on overflow     */
    rb->buf[rb->head] = byte;
    rb->head = (rb->head + 1) % RB_SIZE;   /* wrap around          */
    return 0;
}

/* Called from main loop -- pop one byte */
int rb_pop(RingBuf *rb, uint8_t *out) {
    if (rb_empty(rb)) return -1;
    *out = rb->buf[rb->tail];
    rb->tail = (rb->tail + 1) % RB_SIZE;   /* wrap around          */
    return 0;
}

Q18 · memcpy/memmove — How They Walk src and dst Pointers

Background

At their core, memcpy and memmove are just two-pointer walks: one pointer reads from the source, another writes to the destination, and they both advance one element at a time until n bytes have been transferred. The source and destination are typed as void* (Q07) and internally cast to uint8_t* so that arithmetic proceeds one byte at a time regardless of the original data type.

The critical difference between the two: memcpy assumes the regions do not overlap and can copy in any order (forward, backward, in chunks) — the C standard gives the implementation latitude for speed. memmove guarantees correctness even when regions overlap, by checking the direction and copying backward when the destination would overwrite not-yet-read source bytes.

In embedded firmware, you use memcpy constantly: copy a packet payload into a DMA buffer, copy a struct into flash NVM, copy received bytes from a ring buffer into a frame buffer. Understanding when to use memmove (overlapping regions, in-place shifts) prevents silent data corruption that is extremely hard to debug.

Building the Logic from Scratch
memcpy: forward byte copy, assumes no overlap. memmove: check if dst > src (and overlap exists) -> copy backward to avoid clobbering unread bytes.
MEMCPY (forward, no overlap): src: [A][B][C][D] dst: [A][B][C][D] copy A first, then B, C, D -- safe because dst is far right MEMMOVE overlapping -- WRONG direction (dst > src, overlap): src: [A][B][C][D] dst: [A][B][C][D] (dst = src+1) Forward copy: write A to dst[0]=src[1], OVERWRITES B before reading it! #include <stdint.h>

/* Simplified memcpy -- forward walk, no overlap allowed */
void *my_memcpy(void *dst, const void *src, size_t n) {
    uint8_t       *d = (uint8_t*)dst;
    const uint8_t *s = (const uint8_t*)src;
    while (n--) *d++ = *s++;
    return dst;
}

/* Simplified memmove -- handles overlap correctly */
void *my_memmove(void *dst, const void *src, size_t n) {
    uint8_t       *d = (uint8_t*)dst;
    const uint8_t *s = (const uint8_t*)src;
    if (d < s || d >= s + n) {
        while (n--) *d++ = *s++;        /* no overlap or dst before src: forward */
    } else {
        d += n - 1; s += n - 1;         /* dst in src region: backward           */
        while (n--) *d-- = *s--;
    }
    return dst;
}

int main(void) {
    uint8_t buf[] = {1, 2, 3, 4, 5};

    /* Shift elements [1..4] right by 1 (insert slot at index 1) */
    my_memmove(buf + 2, buf + 1, 4);   /* overlap: dst > src */
    buf[1] = 99;
    for (int i = 0; i < 5; i++) printf("%d ", buf[i]); /* 1 99 2 3 4 */
    printf("\n");
    return 0;
}
