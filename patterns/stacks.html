Pattern 01 Array-Based Stack Implementation
① Story First
A stack of plates: you can only put a new plate on top (push) or take the top plate off (pop). You cannot access plates in the middle. Last in, first out. An array stack uses an integer index (top) pointing at the topmost element — increment on push, decrement on pop.
② The Insight
Array stack is the simplest and fastest stack: O(1) push, pop, and peek with no heap allocation. The top index starts at -1 (empty). Push: data[++top] = val. Pop: return data[top--]. The only failure mode is overflow (top == capacity-1) and underflow (top == -1).
③ Step-by-Step Logic
  1. struct Stack { int data[MAX]; int top; }. Initialize top = -1.
  2. push(val): if top == MAX-1, overflow. Else data[++top] = val.
  3. pop(): if top == -1, underflow. Else return data[top--].
  4. peek(): return data[top] without modifying top.
Diagram
Empty: top=-1 [] push(1): top=0 [1] push(2): top=1 [1,2] push(3): top=2 [1,2,3] pop()→3: top=1 [1,2] peek()→2: top=1 [1,2] (unchanged)
④ Annotated Code
#include <stdio.h>
#include <assert.h>

#define MAX 1024

typedef struct { int data[MAX]; int top; } Stack;

void stack_init(Stack *s) { s->top = -1; }
int  stack_empty(Stack *s) { return s->top == -1; }
int  stack_full(Stack *s)  { return s->top == MAX-1; }

void stack_push(Stack *s, int val) {
    assert(!stack_full(s));    /* catch overflow in debug builds */
    s->data[++s->top] = val;
}
int stack_pop(Stack *s) {
    assert(!stack_empty(s));   /* catch underflow */
    return s->data[s->top--];
}
int stack_peek(Stack *s) {
    assert(!stack_empty(s));
    return s->data[s->top];
}

int main(void) {
    Stack s; stack_init(&s);
    stack_push(&s, 10);
    stack_push(&s, 20);
    stack_push(&s, 30);
    printf("peek=%d\n", stack_peek(&s));  /* 30 */
    printf("pop=%d\n",  stack_pop(&s));   /* 30 */
    printf("pop=%d\n",  stack_pop(&s));   /* 20 */
    printf("empty=%d\n",stack_empty(&s)); /* 0 (10 still there) */
    return 0;
}
⑤ Dry Run
init: top=-1 push(10): data[0]=10, top=0 push(20): data[1]=20, top=1 push(30): data[2]=30, top=2 peek: data[2]=30 ✓ pop: return data[2]=30, top=1 ✓ pop: return data[1]=20, top=0 ✓
⚠ Gotcha: top starts at -1, not 0

If top starts at 0, the first push writes to data[1] (skipping data[0]) or you need a special case for the first push. Starting at -1 means the pre-increment data[++top] writes to data[0] on the first push, which is natural and correct.

N/A (fundamental data structure)
When you need LIFO access → think: array stack, top=-1, push: data[++top]=val, pop: return data[top--].
Pattern 02 Linked List Stack
① Story First
A stack where each item knows what's below it. No fixed capacity — the stack grows as you push and shrinks as you pop. Each push allocates a new node at the top; each pop frees it. The head of the linked list IS the top of the stack.
② The Insight
Linked stack: head = top of stack. Push = insert at head. Pop = remove head. O(1) for both, unlimited capacity (until heap exhausted). Overhead: one malloc/free per push/pop — slower than array stack in practice due to memory allocation cost.
③ Step-by-Step Logic
  1. Push: allocate node, node->next = head, head = node.
  2. Pop: save head->val, temp = head, head = head->next, free(temp), return val.
  3. Peek: return head->val.
  4. Empty: head == NULL.
Diagram
push(1): head→[1]→NULL push(2): head→[2]→[1]→NULL push(3): head→[3]→[2]→[1]→NULL pop()→3: head→[2]→[1]→NULL, free [3]
④ Annotated Code
#include <stdio.h>
#include <stdlib.h>
#include <assert.h>

typedef struct SNode { int val; struct SNode *next; } SNode;
typedef struct { SNode *head; int size; } LStack;

void ls_init(LStack *s) { s->head=NULL; s->size=0; }
int  ls_empty(LStack *s) { return s->head==NULL; }

void ls_push(LStack *s, int val) {
    SNode *n = malloc(sizeof(SNode));
    n->val = val; n->next = s->head;
    s->head = n; s->size++;
}
int ls_pop(LStack *s) {
    assert(!ls_empty(s));
    SNode *tmp = s->head;
    int val = tmp->val;
    s->head = tmp->next;
    free(tmp); s->size--;
    return val;
}
int ls_peek(LStack *s) { assert(!ls_empty(s)); return s->head->val; }

int main(void) {
    LStack s; ls_init(&s);
    ls_push(&s,1); ls_push(&s,2); ls_push(&s,3);
    printf("%d %d %d\n", ls_pop(&s), ls_pop(&s), ls_pop(&s)); /* 3 2 1 */
    return 0;
}
⑤ Dry Run
push(1): head=[1]→NULL, size=1 push(2): head=[2]→[1]→NULL, size=2 push(3): head=[3]→[2]→[1]→NULL, size=3 pop: val=3, head=[2]→[1], free [3], size=2 pop: val=2, head=[1], free [2], size=1 pop: val=1, head=NULL, free [1], size=0 ✓
⚠ Gotcha: Save val BEFORE freeing the node

In pop: save val = tmp->val before calling free(tmp). After free, reading tmp->val is undefined behavior. This is the same pattern as linked list traversal — always save what you need before releasing memory.

N/A (used in DFS, expression eval)
When you need a stack without fixed capacity → think: linked stack, head = top, push = insert at head, pop = remove head.
Pattern 03 Valid Parentheses
① Story First
Every opening bracket needs a matching closing bracket in the right order. A stack tracks unmatched openers. On an opener, push. On a closer, pop — if the popped opener doesn't match, it's invalid. If the stack is empty when closing, invalid. If non-empty at end, unclosed openers remain — invalid.
② The Insight
Stack is perfect here because brackets must close in reverse order of opening (LIFO). The top of the stack is always the most recently opened, unmatched bracket — exactly what needs to match the next closer.
③ Step-by-Step Logic
  1. For each char: if opener, push. If closer and stack empty, return false.
  2. If closer: pop top. If top doesn't match the closer type, return false.
  3. After loop: return stack is empty (all openers matched).
Diagram
"({[]})" '(' → push: ['('] '{' → push: ['(', '{'] '[' → push: ['(', '{', '['] ']' → pop '[', matches ']' ✓: ['(', '{'] '}' → pop '{', matches '}' ✓: ['('] ')' → pop '(', matches ')' ✓: [] empty → VALID ✓
④ Annotated Code
#include <stdio.h>
#include <string.h>

int is_valid(const char *s) {
    char stack[10001];
    int top = -1;
    for (; *s; s++) {
        if (*s=='(' || *s=='[' || *s=='{') {
            stack[++top] = *s;             /* push opener */
        } else {
            if (top == -1) return 0;       /* nothing to match */
            char open = stack[top--];      /* pop */
            if (*s==')' && open!='(') return 0;
            if (*s==']' && open!='[') return 0;
            if (*s=='}' && open!='{') return 0;
        }
    }
    return top == -1;   /* all matched iff stack empty */
}

int main(void) {
    printf("%d\n", is_valid("()[]{}"));  /* 1 */
    printf("%d\n", is_valid("([)]"));    /* 0 */
    printf("%d\n", is_valid("{[]}"));    /* 1 */
    printf("%d\n", is_valid("]"));       /* 0 */
    return 0;
}
⑤ Dry Run
is_valid("([)]"): '(' push, top=0: ['('] '[' push, top=1: ['(','['] ')' → pop '[': open='[', ')' needs '(' but got '[' → return 0 ✓
⚠ Gotcha: Check top==-1 before popping on a closer

If the string starts with a closer (e.g., "]abc"), top is -1 and there's nothing to pop. Without the empty-stack check, stack[top--] with top=-1 reads stack[-1] — undefined behavior. Always check before popping.

Pattern 04 Min Stack — O(1) getMin
① Story First
A stack where you can ask "what's the current minimum?" in O(1) at any time. The trick: maintain a second parallel stack that tracks the minimum at each level. When you push a new value, push min(new_val, current_min) onto the min stack too. When you pop, pop both stacks.
② The Insight
Two stacks — one for data, one for minimums. The min stack's top always reflects the minimum of all values currently in the data stack. When the minimum value is popped from the data stack, the min stack also pops, revealing the previous minimum automatically.
③ Step-by-Step Logic
  1. push(val): push val to data stack. Push min(val, min_stack.top) to min stack.
  2. pop(): pop both data stack and min stack.
  3. getMin(): return min stack top. O(1).
  4. top(): return data stack top.
Diagram
push(5): data=[5], min=[5] push(3): data=[5,3], min=[5,3] push(7): data=[5,3,7], min=[5,3,3] ← min stays 3 getMin()→3 ✓ pop(): data=[5,3], min=[5,3] pop(): data=[5], min=[5] getMin()→5 ✓
④ Annotated Code
#include <stdio.h>
#include <assert.h>

#define MAX 10001

typedef struct {
    int data[MAX], min_s[MAX];
    int dtop, mtop;
} MinStack;

void ms_init(MinStack *s) { s->dtop = s->mtop = -1; }

void ms_push(MinStack *s, int val) {
    s->data[++s->dtop] = val;
    int cur_min = (s->mtop == -1) ? val : (val < s->min_s[s->mtop] ? val : s->min_s[s->mtop]);
    s->min_s[++s->mtop] = cur_min;   /* push current minimum */
}
int ms_pop(MinStack *s) {
    assert(s->dtop >= 0);
    s->mtop--;                        /* pop min stack in sync */
    return s->data[s->dtop--];
}
int ms_top(MinStack *s)    { return s->data[s->dtop]; }
int ms_get_min(MinStack *s){ return s->min_s[s->mtop]; }  /* O(1) */

int main(void) {
    MinStack s; ms_init(&s);
    ms_push(&s,5); ms_push(&s,3); ms_push(&s,7);
    printf("min=%d\n", ms_get_min(&s));  /* 3 */
    ms_pop(&s);
    printf("min=%d\n", ms_get_min(&s));  /* 3 */
    ms_pop(&s);
    printf("min=%d\n", ms_get_min(&s));  /* 5 */
    return 0;
}
⑤ Dry Run
push(5): data=[5], min=[5] push(3): cur_min=min(3,5)=3 → data=[5,3], min=[5,3] push(7): cur_min=min(7,3)=3 → data=[5,3,7], min=[5,3,3] get_min → min[2]=3 ✓ pop: data=[5,3], min=[5,3]; get_min=3 ✓ pop: data=[5], min=[5]; get_min=5 ✓
⚠ Gotcha: Pop BOTH stacks together — they must stay in sync

If you only pop the data stack (forgetting the min stack), they go out of sync and getMin returns the wrong value. The min stack always has exactly as many elements as the data stack — they grow and shrink together.

Pattern 05 Evaluate Reverse Polish Notation (RPN)
① Story First
"3 4 + 2 *" means (3+4)*2. No parentheses needed — the order of operands and operators already encodes the precedence. Walk left to right: push numbers; on an operator, pop two numbers, apply the operation, push the result back.
② The Insight
RPN evaluation is the canonical stack use case. A number means "save for later" (push). An operator means "use the last two saved values" (pop two, operate, push result). When you reach the end of a valid RPN expression, exactly one value remains on the stack — the answer.
③ Step-by-Step Logic
  1. For each token: if number, push it.
  2. If operator: pop b (top), pop a (second). Result = a op b. Push result.
  3. After all tokens: answer is stack[0].
Diagram
Tokens: ["2","1","+","3","*"] "2" → push: [2] "1" → push: [2,1] "+" → pop 1, pop 2, push 2+1=3: [3] "3" → push: [3,3] "*" → pop 3, pop 3, push 3*3=9: [9] Result: 9 ✓
④ Annotated Code
#include <stdio.h>
#include <string.h>
#include <stdlib.h>

int eval_rpn(char **tokens, int n) {
    long stack[n];
    int top = -1;

    for (int i = 0; i < n; i++) {
        char *t = tokens[i];
        if (strcmp(t,"+")==0 || strcmp(t,"-")==0 ||
            strcmp(t,"*")==0 || strcmp(t,"/")==0) {
            long b = stack[top--];   /* second operand (top) */
            long a = stack[top--];   /* first operand */
            if      (*t=='+') stack[++top] = a + b;
            else if (*t=='-') stack[++top] = a - b;
            else if (*t=='*') stack[++top] = a * b;
            else              stack[++top] = a / b;  /* truncates toward zero */
        } else {
            stack[++top] = atol(t);   /* convert token to number and push */
        }
    }
    return (int)stack[0];
}

int main(void) {
    char *t1[] = {"2","1","+","3","*"};
    printf("%d\n", eval_rpn(t1, 5));   /* 9 */

    char *t2[] = {"4","13","5","/","+"};
    printf("%d\n", eval_rpn(t2, 5));   /* 6 */
    return 0;
}
⑤ Dry Run
["4","13","5","/","+"]: "4" → push 4: [4] "13" → push 13: [4,13] "5" → push 5: [4,13,5] "/" → b=5, a=13; 13/5=2; push 2: [4,2] "+" → b=2, a=4; 4+2=6; push 6: [6] result=6 ✓
⚠ Gotcha: Pop order matters for non-commutative ops

For subtraction and division, order matters: the first pop gives b (the second operand), the second pop gives a (the first operand). The expression is a op b. Reversing the pop order gives wrong results for "5 3 -" (should be 5-3=2, not 3-5=-2).

Pattern 06 Daily Temperatures — Next Warmer Day
① Story First
For each day, how many days until a warmer temperature? "73 74 75 71 69 72 76 73" → "1 1 4 2 1 1 0 0". Walk left to right. If today is warmer than some previous days, those days now have their answer. A stack of unresolved days (indices) waits for their warmer future.
② The Insight
Monotonic decreasing stack of indices. For each day i: while the stack top's temperature < today's temperature, pop it — that day's answer is i - popped_index. Then push i. Days still on the stack at the end have no warmer future (answer = 0).
③ Step-by-Step Logic
  1. ans[] = {0}, stack of indices, initially empty.
  2. For each i: while stack not empty and temps[stack.top] < temps[i]: pop j; ans[j] = i - j.
  3. Push i.
  4. Remaining indices on stack have ans = 0 (already initialized).
Diagram
temps=[73,74,75,71,69,72,76,73] i=0: push 0. stack=[0] i=1: 74>73 → pop 0, ans[0]=1-0=1. push 1. stack=[1] i=2: 75>74 → pop 1, ans[1]=2-1=1. push 2. stack=[2] i=3: 71<75. push 3. stack=[2,3] i=4: 69<71. push 4. stack=[2,3,4] i=5: 72>69→pop 4,ans[4]=1; 72>71→pop 3,ans[3]=2; 72<75. push 5. stack=[2,5] i=6: 76>72→pop 5,ans[5]=1; 76>75→pop 2,ans[2]=4. push 6. stack=[6] i=7: 73<76. push 7. stack=[6,7] ans: [1,1,4,2,1,1,0,0] ✓
④ Annotated Code
#include <stdio.h>
#include <string.h>

void daily_temperatures(int *temps, int n, int *ans) {
    int stack[n];   /* stack of unresolved indices */
    int top = -1;
    memset(ans, 0, n * sizeof(int));

    for (int i = 0; i < n; i++) {
        /* Pop days that are colder than today */
        while (top >= 0 && temps[stack[top]] < temps[i]) {
            int j = stack[top--];
            ans[j] = i - j;   /* days waited = today - that day */
        }
        stack[++top] = i;     /* push today's index (unresolved) */
    }
}

int main(void) {
    int temps[] = {73,74,75,71,69,72,76,73};
    int ans[8];
    daily_temperatures(temps, 8, ans);
    for (int i=0; i<8; i++) printf("%d ", ans[i]);
    /* 1 1 4 2 1 1 0 0 */
    return 0;
}
⑤ Dry Run
See diagram above — full trace matches expected output ✓
⚠ Gotcha: Stack stores INDICES, not temperatures

The stack holds indices (positions) so you can compute the distance i - j. If you stored temperatures, you couldn't recover the original day's position. This index-stack pattern appears in most monotonic stack problems.

Pattern 07 Next Greater Element I
① Story First
Given two arrays, for each element in the first array, find the next greater element in the second array (looking rightward from where that element appears). Precompute "next greater" for all elements in the second array using a monotonic stack, then look up answers for the first array in a hash map.
② The Insight
Build a "next greater" map for all elements of nums2 using a monotonic stack in one pass. Then for each element in nums1, look up its next greater value in the map. O(n+m) total. The stack processes each element of nums2 at most twice (once pushed, once popped).
③ Step-by-Step Logic
  1. Process nums2 left to right with a decreasing stack.
  2. When nums2[i] > stack top: that top's "next greater" is nums2[i]. Record in map. Pop.
  3. Push nums2[i]. Elements still on stack have no next greater (-1).
  4. For each element in nums1: look up in map.
Diagram
nums2=[1,3,4,2], build next-greater map: push 1: stack=[1] 3>1: pop 1, map[1]=3; push 3: stack=[3] 4>3: pop 3, map[3]=4; push 4: stack=[4] 2<4: push 2: stack=[4,2] end: map[4]=-1, map[2]=-1 nums1=[4,1,2]: lookup → [-1, 3, -1] ✓
④ Annotated Code
#include <stdio.h>
#include <string.h>

#define MAXVAL 10001

void next_greater_element(int *nums1, int n1, int *nums2, int n2, int *res) {
    int nge[MAXVAL];              /* nge[v] = next greater of value v in nums2 */
    memset(nge, -1, sizeof(nge));

    int stack[n2], top = -1;
    for (int i = 0; i < n2; i++) {
        while (top >= 0 && stack[top] < nums2[i])
            nge[stack[top--]] = nums2[i];   /* nums2[i] is next greater for popped */
        stack[++top] = nums2[i];
    }
    /* remaining on stack: no next greater → already -1 */

    for (int i = 0; i < n1; i++)
        res[i] = nge[nums1[i]];
}

int main(void) {
    int nums1[] = {4,1,2}, nums2[] = {1,3,4,2};
    int res[3];
    next_greater_element(nums1, 3, nums2, 4, res);
    for(int i=0;i<3;i++) printf("%d ",res[i]); /* -1 3 -1 */
    return 0;
}
⑤ Dry Run
nums2=[1,3,4,2]: i=0: push 1. stack=[1] i=1: 3>1→nge[1]=3, pop; push 3. stack=[3] i=2: 4>3→nge[3]=4, pop; push 4. stack=[4] i=3: 2<4; push 2. stack=[4,2] nge[4]=-1, nge[2]=-1 (still in stack) lookup nums1=[4,1,2]: [-1, 3, -1] ✓
⚠ Gotcha: This only works when all values are unique

Mapping by value (nge[val]) requires all values in nums2 to be distinct. If duplicates exist, the map would be overwritten. For duplicate values, map by index instead and use the index to look up the original value's position in nums2.

Pattern 08 Next Greater Element II — Circular Array
① Story First
Same problem but the array wraps around — after the last element, you continue from the first. "3 1 2 3" circularly: for the first 3, the next greater wrapping around... doesn't exist. For 1, it's 2. For 2, it's 3. Simulate two passes by doubling the indices.
② The Insight
Simulate circular traversal by iterating indices 0 to 2n-1, using i % n to get the actual array index. Only push indices (not values) for the first n elements (second pass only resolves, doesn't add new candidates). Run the same monotonic stack logic.
③ Step-by-Step Logic
  1. ans[] = {-1}. Stack of indices, initially empty.
  2. Loop i from 0 to 2n-1: idx = i % n.
  3. While stack not empty and nums[stack.top] < nums[idx]: pop j; ans[j] = nums[idx].
  4. If i < n: push idx (only push actual positions in first pass).
Diagram
nums=[5,4,3,2,1], n=5, circular: First pass (i=0..4): push indices 0,1,2,3,4. No pops (decreasing sequence). Second pass (i=5..9, idx=0..4): i=5,idx=0: nums[0]=5 > nums[4]=1 → pop 4, ans[4]=5 5 > nums[3]=2 → pop 3, ans[3]=5 5 > nums[2]=3 → pop 2, ans[2]=5 5 > nums[1]=4 → pop 1, ans[1]=5 5 == nums[0]=5 → stop i=6,idx=1: nums[1]=4 not > nums[0]=5 → stop ...no more pops ans[0]=-1 (5 never found a larger in circle) ✓
④ Annotated Code
#include <stdio.h>
#include <string.h>

void next_greater_circular(int *nums, int n, int *ans) {
    memset(ans, -1, n * sizeof(int));
    int stack[n], top = -1;

    for (int i = 0; i < 2 * n; i++) {
        int idx = i % n;
        while (top >= 0 && nums[stack[top]] < nums[idx])
            ans[stack[top--]] = nums[idx];
        if (i < n) stack[++top] = idx;   /* only push in first pass */
    }
}

int main(void) {
    int nums[] = {1,2,1};
    int ans[3];
    next_greater_circular(nums, 3, ans);
    for(int i=0;i<3;i++) printf("%d ",ans[i]); /* 2 -1 2 */
    return 0;
}
⑤ Dry Run
nums=[1,2,1], n=3: i=0,idx=0: push 0. stack=[0] i=1,idx=1: 2>1→pop 0, ans[0]=2; push 1. stack=[1] i=2,idx=2: 1<2; push 2. stack=[1,2] i=3,idx=0: 1<2; no push (i>=n) i=4,idx=1: 2>1→pop 2, ans[2]=2; 2==2 stop; no push i=5,idx=2: 1<2; no push ans=[2,-1,2] ✓
⚠ Gotcha: Only push in the first pass (i < n)

In the second pass (i ≥ n), you only resolve existing stack entries — you don't push new indices. If you push in the second pass too, you'd get duplicate index entries and the ans[j] = nums[idx] assignments would corrupt already-resolved answers.

Pattern 09

Largest Rectangle in Histogram

Imagine a city skyline of buildings side by side, each with different heights. You want to find the largest billboard you can paste on a contiguous section of that skyline — it must fit under every building in the section. The billboard's height equals the shortest building it spans.
Core insight: For each bar, the largest rectangle it can be the minimum of extends left until a shorter bar appears and right until a shorter bar appears. A monotonic increasing stack tracks exactly those left-boundary bars — when you pop a bar, the current bar is its right boundary and the new top is its left boundary.
③ Step-by-step Logic
  1. Maintain a stack of indices in increasing-height order.
  2. For each bar i: while stack top has height ≥ heights[i], pop it as the height of a candidate rectangle.
  3. Width = i − stack[top] − 1 (or i if stack empty after pop).
  4. Area = popped_height × width; track max.
  5. After the loop, pop remaining indices with width extending to the end (n − stack[top] − 1).
④ Annotated Code
#include <stdio.h>

int largest_rectangle(int *h, int n) {
    int stack[n+1], top = -1, max_area = 0;
    for (int i = 0; i <= n; i++) {
        int cur = (i == n) ? 0 : h[i];   /* sentinel 0 flushes the stack */
        while (top >= 0 && h[stack[top]] >= cur) {
            int height = h[stack[top--]];
            int width  = (top < 0) ? i : i - stack[top] - 1;
            int area   = height * width;
            if (area > max_area) max_area = area;
        }
        stack[++top] = i;
    }
    return max_area;
}

int main(void) {
    int h[] = {2,1,5,6,2,3};
    printf("%d\n", largest_rectangle(h, 6));  /* 10 */
    return 0;
}

⚠ Gotcha: Sentinel bar of height 0

Appending a virtual bar of height 0 at index n ensures all remaining bars in the stack get flushed cleanly. Without the sentinel you need a second loop — the sentinel trick eliminates duplicate code.

Pattern 10

Trapping Rain Water (Stack)

Think of the histogram as a valley profile. Rain fills between the walls. For each lower bar, the water it can hold depends on the shorter of the two walls flanking it — like a bathtub filling up to the rim of the lower wall.
Core insight: A monotonic decreasing stack of bar indices lets you compute water layer by layer horizontally. When a taller bar appears, the popped bar is the bottom of a pool. The water height is min(left wall, right wall) − bottom, and width is the gap between the walls.
③ Step-by-step Logic
  1. Maintain a stack of bar indices in decreasing-height order.
  2. For each bar i: while stack top has height ≤ current bar's height, pop it as the pool bottom.
  3. If stack is non-empty after pop, left wall = stack top, right wall = i.
  4. Water height = min(h[left], h[i]) − h[bottom]; width = i − left − 1.
  5. Add width × water height to the total.
④ Annotated Code
#include <stdio.h>

int trap(int *h, int n) {
    int stack[n], top = -1, water = 0;
    for (int i = 0; i < n; i++) {
        while (top >= 0 && h[stack[top]] <= h[i]) {
            int bot = stack[top--];           /* pool floor */
            if (top < 0) break;              /* no left wall */
            int left  = stack[top];
            int bound = h[left] < h[i] ? h[left] : h[i];
            water += (bound - h[bot]) * (i - left - 1);
        }
        stack[++top] = i;
    }
    return water;
}

int main(void) {
    int h[] = {0,1,0,2,1,0,1,3,2,1,2,1};
    printf("%d\n", trap(h, 12));  /* 6 */
    return 0;
}
⑤ Dry Run
h=[0,1,0,2,...] (abbreviated) i=0: push 0. stack=[0] i=1: h[0]=0 <= h[1]=1 → pop 0 as bot; top<0 → break. push 1. stack=[1] i=2: h[1]=1 > 0; push 2. stack=[1,2] i=3: h[2]=0 <= h[3]=2 → pop 2 as bot; left=1; bound=min(1,2)=1; water+=(1-0)*(3-1-1)=1 h[1]=1 <= 2 → pop 1 as bot; top<0 → break. push 3. stack=[3] ...continuing: total water = 6 ✓
⚠ Gotcha: Break when stack empty after pop

After popping the pool floor, check if the stack is now empty before accessing stack[top] as the left wall. An empty stack means there's no left wall, so no water can be trapped — skip the water calculation entirely.
