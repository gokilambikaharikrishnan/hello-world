LIFO Intuition — What a Stack Is and When to Reach for It

Fundamentals

A stack is a container where the last item added is the first item removed — Last In, First Out. Think of a stack of plates: you always add and remove from the top. You cannot reach the bottom plate without removing every plate above it.

Stacks appear whenever you need to undo or backtrack in the reverse order of arrival. The C function call stack is the canonical example: when foo() calls bar() which calls baz(), the return order is baz → bar → foo — perfectly reversed. Each frame is pushed on entry and popped on return.

The two signal patterns that scream "use a stack": (1) you process something, and later encounter its matching counterpart — parentheses, tags, open/close brackets; (2) you need the most recently seen element that satisfies some condition — monotonic stack problems. Any time you say "I need to remember what I saw, and process it in reverse," a stack is the answer.

In embedded C, stacks are everywhere: the hardware call stack (SP register on ARM Cortex-M), ISR nesting (interrupts push processor state to the call stack), undo buffers in state machines, and explicitly managed stacks for DFS traversal without recursion.

When to reach for a stack: "I need to process something now, but I might need to revisit it when its counterpart arrives later — and that revisit happens in reverse order of arrival."
/* Minimal array stack — the template used by every stack card in this file */
#define MAXN 100000
int stk[MAXN];
int top = 0;                     /* top points ONE PAST the last element */

void push(int x)   { stk[top++] = x; }
int  pop(void)     { return stk[--top]; }
int  peek(void)    { return stk[top - 1]; }
int  empty(void)   { return top == 0; }
int  size(void)    { return top; }

Gotcha

top is the index of the next free slot, not the last filled slot. So peek = stk[top-1] and pop = stk[--top]. If you define top as the last filled index, every formula shifts by one — pick one convention and stick to it throughout your code.

    Stack Implementation — Array-Based with Top Pointer

    Fundamentals

    The simplest, fastest stack implementation: a fixed-size array plus a single integer top that tracks how many elements are in use. All operations are O(1) with no allocation, no pointer chasing, and excellent cache locality — every element is contiguous in memory.

    This is exactly how the hardware call stack works on ARM Cortex-M: the stack pointer (SP / R13) decrements on push and increments on pop. The hardware stack grows downward in memory; a software array stack typically grows upward (index 0 = bottom). The mental model is the same.

    In competitive programming and embedded firmware, the array-based stack is always the first choice. The only limitation is a fixed capacity — which is fine when the problem bounds are known.

    Any algorithm problem where the input size is bounded
    No malloc, no free, no fragmentation — just an array
    Embedded firmware stack for DFS or expression evaluation
    Heap may not exist; static allocation is safe
    ISR-safe stack (no dynamic allocation in interrupt context)
    malloc is not reentrant; static array avoids the problem
    Performance-critical inner loop needing O(1) guaranteed
    Array push/pop is a single store + increment
    Memory layout — top grows upward from index 0:
    index: 0 1 2 3 4 ... [5] [3] [8] [ ] [ ] ^ ^ bottom top=3 (next free slot) push(7): stk[3]=7, top=4 [5] [3] [8] [7] [ ] top=4 pop(): val=stk[3]=7, top=3 (just decrement — no erasure needed) [5] [3] [8] [7*] [ ] top=3 (* still in memory but logically gone) peek(): return stk[top-1] = stk[2] = 8 (no move)
    The "popped" value physically stays in the array — it's logically gone because top no longer covers it. The next push overwrites it.
    #define STACK_MAX 100000

typedef struct {
    int  data[STACK_MAX];
    int  top;              /* index of next free slot; 0 = empty */
} Stack;

void stk_init(Stack *s)         { s->top = 0; }
int  stk_empty(const Stack *s)  { return s->top == 0; }
int  stk_full(const Stack *s)   { return s->top == STACK_MAX; }
int  stk_size(const Stack *s)   { return s->top; }

void stk_push(Stack *s, int x) {
    s->data[s->top++] = x;   /* store then increment */
}

int stk_pop(Stack *s) {
    return s->data[--s->top]; /* decrement then read */
}

int stk_peek(const Stack *s) {
    return s->data[s->top - 1];
}
    stk_init: top=0 push(10): data[0]=10, top=1 push(20): data[1]=20, top=2 push(30): data[2]=30, top=3 peek(): data[2]=30 (top unchanged) pop(): --top=2, return data[2]=30 pop(): --top=1, return data[1]=20 empty(): top=1 → 0 (false)
    Gotcha

    push uses post-increment (top++): store first at top, then increment. pop uses pre-decrement (--top): decrement first, then read. Swap them and you read/write one slot off — an off-by-one that looks correct until the stack wraps. Always: push stores at current top then moves top up; pop moves top down then reads.

    Stack Implementation — Linked List Based

    Fundamentals

    A linked list stack grows dynamically — no fixed capacity. The head of the list is the top of the stack: push prepends a new node to the front, pop removes the front node. Both are O(1).

    The trade-off: each push calls malloc and each pop calls free, which is expensive and non-deterministic in time. In an embedded system without a heap — or in a hard-real-time context where malloc latency is unacceptable — this is the wrong choice. In a general-purpose application where capacity is unknown and memory is available, it is fine.

    General-purpose stack when maximum depth is unknown at compile time
    Grows on demand — no capacity planning needed
    LRU cache node pool (nodes recycled from a free list)
    Free list is a linked-list stack of available nodes
    Teaching linked list pointer manipulation via stack
    Push/pop show prepend/delete-head patterns
    Stack top = linked list head. Push = prepend. Pop = remove head.
    Empty: top=NULL push(1): [1|next=NULL] top→[1] push(2): [2|next→[1]] top→[2]→[1] push(3): [3|next→[2]] top→[3]→[2]→[1] pop(): val = top->val = 3 old = top (save to free) top = top->next → top→[2]→[1] free(old) return 3
    typedef struct SNode { int val; struct SNode *next; } SNode;

typedef struct { SNode *top; int size; } LStack;

void ls_init(LStack *s)  { s->top = NULL; s->size = 0; }
int  ls_empty(LStack *s) { return s->top == NULL; }

void ls_push(LStack *s, int x) {
    SNode *n = malloc(sizeof(SNode));
    n->val  = x;
    n->next = s->top;  /* new node points at old top */
    s->top  = n;       /* top is now the new node */
    s->size++;
}

int ls_pop(LStack *s) {
    SNode *old = s->top;
    int val = old->val;
    s->top = old->next; /* top moves down one */
    free(old);
    s->size--;
    return val;
}

int ls_peek(LStack *s) { return s->top->val; }
    push(5): top→[5→NULL], size=1 push(9): top→[9→[5→NULL]], size=2 peek(): top->val=9 pop(): val=9, top→[5→NULL], free node9, size=1 pop(): val=5, top=NULL, size=0 empty(): top==NULL → 1 (true)
    Gotcha

    Save top to a temp pointer before advancing top = top->next, then free the saved pointer. If you free first, top->next is a use-after-free. Always: save the node to be freed, move the pointer, then free.

    Stack Overflow and Underflow — Guards and Detection

    Fundamentals

    Stack overflow happens when you push onto a full stack. Stack underflow happens when you pop from an empty stack. Both are silent bugs if unchecked — overflow corrupts adjacent memory, underflow reads garbage data or crashes with an array-index fault.

    On ARM Cortex-M, hardware call-stack overflow is one of the leading causes of hard faults in embedded firmware. The stack grows downward into the heap; when it collides, you get data corruption that manifests far from the actual overflow. FreeRTOS and most RTOSes paint the stack with a known canary pattern and check it periodically.

    For software stacks in algorithms, the guard is simple: check before push (is top < STACK_MAX?) and before pop (is top > 0?). In competitive programming these checks are usually omitted since input bounds guarantee the depth; in production code they are mandatory.

    Embedded firmware — call stack overflow causes HardFault on Cortex-M
    Stack grows into heap; canary detection or MPU guard region
    Recursive DFS hitting stack depth limit
    Deep trees overflow the call stack — switch to iterative
    Bracket matching on malformed input (all opens, no closes)
    Stack grows to size of input — must cap or handle gracefully
    Calculator with deeply nested parentheses
    100 levels of nesting = 100 stack frames; check capacity
    Overflow: push when full. Underflow: pop when empty.
    OVERFLOW — push on full stack (top == STACK_MAX): stk[STACK_MAX] = x; // writes beyond array → UB / memory corruption top becomes STACK_MAX+1 → next pop reads stk[STACK_MAX] = garbage UNDERFLOW — pop on empty stack (top == 0): --top → top = -1 return stk[-1]; // reads before array → UB Canary pattern (embedded): Fill stack array with 0xDEADBEEF at init. Periodically check if canary near the top is still intact. If overwritten → overflow detected before crash.
    Guard pattern: check before every push and pop. Fail loudly (assert, error return, or halt) — silent corruption is far worse than a clean error.
    #define STACK_MAX 100000
#define CANARY    0xDEADBEEFu

typedef struct {
    int  data[STACK_MAX];
    int  top;
} Stack;

/* Returns 0 on success, -1 on overflow */
int stk_push_safe(Stack *s, int x) {
    if (s->top >= STACK_MAX) return -1;  /* overflow guard */
    s->data[s->top++] = x;
    return 0;
}

/* Returns INT_MIN on underflow */
int stk_pop_safe(Stack *s) {
    if (s->top == 0) return INT_MIN;     /* underflow guard */
    return s->data[--s->top];
}

/* Embedded canary check — call from a periodic timer ISR */
void stk_check_canary(Stack *s) {
    /* check top few slots for canary overwrite */
    for (int i = STACK_MAX - 4; i < STACK_MAX; i++)
        if ((unsigned)s->data[i] != CANARY)
            __asm volatile("bkpt 0");   /* halt debugger */
}
    Overflow: STACK_MAX=3, push 3 elements (top=3), push 4th: stk_push_safe: top(3) >= STACK_MAX(3) → return -1 ✓ Underflow: top=0, call pop: stk_pop_safe: top==0 → return INT_MIN ✓ Normal: top=1, pop: --top=0, return data[0] ✓
    Gotcha

    In competitive programming, the "safe" guards add a branch to every push/pop. People often skip them and rely on input bounds — that is fine for a contest. In any code that ships, skip the guards only if you can prove the bound is never exceeded. A defensive assert(top < STACK_MAX) that fires in testing is infinitely better than silent memory corruption in production.

    Valid Parentheses — Push Open, Match on Close

    Bracket / Matching

    Given a string containing only (, ), [, ], {, }, determine whether the brackets are correctly matched and nested. The rule: every closing bracket must match the most recently opened unmatched bracket.

    "Most recently opened" is exactly LIFO — the stack holds the opens we haven't matched yet. When we see a close, we check whether it matches the top of the stack. If yes, pop and continue. If no, or if the stack is empty, the string is invalid.

    This pattern is the fundamental building block of every parser, compiler, and syntax validator ever written. XML/HTML tag matching, JSON validation, and expression parsers all reduce to this core idea.

    Firmware command-line parser — validate nested commands
    Embedded CLI with grouped command syntax
    Regular expression engine — validate character classes []
    Nested quantifiers must be balanced
    Rule: push every open bracket; on close, check it matches the top then pop.
    Input: "({[]})" char action stack ( push ( [(] { push { [(, {] [ push [ [(, {, [] ] close ]: top=[ pop → match ✓ [(, {] } close }: top={ pop → match ✓ [(] ) close ): top=( pop → match ✓ [] end stack empty → VALID ✓ Input: "([)]" char action stack ( push ( [(] [ push [ [(, [] ) close ): top=[ mismatch! → INVALID ✗
    Two failure modes: (1) a close bracket doesn't match the top — wrong type of close; (2) the stack is empty when we see a close — too many closes. A third: stack non-empty at the end — unclosed opens.
    int is_valid(const char *s) {
    char stk[10001];
    int top = 0;

    for (; *s; s++) {
        if (*s == '(' || *s == '[' || *s == '{') {
            stk[top++] = *s;          /* push any open bracket */
        } else {
            if (top == 0) return 0;   /* close but stack empty */
            char open = stk[--top];   /* pop */
            if (*s == ')' && open != '(') return 0;
            if (*s == ']' && open != '[') return 0;
            if (*s == '}' && open != '{') return 0;
        }
    }
    return top == 0;  /* valid only if no unmatched opens remain */
}
    "()[]{}": (, push. ), pop (→ match. [, push. ], pop [→ match. {, push. }, pop {→ match. top=0 → return 1 ✓ "(]": (, push. ], top=(, (≠[ → return 0 ✓ "(((": (, push×3. end: top=3≠0 → return 0 ✓
    Gotcha

    Check top == 0 before popping on a close bracket — otherwise --top goes to -1 and you read garbage. Also, at the end return top == 0, not just 1 — unclosed opens are invalid even if all closes matched.

    Longest Valid Parentheses Substring

    Bracket / Matching

    Find the length of the longest contiguous substring of correctly balanced parentheses. The trick: use a stack of indices rather than characters. Push the index of every (. When we see ), pop the matching ('s index; the length of the valid substring is i - stack_top (the index below the just-matched pair acts as the left boundary).

    Initialise the stack with -1 as a sentinel so the first unmatched ) doesn't need a special case — it just becomes the new boundary.

    Find the longest well-formed expression in a partially corrupt stream
    Recover the valid portion from garbled input

    Demonstrates stack-of-indices technique
    Stack holds indices. Bottom of stack always holds the boundary of the last unmatched ')' (or -1 initially).
    Input: "()(()" indices 0-4 stk: [-1] (sentinel) i=0 '(': push 0 stk: [-1, 0] i=1 ')': pop 0 stk: [-1] length = i - stk_top = 1 - (-1) = 2 max=2 i=2 '(': push 2 stk: [-1, 2] i=3 '(': push 3 stk: [-1, 2, 3] i=4 ')': pop 3 stk: [-1, 2] length = 4 - stk_top = 4 - 2 = 2 max=2 Result: 2 Input: ")()())" i=0 ')': pop -1 (sentinel)! stk empty → push 0 as new boundary stk: [0] i=1 '(': push 1 stk:[0,1] i=2 ')': pop 1 stk:[0] len=2-0=2 max=2 i=3 '(': push 3 stk:[0,3] i=4 ')': pop 3 stk:[0] len=4-0=4 max=4 i=5 ')': pop 0 stk empty → push 5 as new boundary Result: 4
    int longest_valid_parens(const char *s) {
    int n = strlen(s);
    int stk[n + 1], top = 0;
    stk[top++] = -1;   /* sentinel: left boundary */
    int best = 0;

    for (int i = 0; i < n; i++) {
        if (s[i] == '(') {
            stk[top++] = i;          /* push index of open */
        } else {
            top--;                   /* pop the matching open (or sentinel) */
            if (top == 0) {
                stk[top++] = i;      /* no match — this ')' is new boundary */
            } else {
                int len = i - stk[top - 1];
                if (len > best) best = len;
            }
        }
    }
    return best;
}
    "(()": push -1. i=0 '(' push 0. i=1 '(' push 1. i=2 ')' pop 1: top=2, len=2-stk[1]=2-0=2. max=2. end. return 2 ✓ (longest is "()") "(()): push -1. push 0. push 1. i=2 ')' pop 1: top=2, len=2-0=2. max=2. i=3 ')' pop 0: top=1, len=3-(-1)=4. max=4. return 4 ✓
    Gotcha

    When you pop and the stack becomes empty, push the current index i as the new boundary — don't just leave the stack empty. The next valid pair needs a boundary to measure against. Forgetting this gives wrong lengths after an unmatched ).

    Minimum Removals to Make Valid Parentheses

    Bracket / Matching

    Given a string with only ( and ), find the minimum number of brackets to remove so the remaining string is valid. A greedy two-pass approach: scan left-to-right counting unmatched closes, then right-to-left counting unmatched opens. The sum is the answer.

    The stack-based equivalent: use the stack to count unmatched opens; use a counter for unmatched closes. At the end, opens_on_stack + close_counter = minimum removals.

    int min_remove_to_valid(const char *s) {
    int open = 0;   /* unmatched '(' remaining on virtual stack */
    int close = 0;  /* unmatched ')' seen so far */

    for (; *s; s++) {
        if (*s == '(') {
            open++;
        } else {          /* ')' */
            if (open > 0)
                open--;   /* matched with an unmatched '(' */
            else
                close++;  /* no open available — must remove this ')' */
        }
    }
    return open + close;  /* unmatched opens + unmatched closes */
}

    The open counter acts as a virtual stack depth. You never need an actual stack here — open is sufficient because you only care about the count, not which specific open each close matched.

    Score of Parentheses

    Bracket / Matching

    A balanced parentheses string has a score: () = 1, and concatenated strings add scores, while a string wrapped in outer parens doubles the inner score. E.g. (()) = 2, ()() = 2, ((())) = 4.

    Stack approach: push 0 when you see ( (placeholder for "score of what's inside"). When you see ), pop the top (the inner score), and add max(2*inner, 1) to the new top. The bottom of the stack accumulates the total.

    Evaluate a scoring rule encoded as nested brackets
    Recursive score structure maps naturally to a stack
    LeetCode #856 — score of parentheses
    Shows how stacks handle nested aggregation
    Stack holds running scores at each nesting level. '(' opens a new level; ')' collapses it into the level below.
    Input: "(()(()))" char action stack ( push 0 (new level) [0, 0] ( push 0 [0, 0, 0] ) pop 0, inner=0, add max(2*0,1)=1 to top [0, 1] ( push 0 [0, 1, 0] ( push 0 [0, 1, 0, 0] ) pop 0, add max(1)=1 [0, 1, 1] ) pop 1, add max(2*1,1)=2 [0, 3] ) pop 3, add max(2*3,1)=6 [6] Result: 6 ✓ ("(()(()))": outer doubles inner (()(())) = (1+2)×2 = 6)
    int score_of_parens(const char *s) {
    int stk[200], top = 0;
    stk[top++] = 0;   /* base score accumulator */

    for (; *s; s++) {
        if (*s == '(') {
            stk[top++] = 0;              /* new nesting level */
        } else {
            int inner = stk[--top];      /* pop inner score */
            int add = inner == 0 ? 1 : 2 * inner;  /* "()" → 1, else double */
            stk[top - 1] += add;         /* add to enclosing level */
        }
    }
    return stk[0];
}
    "()": push 0. ')': pop 0, inner=0 → add 1 to stk[0]. stk=[1]. return 1 ✓ "(())": push 0, push 0. ')': pop 0 → add 1, stk=[1]. ')': pop 1 → add 2, stk=[2]. return 2 ✓ "()()": push 0. ')': add 1, stk=[1]. '(': push 0, stk=[1,0]. ')': add 1, stk=[2]. return 2 ✓
    Gotcha

    The initial stk[0]=0 is the global accumulator. Don't forget to push it before entering the loop — otherwise the first ) pops into an empty stack. The invariant is: there is always at least one element on the stack (the current level's accumulator).

    Remove Duplicate Letters (Lexicographically Smallest)

    Bracket / Matching

    Remove duplicate letters so each letter appears exactly once and the result is the lexicographically smallest possible subsequence.     Monotonic Stack Core Idea — Why Popping Finds Answers

    Monotonic Stack

    A monotonic stack is a stack that maintains its elements in strictly increasing or strictly decreasing order from bottom to top. You achieve this by popping elements that violate the order before pushing. The moment you pop an element, you have found its answer.

    This is the key insight that most people miss: popping is not housekeeping — popping IS the computation. When element X is about to be pushed and X is larger than the stack top Y, that means X is the first element to the right that is larger than Y. At the moment we pop Y, we record "the next greater element of Y is X." We got Y's answer for free, as a side effect of maintaining order.

    A monotonic stack processes every element at most twice: once pushed, once popped. This guarantees O(n) total time despite the nested loop appearance. The entire array is processed in linear time regardless of its shape.

    The direction of the scan and the order of the stack (increasing vs decreasing) determine which of the four basic queries you answer: next/previous greater/smaller. Mastering the core idea lets you derive all four variants from first principles rather than memorising four separate algorithms.

    Largest Rectangle in Histogram

    Monotonic Stack

    Given histogram bar heights, find the area of the largest rectangle that fits entirely within the histogram. For each bar, the maximum rectangle it can be part of extends left and right until it hits a bar shorter than itself. The area for bar i is height[i] × (right_boundary[i] - left_boundary[i] - 1).

    A monotonic stack (increasing order) finds both boundaries in a single O(n) pass: when we pop bar i because bar j (current) is shorter, j is i's right boundary. The new stack top (after popping) is i's left boundary. We compute the area at pop time.

    This is one of the most elegant stack problems: the pop event simultaneously reveals both the left and right boundaries for the popped bar.

    Sum of Subarray Minimums

    Monotonic Stack

    For every contiguous subarray, find its minimum element. Return the sum of all those minimums. Brute force is O(n³) or O(n²). The O(n) insight: each element arr[i] is the minimum of exactly those subarrays where it is the smallest element — the subarrays whose left and right extent don't reach a smaller element.

    Use two monotonic stack passes: prev_smaller (strict) gives the left boundary of arr[i]'s dominance, next_smaller_or_equal gives the right boundary. The number of subarrays where arr[i] is the minimum = left_span × right_span, and arr[i]'s total contribution = arr[i] × left_span × right_span.

    The strict/non-strict asymmetry on equal elements prevents double-counting: for equal-valued adjacent elements, exactly one is counted as the minimum.

    int stk[n], top;

    /* prev strictly smaller — use > to pop (keep equal elements) */
    top = 0;
    for (int i = 0; i < n; i++) {
        while (top > 0 && arr[stk[top-1]] >= arr[i]) top--;
        left[i] = (top > 0) ? i - stk[top-1] : i + 1;
        stk[top++] = i;
    }

    /* next smaller or equal — use >= to pop (consume equal elements) */
    top = 0;
    for (int i = n - 1; i >= 0; i--) {
        while (top > 0 && arr[stk[top-1]] > arr[i]) top--;
        right[i] = (top > 0) ? stk[top-1] - i : n - i;
        stk[top++] = i;
    }

    long long ans = 0;
    for (int i = 0; i < n; i++)
        ans = (ans + (long long)arr[i] * left[i] % MOD * right[i]) % MOD;

    free(left); free(right);
    return ans;
}

    Evaluate Reverse Polish Notation

    Expression / Calculation

    Reverse Polish Notation (RPN / postfix) puts the operator after its operands: 3 4 + means 3+4. No parentheses needed — operator precedence is encoded by order. The evaluation rule is simple: scan left to right; push numbers; when you see an operator, pop two numbers, apply the operator, push the result.

    RPN is how compilers internally represent expressions, how Forth-family languages work, and how HP calculators operate. It eliminates the need for parentheses by encoding evaluation order explicitly.

    Forth-like scripting language for embedded systems
    Stack-based VMs use RPN natively (used in PostScript, GFORTH)
    LeetCode #150 — Evaluate Reverse Polish Notation
    Classic O(n) stack evaluation problem
    Number → push. Operator → pop two, compute, push result. Final answer is stk[0].
    Tokens: ["2","1","+","3","*"] (meaning (2+1)*3 = 9) token action stack "2" push 2 [2] "1" push 1 [2, 1] "+" pop 1,2. 2+1=3. [3] push 3 "3" push 3 [3, 3] "*" pop 3,3. 3*3=9.     int eval_rpn(char **tokens, int n) {
    long stk[n];
    int top = 0;

    for (int i = 0; i < n; i++) {
        char *t = tokens[i];
        if (t[1] == '\0' && (*t == '+' || *t == '-' || *t == '*' || *t == '/')) {
            long b = stk[--top];   /* right operand (popped second) */
            long a = stk[--top];   /* left operand  (popped first) */
            if      (*t == '+') stk[top++] = a + b;
            else if (*t == '-') stk[top++] = a - b;
            else if (*t == '*') stk[top++] = a * b;
            else                stk[top++] = a / b;  /* C truncates toward 0 */
        } else {
            stk[top++] = atol(t);
        }
    }
    return (int)stk[0];
}

    Gotcha

    Pop order matters for non-commutative operators. The FIRST pop is the RIGHT operand (b), the SECOND pop is the LEFT operand (a). So a - b is correct, not b - a. For "3 4 -" the result is 3-4=-1, not 4-3=1. Getting this backwards is the most common RPN bug.

    Basic Calculator — Plus/Minus with Parentheses

    Expression / Calculation

    Evaluate a string expression containing non-negative integers, +, -, and (). The challenge is parentheses — they temporarily override the current sign context. The stack stores (current_result, current_sign) pairs so that when you close a parenthesis, you can restore the outer context and add in the sub-expression result.

    There is no multiplication or division — this makes it simpler than the full calculator. The sign propagates: a - before a parenthesis inverts everything inside.

    LeetCode #224 — Basic Calculator
    Plus/minus with nested parens; no multiply/divide
    Simple expression evaluation in an embedded scripting engine
    Config file expressions with grouping but no precedence
    Track running result and current sign. On '(': save (result, sign) to stack, reset. On ')': pop (outer_result, outer_sign), merge.
    Expression: "1 - (2 + 3)" = 1 - 5 = -4 Token result sign num stack '1' build num=1 ' ' result+=sign*num=1, num=0 result=1 '-' sign=-1 '(' push(result=1, sign=-1), reset result=0, sign=+1 stk:[(1,-1)] '2' num=2 '+' result+=sign*num=2, sign=+1 result=2 '3' num=3 ')' result+=sign*num=3 → result=5 pop (outer_res=1, outer_sign=-1) result = outer_res + outer_sign * result = 1 + (-1)*5 = -4 Result: -4 ✓
    int calculate_basic(const char *s) {
    int stk[100001], top = 0;
    int result = 0, sign = 1, num = 0;

    for (; *s; s++) {
        if (*s >= '0' && *s <= '9') {
            num = num * 10 + (*s - '0');    /* build multi-digit number */
        } else if (*s == '+' || *s == '-') {
            result += sign * num;            /* commit current number */
            num = 0;
            sign = (*s == '+') ? 1 : -1;
        } else if (*s == '(') {
            stk[top++] = result;             /* save outer result */
            stk[top++] = sign;               /* save sign before '(' */
            result = 0;  sign = 1;           /* reset for sub-expression */
        } else if (*s == ')') {
            result += sign * num;            /* commit final number in parens */
            num = 0;
            int outer_sign = stk[--top];
            int outer_res  = stk[--top];
            result = outer_res + outer_sign * result;
        }
        /* spaces are ignored */
    }
    return result + sign * num;  /* commit the last number */
}
    "2-(3-4)": num=2, '-': result=2, sign=-1. '(': push(2,-1), result=0,sign=1. num=3, '-': result=3, sign=-1. num=4. ')': result+=(-1)*4=3-4=-1. pop: outer_sign=-1, outer_res=2. result=2+(-1)*(-1)=3. end: result+sign*num = 3+1*0 = 3 ✓ (2-(3-4)=2-(-1)=3)
    Gotcha

    Don't forget to add sign * num to result at the very end (after the loop). The last number in the expression is never followed by an operator that would flush it — so you must commit it explicitly after the loop exits.

    Calculator with Multiply/Divide Precedence

    Expression / Calculation

    Evaluate a string expression with integers, +, -, *, /, no parentheses. Multiplication and division have higher precedence than addition and subtraction. The stack-based approach handles precedence without a full parser: treat the stack as a "pending addition" list. Multiply and divide are applied immediately to the top of the stack; addition and subtraction push a new pending term.

    LeetCode #227 — Basic Calculator II
    Precedence handling without parentheses
    Embedded: evaluate simple sensor threshold formulas at runtime

    + and -: push ±num onto the stack. * and /: pop top, compute with num, push result. Sum stack at end.
    Expression: "3+2*2-1" = 3+4-1 = 6 char num prev_op action stack '3' 3 '+' (initial) '+' '+' push sign*num=+3 stk:[3] num=0 '2' 2 '+' '*' '*' push +2 stk:[3,2] (prev=*) '2' 2 '*' '-' '-' pop 2, *num=2*2=4, push 4 stk:[3,4] prev='-' '1' 1 '-' end '-' push -1 stk:[3,4,-1] Sum: 3+4-1 = 6 ✓
    int calculate_ii(const char *s) {
    int stk[100001], top = 0;
    int num = 0;
    char prev_op = '+';   /* treat start as if preceded by '+' */

    for (int i = 0; s[i]; i++) {
        char c = s[i];
        if (c >= '0') num = num * 10 + (c - '0');  /* build number */

        if ((c == '+' || c == '-' || c == '*' || c == '/') || !s[i+1]) {
            if (prev_op == '+') stk[top++] =  num;
            if (prev_op == '-') stk[top++] = -num;
            if (prev_op == '*') stk[top-1] *= num;
            if (prev_op == '/') stk[top-1] /= num;
            prev_op = c;
            num = 0;
        }
    }
    int ans = 0;
    while (top > 0) ans += stk[--top];
    return ans;
}

    Gotcha

    For * and /, update stk[top-1] in-place (don't pop-push, just modify the top). This is equivalent to "apply immediately." The stack accumulates additive terms; multiplicative terms collapse into the most recent additive term.

    Decode String with Stack

    Expression / Calculation

    A string is encoded as k[str] meaning str repeated k times, with possible nesting: 3[a2[b]] = "abbabbabb". The stack handles nesting: when you see [, push the current string and current count; when you see ], pop the count and outer string, repeat the inner string, and append to the outer.

char *decode_string(const char *s) {
    char *str_stk[100];   /* stack of partial strings */
    int   k_stk[100];     /* stack of repeat counts */
    int   top = 0;
    char *curr = calloc(1, 10001);
    int   k = 0;

    for (; *s; s++) {
        if (*s >= '0' && *s <= '9') {
            k = k * 10 + (*s - '0');
        } else if (*s == '[') {
            k_stk[top]   = k;
            str_stk[top] = strdup(curr);   /* save current string */
            top++;
            curr[0] = '\0';               /* reset curr for inner */
            k = 0;
        } else if (*s == ']') {
            top--;
            char *outer = str_stk[top];
            int   rep   = k_stk[top];
            char *inner = strdup(curr);
            strcpy(curr, outer);
            for (int i = 0; i < rep; i++) strcat(curr, inner);
            free(inner); free(outer);
        } else {
            /* append character to curr */
            int len = strlen(curr);
            curr[len] = *s; curr[len+1] = '\0';
        }
    }
    return curr;
}

    Gotcha

    Reset k = 0 after pushing on [. If you forget, the k from the outer level leaks into the inner level computation. Also: strcat on large repetitions is O(n²) — in production, build into a proper buffer with memcpy.
