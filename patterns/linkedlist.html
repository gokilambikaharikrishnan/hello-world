L01 · Node Struct — Memory Layout and Chaining

A linked list is a chain of nodes where each node contains two things: the data you care about and the address of the next node. Think of a treasure hunt: each clue tells you what the prize is at this location and gives you the address of the next clue. The final clue has no next address — it stores NULL, signalling the end of the chain.

Unlike an array, list nodes do not need to be contiguous in memory. They can be scattered anywhere in the heap. The only connection between them is the next pointer inside each node. This means insertion and deletion at any point costs O(1) pointer rewiring — no shifting of elements — but random access to the Kth element costs O(K) because you must follow K pointers from the head.

In C, a node is a self-referential struct: it contains a pointer to its own type. This is legal because the pointer size is always known (4 or 8 bytes) even when the full struct size is not yet resolved by the compiler.

Where You See This Building any singly linked list from scratch. The Node struct is the universal building block for every pattern in this file. Embedded free-list allocator: freed blocks are chained via their own next pointer. No separate metadata needed; the node itself holds the chain link. OS task queue: each TCB (task control block) contains a next pointer for the ready list. Intrusive linked list embeds the link directly in the data structure.
Building the Logic from Scratch
A node struct has two fields: val (the payload) and next (the address of the next node or NULL).
Memory layout for list 1 -> 2 -> 3 -> NULL Address Field Value 0x1000 node1.val 1 0x1004 node1.next 0x2000 <-- points to node2 0x2000 node2.val 2 0x2004 node2.next 0x3000 <-- points to node3 0x3000 node3.val 3 0x3004 node3.next NULL (0x0000) head = 0x1000 (pointer to first node) Accessing val of node2: head->next->val = 2 Accessing val of node3: head->next->next->val = 3

#include <stdio.h>
#include <stdlib.h>

/* Self-referential struct: next points to another Node */
typedef struct Node {
    int         val;   /* payload data                        */
    struct Node *next; /* address of next node, or NULL       */
} Node;

/* Allocate one node on the heap */
Node *make_node(int val) {
    Node *n = malloc(sizeof(Node)); /* heap allocation         */
    n->val  = val;
    n->next = NULL;                 /* always initialise next  */
    return n;
}

int main(void) {
    /* Build list 1 -> 2 -> 3 -> NULL manually */
    Node *head = make_node(1);
    head->next = make_node(2);
    head->next->next = make_node(3);

    /* Walk and print */
    for (Node *p = head; p != NULL; p = p->next)
        printf("%d ", p->val);   /* 1 2 3 */
    printf("\n");

    /* Free all nodes */
    Node *cur = head;
    while (cur) { Node *tmp = cur->next; free(cur); cur = tmp; }
    return 0;
}
Step-by-step memory after building the list: make_node(1): alloc at 0x1000, val=1, next=NULL -> head=0x1000 make_node(2): alloc at 0x2000, val=2, next=NULL head->next = 0x2000: node1.next now points to node2 make_node(3): alloc at 0x3000, val=3, next=NULL head->next->next = 0x3000: node2.next now points to node3 Walk: p=0x1000->1, p=0x2000->2, p=0x3000->3, p=NULL->stop
Gotcha

Always set next = NULL when creating a node. An uninitialized next pointer is wild (points to garbage), so the loop termination check p != NULL will never fire and the traversal runs off into undefined memory.

L02 · Basic Traversal — Walking the List with a Pointer

Traversal is the act of visiting every node in the list exactly once, in order, by following next pointers from head to NULL. It is the foundation of every other operation: searching for a value, computing the length, printing the list, and finding the predecessor of a node all require traversal. Every linked list algorithm begins with "walk the list until you reach the target."

The idiom is a single pointer variable (call it p or curr) that starts at head and advances one step per iteration: p = p->next. The loop condition is p != NULL (or equivalently p). When p becomes NULL, you have passed the last node and the loop exits.

Where You See This Print all values, compute sum, find maximum. All require visiting every node exactly once. Search for a node with a specific value. Walk until p->val == target or p == NULL (not found). Count the length of the list. Increment a counter for each node visited; return it after traversal.
Building the Logic from Scratch
Start p at head. Each step: process p->val, then p = p->next. Stop when p == NULL.
List: [1]->[2]->[3]->[4]->NULL Step 1: p=&[1] process val=1 p = p->next -> &[2] Step 2: p=&[2] process val=2 p = p->next -> &[3] Step 3: p=&[3] process val=3 p = p->next -> &[4] Step 4: p=&[4] process val=4 p = p->next -> NULL Step 5: p=NULL loop ends

#include <stdio.h>

typedef struct Node { int val; struct Node *next; } Node;

/* Print every value */
void print_list(Node *head) {
    for (Node *p = head; p != NULL; p = p->next)
        printf("%d ", p->val);
    printf("\n");
}

/* Count nodes */
int length(Node *head) {
    int cnt = 0;
    for (Node *p = head; p; p = p->next) cnt++;
    return cnt;
}

/* Find node by value; returns pointer or NULL */
Node *find(Node *head, int target) {
    for (Node *p = head; p; p = p->next)
        if (p->val == target) return p;
    return NULL;
}
find(head, 3) on list 1->2->3->4->NULL: p=1: 1!=3, p=p->next p=2: 2!=3, p=p->next p=3: 3==3, return p -> found node with val=3 length(head) on same list: p=1: cnt=1, p=p->next p=2: cnt=2, p=p->next p=3: cnt=3, p=p->next p=4: cnt=4, p=p->next p=NULL: return 4
Gotcha

Never advance the pointer with head = head->next inside the traversal loop if you need head again afterward — that destroys your only reference to the list. Always use a separate traversal variable p = head.

Visit every node -> for (Node *p = head; p; p = p->next). Use separate p, never advance head itself.
  • Search: if (p->val == target) return p;
  • Count: cnt++ each iteration, return cnt
  • Find tail: while (p->next) p = p->next; return p;

L03 · Dummy Head Node Trick — Eliminating Edge Cases

Many linked list operations have awkward special cases for the head node. Inserting before the first node changes head; deleting the first node changes head; building a list by appending requires checking if the list is empty. The dummy head (also called sentinel head or fake head) eliminates all of these by introducing a node that sits before the real first node and never moves or gets deleted.

The dummy node has no meaningful value. Its next pointer is the real head. All operations that would otherwise need to special-case the head can now treat every node identically — because every real node always has a predecessor (at worst, the dummy). At the end of the operation, the real head is dummy.next.

Where You See This Building a list by tail-appending in a loop. Dummy lets you start with a valid tail pointer without an empty-list check. Deleting a node by value when it might be the head. Every node has a prev; no special case for head deletion. Merge two sorted lists, partition list, remove Nth from end. These algorithms all produce a result list; dummy is the anchor for the output.
Building the Logic from Scratch
Declare Node dummy = {0, NULL}. Set tail = &dummy. Append to tail->next and advance tail. Real result starts at dummy.next.
BEFORE (building list 1->2->3): dummy -> NULL tail = &dummy Append 1: tail->next = new Node(1) => dummy -> [1] -> NULL tail = tail->next => tail points to [1] Append 2: tail->next = new Node(2) => dummy -> [1] -> [2] -> NULL tail = tail->next => tail points to [2] Append 3: tail->next = new Node(3) => dummy -> [1] -> [2] -> [3] -> NULL tail = tail->next RESULT: dummy.next = &[1] (real head of list)

#include <stdio.h>
#include <stdlib.h>

typedef struct Node { int val; struct Node *next; } Node;
Node *mk(int v) { Node *n=malloc(sizeof(Node)); n->val=v; n->next=NULL; return n; }

/* Build list from array using dummy head */
Node *build(int *arr, int n) {
    Node dummy = {0, NULL};        /* dummy sits before the real list  */
    Node *tail = &dummy;           /* tail always points to last node  */
    for (int i = 0; i < n; i++) {
        tail->next = mk(arr[i]);   /* append new node after tail       */
        tail = tail->next;         /* advance tail to new last node    */
    }
    return dummy.next;             /* real head (dummy.next)           */
}

/* Delete first occurrence of val; dummy eliminates head special case */
Node *delete_val(Node *head, int val) {
    Node dummy = {0, head};        /* dummy.next = head                */
    Node *prev = &dummy;
    Node *curr = head;
    while (curr) {
        if (curr->val == val) {
            prev->next = curr->next; /* unlink curr                   */
            free(curr);
            break;
        }
        prev = curr;
        curr = curr->next;
    }
    return dummy.next;             /* head may have changed            */
}

int main(void) {
    int arr[] = {1, 2, 3, 4, 5};
    Node *h = build(arr, 5);
    h = delete_val(h, 1);          /* delete head node -- no special case */
    for (Node *p = h; p; p = p->next) printf("%d ", p->val); /* 2 3 4 5 */
    printf("\n");
    while (h) { Node *t=h->next; free(h); h=t; }
    return 0;
}
delete_val(head=&[1], val=1): dummy = {0, &[1]} prev=&dummy curr=&[1] curr->val==1: prev->next = curr->next = &[2] dummy.next now = &[2] free(node1) return dummy.next = &[2] (new head) No special case needed even though we deleted the head node.
Gotcha

The dummy is usually declared as a stack variable (Node dummy = {0, head};), not malloc'd. Do not free(&dummy) at the end — it lives on the stack. Only the real nodes (dummy.next onward) were malloc'd.

  2. After Node dummy = {0, head};, what is dummy.next?
  3. What would go wrong if you returned &dummy instead of dummy.next?
Any list op that may change head -> use dummy: Node dummy={0,head}; work on dummy.next; return dummy.next as new head.
  • Build by appending -> tail=&dummy; tail->next=new_node; tail=tail->next
  • Delete head-possibly -> prev=&dummy; unlink curr; return dummy.next
  • Merge/partition output -> dummy as anchor; real result = dummy.next

L04 · prev/curr/next — The Triple Pointer Walk Pattern

Most non-trivial linked list operations — deletion, insertion in the middle, reversal — need to know not just the current node but also its predecessor. In a singly linked list you cannot go backward, so you carry three pointers simultaneously: prev (one step behind curr), curr (the node being processed), and next (one step ahead, saved before any rewiring so you don't lose the rest of the list).

The discipline is always the same: save next = curr->next before touching any pointers, do the rewiring, then advance all three pointers one step forward. Saving next first is critical — rewiring curr's pointer before saving it loses the rest of the list forever.

Where You See This Iterative list reversal (L07): redirect every next pointer backward. prev captures where we came from; next captures where to go next. Delete node by value without dummy head. prev->next = curr->next unlinks curr; prev is required for this. Insert a node between two existing nodes. new->next = curr; prev->next = new connects the new node into the chain.
Building the Logic from Scratch
Save next FIRST. Then rewire. Then advance. In that order, always.
List: [1] -> [2] -> [3] -> [4] -> NULL Deleting node with val=2: Initial: prev=NULL curr=[1] (scan forward) Step 1: prev=[1] curr=[2] <-- found target next = curr->next = [3] prev->next = next [1]->next now points to [3] free(curr) Result: [1] -> [3] -> [4] -> NULL BEFORE delete: [1] -> [2] -> [3] -> [4] -> NULL AFTER delete: [1] -> [3] -> [4] -> NULL

#include <stdio.h>
#include <stdlib.h>

typedef struct Node { int val; struct Node *next; } Node;
Node *mk(int v){Node *n=malloc(sizeof(Node));n->val=v;n->next=NULL;return n;}

/* Delete node with given val; return new head */
Node *delete_node(Node *head, int val) {
    Node *prev = NULL, *curr = head;
    while (curr) {
        Node *next = curr->next;     /* SAVE next before any rewiring   */
        if (curr->val == val) {
            if (prev) prev->next = next; /* unlink: prev skips curr     */
            else      head = next;       /* deleting head: update head  */
            free(curr);
            return head;
        }
        prev = curr;                 /* advance prev to current         */
        curr = next;                 /* advance curr using saved next   */
    }
    return head;                     /* val not found                   */
}

int main(void) {
    Node *h = mk(1); h->next = mk(2); h->next->next = mk(3);
    h = delete_node(h, 2);
    for (Node *p = h; p; p = p->next) printf("%d ", p->val); /* 1 3 */
    printf("\n");
    while (h) { Node *t=h->next; free(h); h=t; }
    return 0;
}
List: [1]->[2]->[3]->NULL delete val=2 prev=NULL curr=[1] curr->val=1 != 2 prev=[1], curr=[2] prev=[1] curr=[2] curr->val=2 == 2 next = [3] prev->next = [3] ([1]->next now points to [3]) free([2]) return head=[1] Result: [1]->[3]->NULL
Gotcha

Saving next = curr->next AFTER rewiring curr->next loses the rest of the list. The save must always happen as the very first action inside the loop body, before any pointer is modified.

Confidence Check
  1. What is the purpose of next = curr->next at the top of the loop, before any rewiring?
  2. After deleting curr, why do we return immediately rather than continuing the loop?
  3. How does this pattern handle deleting the last node in the list?
Modify a node's links -> triple walk: save next first, rewire, then advance. Order: save -> rewire -> advance.
  • Delete curr: prev->next = curr->next; free(curr)
  • Insert after curr: new->next=curr->next; curr->next=new
  • Reverse step: curr->next=prev; prev=curr; curr=saved_next

L05 · Insert Node — At Head, Tail, and Position

Insertion is one of the linked list's strongest advantages over arrays: inserting anywhere costs O(1) pointer rewiring once you are at the right location (finding the location still costs O(n)). There are three canonical cases: insert at head (prepend), insert at tail (append), and insert at a given position (after finding the predecessor).

Insert at head is the simplest: set new->next = head, then update head to the new node. Insert at tail requires finding the last node first, then setting last->next = new. Insert at position k requires walking k-1 steps to reach the predecessor, then splicing in the new node.

Where You See This Stack push on a linked list: insert at head, O(1). Head insertion is the cheapest operation; it becomes the stack push. Queue enqueue: insert at tail (with a tail pointer for O(1)). With a tail pointer, tail append is also O(1). Sorted insert: find the right position by value, splice in the new node. Walk until next->val > new->val, then insert between curr and next.
Building the Logic from Scratch
Three cases, each a two-step rewire: (1) new->next=head; head=new. (2) tail->next=new; tail=new. (3) new->next=prev->next; prev->next=new.
INSERT AT HEAD (prepend 0 to [1]->[2]): BEFORE: head->[1]->[2]->NULL new->next = head => [0]->[1]->[2] head = new => head->[0]->[1]->[2] AFTER: head->[0]->[1]->[2]->NULL INSERT AT TAIL (append 3 to [1]->[2]): BEFORE: [1]->[2]->NULL walk to tail: tail=[2] tail->next = new => [1]->[2]->[3]->NULL AFTER: [1]->[2]->[3]->NULL INSERT AT POSITION 1 (0-indexed) (insert 9 between [1] and [2]): BEFORE: [1]->[2]->[3]->NULL walk to predecessor: prev=[1] (0 steps) new->next = prev->next = [2] => [9]->[2]->[3] prev->next = new => [1]->[9]->[2]->[3] AFTER: [1]->[9]->[2]->[3]->NULL

#include <stdio.h>
#include <stdlib.h>

typedef struct Node { int val; struct Node *next; } Node;
Node *mk(int v){Node *n=malloc(sizeof(Node));n->val=v;n->next=NULL;return n;}

Node *insert_head(Node *head, int val) {
    Node *n = mk(val);
    n->next = head;          /* new node points to old head            */
    return n;                /* new node IS the new head               */
}

Node *insert_tail(Node *head, int val) {
    Node *n = mk(val);
    if (!head) return n;     /* empty list: new node is head and tail  */
    Node *tail = head;
    while (tail->next) tail = tail->next;  /* walk to last node       */
    tail->next = n;          /* last node now points to new node       */
    return head;
}

/* Insert after the node at 0-indexed position pos */
Node *insert_at(Node *head, int val, int pos) {
    if (pos == 0) return insert_head(head, val);
    Node *prev = head;
    for (int i = 0; i < pos - 1 && prev; i++) prev = prev->next;
    if (!prev) return head;  /* pos out of range                       */
    Node *n = mk(val);
    n->next    = prev->next; /* new node points to what was after prev */
    prev->next = n;          /* prev now points to new node            */
    return head;
}

int main(void) {
    Node *h = NULL;
    h = insert_tail(h, 2); h = insert_tail(h, 3);
    h = insert_head(h, 1);
    h = insert_at(h, 9, 1);
    for (Node *p=h; p; p=p->next) printf("%d ", p->val); /* 1 9 2 3 */
    printf("\n");
    while (h){Node *t=h->next;free(h);h=t;}
    return 0;
}
insert_at(head=[1]->[2]->[3], val=9, pos=1): pos != 0, walk to prev at pos-1=0: prev=[1] n = new node(9) n->next = prev->next = [2] => [9]->[2]->[3] prev->next = n => [1]->[9]->[2]->[3] return head=[1] Final list: [1]->[9]->[2]->[3]->NULL
Gotcha

In insert_at, always set n->next = prev->next BEFORE prev->next = n. If you do it in reverse, prev->next is overwritten to n before you copy it to n->next, and the rest of the list is lost.

Confidence Check
  1. Why does insert_head return the new node rather than modifying head in-place?
  2. What is the time complexity of insert_tail without a tail pointer? With one?
  3. What does insert_at do if pos is greater than the list length?
Insert head: new->next=head; return new. Insert tail: walk to last, last->next=new. Insert middle: new->next=prev->next; prev->next=new.
  • Stack push -> insert_head, O(1)
  • Queue enqueue -> insert_tail with tail ptr, O(1)
  • Sorted insert -> walk while next->val < val, then splice

L06 · Delete Node — By Value and By Position

Deleting a node from a singly linked list requires knowing the node's predecessor, because the predecessor's next pointer must be updated to skip the deleted node. Since there is no backward pointer, you must walk the list carrying a prev pointer alongside curr. The dummy head trick (L03) simplifies the head-deletion case by ensuring every real node always has a predecessor.

After unlinking the node (prev->next = curr->next), you must free it if it was heap-allocated. Forgetting to free is a memory leak; freeing and then accessing the node is a use-after-free bug. The correct sequence: save any data you need, unlink, free, done.

Where You See This Remove a task from an OS ready queue by TCB pointer. Walk the list, find the node, unlink it, the task is dequeued. Remove duplicate entries from a sorted list. While curr->val == curr->next->val, delete curr->next. Remove all nodes matching a condition (filter). Delete every node where pred(curr->val) is true; walk continues.
Building the Logic from Scratch
Use a dummy head. Walk prev and curr together. When curr is the target: prev->next = curr->next, free curr, done. Return dummy.next as new head.
Delete val=3 from [1]->[2]->[3]->[4]->NULL BEFORE: dummy->[1]->[2]->[3]->[4]->NULL prev=dummy curr=[1]: val=1!=3, advance prev=[1] curr=[2]: val=2!=3, advance prev=[2] curr=[3]: val=3==3, TARGET FOUND Rewire: prev->next = curr->next [2]->next now points to [4] (skipping [3]) free([3]) AFTER: dummy->[1]->[2]->[4]->NULL return dummy.next = [1]

#include <stdio.h>
#include <stdlib.h>

typedef struct Node { int val; struct Node *next; } Node;
Node *mk(int v){Node *n=malloc(sizeof(Node));n->val=v;n->next=NULL;return n;}

/* Delete first occurrence of val; use dummy to handle head deletion */
Node *del_val(Node *head, int val) {
    Node dummy = {0, head};
    Node *prev = &dummy, *curr = head;
    while (curr) {
        if (curr->val == val) {
            prev->next = curr->next;  /* skip over curr                */
            free(curr);               /* release memory                */
            return dummy.next;        /* done -- head may have changed */
        }
        prev = curr;
        curr = curr->next;
    }
    return dummy.next;  /* val not found, list unchanged               */
}

/* Delete node at 0-indexed position */
Node *del_pos(Node *head, int pos) {
    Node dummy = {0, head};
    Node *prev = &dummy;
    for (int i = 0; i < pos && prev->next; i++) prev = prev->next;
    Node *target = prev->next;
    if (target) {
        prev->next = target->next;    /* unlink target                 */
        free(target);
    }
    return dummy.next;
}

int main(void) {
    Node *h = mk(1); h->next=mk(2); h->next->next=mk(3); h->next->next->next=mk(4);
    h = del_val(h, 3);
    for (Node *p=h;p;p=p->next) printf("%d ",p->val); /* 1 2 4 */
    printf("\n");
    h = del_pos(h, 0);  /* delete head */
    for (Node *p=h;p;p=p->next) printf("%d ",p->val); /* 2 4 */
    printf("\n");
    while(h){Node *t=h->next;free(h);h=t;}
    return 0;
}
del_pos(head=[1]->[2]->[4], pos=0): dummy={0,[1]} prev=&dummy i=0: loop condition i<0 is FALSE, loop does not run target = prev->next = [1] prev->next = [1]->next = [2] (dummy->next now = [2]) free([1]) return dummy.next = [2] (new head)
Gotcha

After free(curr), do NOT read curr->next or any field of curr. If you need curr->next for the next iteration, save it as Node *next = curr->next before calling free.

Confidence Check

  2. What is the correct order of operations when deleting curr: save next, unlink, or free first?
  3. How would you delete ALL nodes matching a value (not just the first)?
Delete a node -> dummy head, walk prev+curr, on match: prev->next=curr->next; free(curr); return dummy.next.
  • Delete first match -> break after free
  • Delete all matches -> continue loop (don't break) using saved next
  • Delete by position -> walk prev pos steps, then unlink prev->next
L07

Reverse Full List — Iterative (prev/curr/next)

Reversal

Reversing a linked list is like a one-way street that needs to flip direction. Every arrow currently points forward — you must redirect each arrow to point backward, one at a time, without losing the rest of the chain.

The three-pointer dance: save next before you break the link, flip the link, then slide all three pointers one step forward.

Palindrome check on a linked list (reverse second half)
Need reversed copy to compare
Reorder list (L0→Ln→L1→Ln-1)
Reverse second half first
Add two numbers stored in lists (MSB first)

        return head;                    /* base: 0 or 1 nodes */

Node *reverse_between(Node *head, int m, int n) {
    Node dummy = {0, head};
    Node *pre = &dummy;

    /* walk pre to the node just before position m */
    for (int i = 1; i < m; i++)
        pre = pre->next;

    Node *curr = pre->next;          /* first node of the window */

    /* front-insert n-m times */
    for (int i = 0; i < n - m; i++) {
        Node *next = curr->next;     /* node to pull to front */
        curr->next = next->next;     /* unlink next from chain */
        next->next = pre->next;      /* next now points at window head */
        pre->next = next;            /* pre now points at next */
    }
    return dummy.next;
}

static Node *kth(Node *curr, int k) {
    while (curr && k-- > 0)
        curr = curr->next;
    return curr;
}

Node *reverse_k_groups(Node *head, int k) {
    Node dummy = {0, head};
    Node *group_prev = &dummy;   /* tail of the already-processed part */

    while (1) {
        Node *kth_node = kth(group_prev, k);
        if (!kth_node) break;    /* fewer than k nodes left — stop */

        Node *group_next = kth_node->next;  /* first node after this group */

        /* reverse k nodes starting from group_prev->next */
        Node *prev = group_next;
        Node *curr = group_prev->next;
        for (int i = 0; i < k; i++) {
            Node *nxt = curr->next;
            curr->next = prev;
            prev = curr;
            curr = nxt;
        }

        /* stitch: group_prev → new group head; old group head → group_next */
        Node *old_head = group_prev->next;  /* will become group tail */
        group_prev->next = kth_node;        /* kth_node is new group head */
        group_prev = old_head;              /* advance group_prev to new tail */
    }
    return dummy.next;
}

    while (curr && k-- > 0) curr = curr->next;

    /* Phase 1: find meeting point */
    while (fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) break;

        slow = slow->next;

    return ptr;   /* cycle entry node */
}

Node *kth_from_end(Node *head, int k) {

    Node *follower = head;

    /* advance runner k steps */
    for (int i = 0; i < k; i++) {
        if (!runner) return NULL;   /* list shorter than k */
        runner = runner->next;

    /* move both until runner == NULL */
    while (runner) {
        runner   = runner->next;
        follower = follower->next;
    }
    return follower;
}

            b = b->next;

Merge K Sorted Lists

Merge and Sort

Merging K sorted lists at once naively (pick min from K heads each step) costs O(N·K). The efficient approach: divide and conquer — pair up the K lists, merge each pair, repeat until one list remains. This is O(N log K).

Alternatively use a min-heap of K heads for O(N log K) with less code in languages that have heaps. In C, the divide-and-conquer approach is simpler.

Classic merge-sort merge step
4 lists: divide and conquer in log2(4)=2 rounds
Round 1: pair up merge(list[0], list[1]) → merged01 merge(list[2], list[3]) → merged23 Round 2: pair up again merge(merged01, merged23) → final result K=5: round1 pairs (0,1),(2,3), list[4] is unpaired → carry forward merge(list[0],list[1]) → m01 merge(list[2],list[3]) → m23 list[4] unchanged round2: merge(m01,m23) → m0123 merge(m0123,list[4]) → final Total merges: O(K) per round × O(log K) rounds = O(K log K) merges Each merge O(n/K nodes) on average → total O(N log K)
Each round halves the number of lists. Total list-pairs processed is O(K), total nodes touched per round is O(N), and there are O(log K) rounds.
/* merge_two_sorted from L16 assumed available */

Node *merge_k_lists(Node **lists, int k) {
    if (k == 0) return NULL;
    int count = k;
    while (count > 1) {
        int new_count = 0;
        for (int i = 0; i < count; i += 2) {
            if (i + 1 < count)
                lists[new_count++] = merge_two_sorted(lists[i], lists[i+1]);
            else
                lists[new_count++] = lists[i];  /* odd one out */
        }
        count = new_count;
    }
    return lists[0];
}

Gotcha

Sort Linked List — Merge Sort

Merge and Sort

Merge sort is the optimal comparison sort for linked lists: O(n log n) time, O(log n) stack space, and no random access needed. QuickSort is poor on lists because finding the pivot's final position requires a pass.

Pattern: find the middle (use first-middle variant to avoid infinite recursion), split there, recursively sort both halves, merge them back together.

Log is a linked list; merge sort fits naturally
Sort: 4→2→1→3
split at middle (first-mid variant): left = 4→2 right = 1→3 sort(4→2): split: left=4 right=2 sort(4)→4 sort(2)→2 merge(4,2) → 2→4 sort(1→3): split: left=1 right=3 sort(1)→1 sort(3)→3 merge(1,3) → 1→3 merge(2→4, 1→3): 1<2 → [1], 2<3 → [2], 3<4 → [3], append 4 → 1→2→3→4 ✓
Critical: use the first-middle variant (stop when fast->next->next==NULL) so the left half always has at least one node. Using the second-middle variant causes infinite recursion on 2-node lists.
static Node *split_half(Node *head) {
    /* returns head of second half; first half ends at slow */
    Node *slow = head, *fast = head;
    while (fast->next && fast->next->next) {
        slow = slow->next;
        fast = fast->next->next;
    }
    Node *second = slow->next;
    slow->next = NULL;   /* cut the list */
    return second;
}

Node *sort_list(Node *head) {
    if (!head || !head->next) return head;   /* 0 or 1 node */

    Node *right = split_half(head);          /* split; head = left half */
    Node *left  = sort_list(head);
    right       = sort_list(right);
    return merge_two_sorted(left, right);
}
Input: 3→1→2
split: left=3→1, right=2 (slow stops at node1, second=node2, node1→next=NULL)
sort(3→1): split left=3,right=1; merge(3,1)=1→3
sort(2)=2
merge(1→3, 2): 1,2,3 → 1→2→3 ✓
Gotcha
slow->next = NULL after finding the split point is essential — it terminates the left half. Without it both recursive calls receive the full list and you recurse infinitely. Set the cut before making any recursive calls.
Confidence Check

Two dummy heads eliminate all edge cases. The lo tail's next must be set to NULL after joining (the last hi node's next is already NULL, but lo_tail's original next pointer might still dangle).
Node *partition(Node *head, int x) {
    Node lo_dummy = {0, NULL}, hi_dummy = {0, NULL};
    Node *lo = &lo_dummy, *hi = &hi_dummy;

    for (Node *curr = head; curr; curr = curr->next) {
        if (curr->val < x) {
            lo->next = curr;
            lo = lo->next;
        } else {
            hi->next = curr;
            hi = hi->next;
        }
    }
    hi->next = NULL;          /* terminate hi list (avoid stale next) */
    lo->next = hi_dummy.next; /* stitch lo tail to hi head */
    return lo_dummy.next;
}

Gotcha
Always set hi->next = NULL before joining. The last node routed to hi still has its original next pointer which may point into the lo list — creating a cycle. Terminate hi explicitly.
