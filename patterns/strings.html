Pattern 01 Null Terminator and String Length
① Background

In C, a string is not a first-class type — it is a convention: a contiguous sequence of char values ending with a zero byte ('\0', ASCII value 0). Every standard library function that takes a string relies on finding this sentinel to know where the string ends. There is no hidden length field, no bounds checking, and no exception if the null terminator is missing — the function just keeps reading memory until it finds a zero byte or crashes.

strlen(s) counts bytes from s[0] until it hits '\0', then returns that count — not including the null byte itself. This is O(n). Calling strlen in a loop header (for (int i = 0; i < strlen(s); i++)) recomputes the length on every iteration — an O(n²) bug hiding in plain sight.

sizeof(arr) on a char array gives the total allocated bytes including the null terminator. On a char * pointer it gives the pointer size (4 or 8), not the string length. These two are frequently confused: char buf[10] = "hello" has sizeof(buf) = 10 but strlen(buf) = 5.

When you declare char buf[n] and want to store a string of length L, you need n ≥ L + 1 — one extra byte for '\0'. Forgetting the +1 is the root cause of countless off-by-one buffer overflows. After manual construction of a string in a buffer, always write buf[len] = '\0' explicitly.

② Where You See This
  • Any strlen call in a loop conditionrecomputes length O(n) per iteration; cache it before the loop
  • Embedded firmware string buffersfixed-size char arrays on the stack; must reserve the null byte or corrupt adjacent memory
  • Network packet parsingreading a C-string from a socket; must null-terminate the receive buffer before calling strlen
  • LeetCode 344 / 541 — Reverse Stringmodify char array in-place; null terminator marks the end so you know where to stop
  • Manual string buildersappending characters one by one into a buf[] — track index and always write '\0' at the end
  • UART / serial driver outputtransmit-until-null loops; a missing '\0' causes the driver to send garbage bytes indefinitely
③ Building the Logic from Scratch

How strlen works internally: it is just a pointer walk. Start at the beginning, advance until the byte is zero, return the distance traveled.

s = "hello"

Memory layout (6 bytes):
 index:  0    1    2    3    4    5
 char:  'h'  'e'  'l'  'l'  'o'  '\0'
 value:  104  101  108  108  111   0

strlen starts at index 0, walks right until value == 0.
Stops at index 5 (the '\0'), returns 5.
sizeof("hello") = 6  (the string literal includes the null byte)

The loop-condition bug:

WRONG — strlen called on every iteration:
for (int i = 0; i < strlen(s); i++)   /* O(n) per check → O(n²) total */

CORRECT — cache the length once:
int n = strlen(s);
for (int i = 0; i < n; i++)           /* O(1) per check → O(n) total */

Aha moment: strlen has no magic — it is a linear scan every time you call it. If the string does not change inside the loop, calling strlen once before the loop and storing the result is free speed.

sizeof vs strlen:

char arr[] = "hello";    /* compiler sets aside 6 bytes */
sizeof(arr)  == 6        /* total allocated bytes, compile-time constant */
strlen(arr)  == 5        /* bytes before '\0', runtime scan */

char *ptr = "hello";
sizeof(ptr)  == 8        /* pointer size on 64-bit — NOT the string length */
strlen(ptr)  == 5        /* still works: follows the pointer and scans */

Pattern 02 char* vs char[] — Pointer vs Array
① Background

char *p = "hello"; and char a[] = "hello"; look nearly identical but behave very differently. The pointer form makes p point to a string literal — a read-only block of memory placed in the program's data segment by the compiler. Attempting to write through p (like p[0] = 'H';) is undefined behavior on all modern systems, and on most it causes a segmentation fault.

The array form copies the literal's bytes into a writable char array on the stack (or in static storage, depending on where it is declared). a[0] = 'H'; is perfectly legal — you own those bytes. The key difference: char[] gives you a private, mutable copy; char * gives you a read-only view.

Function parameters that look like char arr[] are actually char * — the array decays to a pointer at the call site. Inside the function, sizeof(arr) gives the pointer size, not the original array size. This array-to-pointer decay is one of C's most pervasive implicit conversions.

When you want to modify a string passed into a function, the caller must pass a writable buffer (a char[] or heap-allocated memory), not a pointer to a string literal. Documenting whether a function modifies its argument is essential — const char * signals read-only, plain char * signals potentially writable.

② Where You See This
  • Function signature designconst char* for read-only input; char* or char[] for output/modification buffers
  • String literal segfault bugsassigning to char* then trying to modify — crashes on Linux/macOS, silent corruption on some embedded targets
  • Returning strings from functionsreturning a pointer to a local char[] is a dangling pointer; must return heap-allocated or static storage
  • LeetCode string problems in Cchar** parameters for arrays of strings; each element may be a literal (don't modify) or heap (safe to modify)
  • argv in main()argv[i] is char* pointing to OS-managed memory; modifying it is implementation-defined
  • ROM / flash strings in microcontrollersstring literals stored in flash (const); writing through char* pointer faults or silently fails

Pattern 03 Safe String Copy
① Background

strcpy(dst, src) copies bytes from src into dst until it copies the null terminator. It does zero bounds checking. If src is longer than dst can hold, strcpy writes past the end of dst — a classic buffer overflow. In security contexts, this is a code execution vulnerability; in embedded systems, it silently corrupts adjacent variables on the stack.

strncpy(dst, src, n) was designed to fix this, but it introduces its own hazard: if src has n or more bytes before its null terminator, strncpy copies exactly n bytes and does NOT append a null terminator to dst. Calling strlen or printf on dst then reads garbage. The idiom is to always follow strncpy with dst[n-1] = '\0'; to guarantee termination.

The modern idiomatic safe copy in C is to use snprintf(dst, size, "%s", src) — it always null-terminates and returns the number of characters that would have been written, so you can detect truncation. Some codebases use strlcpy (BSD/macOS) which also always null-terminates, but it is not in the C standard library.

When you own both buffers and know the sizes, the cleanest pattern is: compute the copy length as min(src_len, dst_size - 1), use memcpy for that many bytes, then write the null terminator manually. This avoids strncpy's quirks entirely.

  • Embedded config string parsingreading a string field from EEPROM into a fixed char[32] buffer
  • LeetCode string manipulation problemscopying substrings into output buffers in C solutions
  • Network protocol field extractionextracting a hostname field from a packet into a local buffer with strncpy + force-null
  • File path constructionbuilding paths with snprintf to prevent truncated paths from writing to wrong locations

③ Building the Logic from Scratch

What strcpy does (and why it is dangerous):

src = "hello world"   (11 chars + '\0' = 12 bytes)
dst = char[6]         (only 6 bytes allocated)

strcpy(dst, src):
dst[0]='h' dst[1]='e' dst[2]='l' dst[3]='l' dst[4]='o' dst[5]=' '
dst[6]='w' dst[7]='o' ...  ← past the end of dst! corrupts stack

Safe copy recipe:

dst_size = 6   (buffer capacity including null byte)
src_len  = strlen(src) = 11
copy_len = min(src_len, dst_size - 1) = min(11, 5) = 5

memcpy(dst, src, 5);   copies 'h','e','l','l','o'
dst[5] = '\0';         writes null terminator

result: dst = "hello"  (safely truncated, always terminated)

Aha moment: the "safe" in safe copy has two requirements — (1) never write past dst's end, and (2) always leave dst null-terminated. strncpy satisfies only the first. Every safe alternative must satisfy both.

④ Full Code Walkthrough
#include <string.h>
#include <stdio.h>

/* Safe copy: always null-terminates, never overflows dst. */
void safe_strcpy(char *dst, const char *src, int dst_size) {
    if (dst_size <= 0) return;           /* nothing to write */
    int i = 0;
    while (i < dst_size - 1 && src[i]) { /* leave 1 slot for '\0' */
        dst[i] = src[i];
        i++;
    }
    dst[i] = '\0';                        /* always terminate */
}

/* Using snprintf — idiomatic modern C */
void snprintf_copy(char *dst, int dst_size, const char *src) {
    int written = snprintf(dst, dst_size, "%s", src);
    if (written >= dst_size) {
        /* truncation occurred: written holds what would have been written */
    }
    /* dst is always null-terminated by snprintf */
}

/* The strncpy + force-null idiom (common in C89 codebases) */
void strncpy_safe(char *dst, const char *src, int dst_size) {
    strncpy(dst, src, dst_size - 1);   /* copy at most dst_size-1 bytes */
    dst[dst_size - 1] = '\0';           /* force null terminator */
}

Pattern 04 String Comparison (strcmp)
① Background

strcmp(a, b) compares two C strings lexicographically — character by character using ASCII values. It returns a negative number if a comes before b, zero if they are equal, or a positive number if a comes after b. The exact magnitude of the non-zero return is implementation-defined; only the sign matters.

The most common beginner mistake is comparing strings with ==: if (s1 == s2) compares the two pointer values (memory addresses), not the string contents. Two equal strings stored in different arrays have different addresses and will compare as not-equal. This bug is silent — the code compiles without warning and runs without crashing, but gives the wrong answer.

Lexicographic order follows ASCII values: uppercase letters come before lowercase ('A'=65, 'a'=97). "Apple" < "apple" and "B" < "a". For case-insensitive comparison, use strcasecmp (POSIX) or roll your own with tolower on each character before comparing.

strncmp(a, b, n) compares at most n characters and is the bounded form — useful for checking a prefix or comparing fixed-length fields without requiring a null terminator in either string.

③ Building the Logic from Scratch

How strcmp works: walk both strings simultaneously, comparing ASCII values. Stop at the first difference or when both reach '\0'.

strcmp("cat", "car"):
  i=0: 'c'=='c' → continue
  i=1: 'a'=='a' → continue
  i=2: 't' vs 'r'  →  't'(116) - 'r'(114) = +2  → return positive
  → "cat" comes AFTER "car" lexicographically

strcmp("dog", "dog"):
  i=0,1,2: all equal
  i=3: both '\0' → equal → return 0

strcmp("", "a"):
  i=0: '\0' vs 'a' → '\0'(0) - 'a'(97) = -97 → return negative
  → empty string comes BEFORE "a"

qsort comparator pattern:

int cmp_str(const void *a, const void *b) {
    return strcmp(*(const char **)a, *(const char **)b);
}
/* Usage: qsort(arr, n, sizeof(char*), cmp_str); */

Why *(const char **)a ?
  qsort passes pointers to the array elements.
  Each element is itself a char* (a string pointer).
  So a is char** — dereference once to get the char*.

Aha moment: strcmp returns the difference of the first differing characters (conceptually). The sign tells you the order; zero means equal. Never check strcmp(a,b) == true — that checks for return value 1, which is NOT what "equal" means. Always check strcmp(a,b) == 0 for equality.

④ Full Code Walkthrough
#include <string.h>
#include <stdlib.h>

/* Manual strcmp implementation */
int my_strcmp(const char *a, const char *b) {
    while (*a && *a == *b) {   /* advance while both match and not at end */
        a++; b++;
    }
    return (unsigned char)*a - (unsigned char)*b;  /* cast to avoid sign issues */
}

/* qsort comparator for an array of char* */
int cmp_strings(const void *x, const void *y) {
    /* x and y are pointers to elements; each element is a char* */
    return strcmp(*(const char **)x, *(const char **)y);

int strcasecmp_manual(const char *a, const char *b) {
    while (*a && tolower((unsigned char)*a) == tolower((unsigned char)*b)) {
        a++; b++;
    }
    return tolower((unsigned char)*a) - tolower((unsigned char)*b);

Pattern 05 String Search and Scan (strchr, strstr)
① Background

strchr(s, c) scans s for the first occurrence of character c and returns a pointer to it, or NULL if not found. The character is passed as an int (the function predates char in C's type system) and compared against each byte. Using the returned pointer, you can find the position: strchr(s, c) - s gives the index.

strrchr(s, c) is the right-to-left version — it finds the last occurrence. Together, strchr and strrchr cover "find first" and "find last" for single characters, which covers most practical needs: locating a delimiter, finding a path separator, checking if a character is present.

strstr(haystack, needle) finds the first occurrence of the substring needle inside haystack. It returns a pointer to the start of the match, or NULL if needle is not found. Under the hood, most libc implementations use a variant of Boyer-Moore or similar; the worst case is still O(n*m) but average case is much better.

Manual scanning with a loop (checking each character against a set) is sometimes clearer than chaining multiple strchr calls. Pattern 06 Frequency Array int[26]
① Background

When a problem asks about letter frequencies in a string — how many 'a's, how many 'b's — the simplest and fastest data structure is a fixed-size integer array of length 26, one slot per lowercase letter. The mapping is freq[c - 'a']: subtract the ASCII value of 'a' (97) from the character to get an index between 0 and 25.

This is essentially a hash map with a perfect hash function for the English alphabet. There are no collisions, no dynamic allocation, no overhead — just a direct array index. Building the frequency table is O(n) and takes exactly 26*4 = 104 bytes regardless of string length.

For case-insensitive problems, convert to lowercase first with tolower(c) before indexing. For the full ASCII range (256 characters) or Unicode code points, increase the array size accordingly — int[256] covers all single-byte characters.

The frequency array shines in comparison problems: to check if two strings are anagrams, build freq tables for both and compare them (or build one, decrement for the second, check all zeros). This is O(n + m) time and O(1) space (the 26-slot array is constant size).

#include <string.h>
#include <ctype.h>

/* Build frequency array for lowercase letters in s */
void build_freq(const char *s, int freq[26]) {
    memset(freq, 0, 26 * sizeof(int));  /* zero all 26 slots */
    while (*s) {
        if (*s >= 'a' && *s <= 'z')    /* only count lowercase letters */
            freq[*s - 'a']++;
        s++;
    }
}

/* Check if s and t are anagrams (same letters, same counts) */
int is_anagram(const char *s, const char *t) {
    if (strlen(s) != strlen(t)) return 0;  /* quick length check */
    int freq[26] = {0};
    while (*s) freq[*s++ - 'a']++;        /* increment for s */
    while (*t) freq[*t++ - 'a']--;        /* decrement for t */
    for (int i = 0; i < 26; i++)
        if (freq[i] != 0) return 0;       /* any mismatch → not anagram */
    return 1;
}

/* Find first unique character (index), or -1 if none */
int first_unique(const char *s) {
    int freq[26] = {0};
    int n = strlen(s);
    for (int i = 0; i < n; i++) freq[s[i] - 'a']++;   /* count all */
    for (int i = 0; i < n; i++)
        if (freq[s[i] - 'a'] == 1) return i;            /* first with count 1 */
    return -1;
}

Pattern 07 Anagram Detection
① Background

Two strings are anagrams if they contain exactly the same characters with exactly the same frequencies. "listen" and "silent" are anagrams; "hello" and "world" are not. The problem appears as-is in many interview questions and also as a building block in more complex problems (group anagrams, permutation in string, minimum window).

There are three main approaches. The sort approach: sort both strings alphabetically and compare with strcmp — equal sorted forms means anagram. O(n log n) time, O(n) space for the sorted copies. Clean and simple but not the fastest.

The frequency array approach: build a freq[26] table for one string, decrement for the other, check all zeros. O(n) time, O(1) space (26 slots are constant). This is the standard interview-optimal solution.

The prime product approach (conceptual): assign each letter a unique prime, compute the product of all character primes — anagrams will have the same product. Works in theory but overflows for realistic string lengths, so it's not practical in C without big-integer arithmetic.

Pattern 08 First Non-Repeating Character
① Background

Find the first character in a string that appears exactly once. This is a two-pass problem: you cannot know if a character is unique until you have seen the whole string. The first pass builds a frequency count; the second pass scans left-to-right and returns the first position where the frequency is 1.

The freq[26] array makes both passes O(n). The total space is O(1) since 26 integers is a fixed constant regardless of string length. You could do this in one pass with a hash map (storing position of first occurrence), but the two-pass approach is simpler and has better cache behavior for the common case of lowercase English letters.

A subtle variant: "first unique character in a stream" where characters arrive one at a time and you must report the current first unique character after each arrival. This requires a more complex data structure (doubly linked list + hash map) to support O(1) updates. The static two-pass approach does not generalize to streaming.

#include <string.h>

/* First unique character index. Returns -1 if none. O(n) two-pass. */
int first_unique_char(const char *s) {
    int freq[26] = {0};
    int n = strlen(s);

    /* Pass 1: count every character */
    for (int i = 0; i < n; i++)
        freq[s[i] - 'a']++;

    /* Pass 2: find leftmost with count == 1 */
    for (int i = 0; i < n; i++)
        if (freq[s[i] - 'a'] == 1) return i;

    return -1;   /* no unique character */
}

/* One-pass variant using first-occurrence positions */
int first_unique_onepass(const char *s) {
    int pos[26];
    for (int i = 0; i < 26; i++) pos[i] = -1;   /* -1 = unseen */

    for (int i = 0; s[i]; i++) {
        int c = s[i] - 'a';
        if (pos[c] == -1) pos[c] = i;   /* first occurrence: record index */
        else              pos[c] = -2;  /* seen again: mark as duplicate */
    }

    int result = INT_MAX;
    for (int i = 0; i < 26; i++)
        if (pos[i] >= 0 && pos[i] < result) result = pos[i];

    return result == INT_MAX ? -1 : result;
}

Pattern 09 Character Classification (isalpha, isdigit, tolower)
① Background

C's <ctype.h> provides a family of character classification functions: isalpha(c) (letter), isdigit(c) (0-9), isalnum(c) (letter or digit), isspace(c) (whitespace), isupper(c), islower(c), ispunct(c). Each returns a non-zero (true) or zero (false) int. They are locale-aware, which matters for international text but creates subtle bugs if you forget to cast the argument.

The critical casting rule: these functions expect an int with value in the range of unsigned char or the special value EOF. Passing a plain char when char is signed on the platform (GCC default on x86) means characters with values 128–255 (accented letters, etc.) become negative ints, which is undefined behavior. Always cast: isalpha((unsigned char)c).

tolower(c) and toupper(c) convert case. They return the converted character or the original unchanged if conversion does not apply. Same unsigned char casting rule applies. These functions are commonly used in two-pointer palindrome checks, case-insensitive comparisons, and filtering.

For ASCII-only code (common in competitive programming / embedded), the arithmetic approach is slightly faster: c >= 'a' && c <= 'z' for lowercase, c | 32 to force lowercase (works for ASCII letters only). The ctype.h functions are safer and more portable.

Pattern 10 Reverse String In-Place (Two Pointer)
① Background

Reversing a string in-place is the foundational two-pointer operation on strings. Two indices start at opposite ends of the string and move toward each other, swapping characters at each step. When the pointers meet or cross, the reversal is complete. It uses O(1) extra space and O(n) time.

This exact same pattern — two pointers, start at ends, march inward — appears in palindrome checking (compare instead of swap), valid palindrome (skip non-alphanumeric), rotate array, and the "reverse words" problem (reverse the whole string, then reverse individual words). Mastering it mechanically frees you to focus on the logic of harder problems that use it as a subproblem.

In C, the function signature matters: you must pass a writable char array, not a pointer to a string literal. The function operates on indices (or pointer offsets) into the same buffer. No allocation is needed. The swap uses a temporary char variable — do not attempt to use the XOR swap trick on strings; it breaks when both pointers point to the same element (odd-length strings).

        char tmp = s[lo];    /* standard three-variable swap */
        s[lo] = s[hi];
        s[hi] = tmp;
        lo++;
        hi--;
    }
}

Pattern 11 Palindrome Check (Two Pointer)
① Background

A palindrome reads the same forwards and backwards: "racecar", "level", "noon". The two-pointer check is the most efficient method: place one pointer at the start and one at the end, compare the characters they point to, and march them inward. If any pair mismatches, return false. If the pointers meet or cross without a mismatch, return true.

This is O(n) time and O(1) space — no reversal, no extra array, no recursive call stack. The loop stops as soon as it finds a mismatch, so it is also efficient in the average case when strings are not palindromes: the mismatch is often found early.

The harder variant (LeetCode 125) ignores non-alphanumeric characters and treats uppercase and lowercase as equal. The two-pointer structure is identical but the advance step skips non-alphanumeric characters before each comparison. The comparison uses tolower to normalize case.

Pattern 12 Valid Palindrome II (One Deletion Allowed)
① Background

Given a string, can you make it a palindrome by removing at most one character? "abca" → remove 'c' → "aba" (palindrome). This is a two-pointer problem with a single branch point: when the two-pointer scan hits a mismatch, you have two choices — delete the left character or delete the right character. Try both and check if either of the remaining substrings is a palindrome.

The key insight is that you only get to exercise the "delete" option once, and only when you hit the first mismatch. After that first deletion, the remainder must be a perfect palindrome with no further deletions. This means you need a helper function that checks if a range [lo, hi] is a palindrome with no deletions allowed.

This pattern generalizes: "at most k deletions" becomes a DP problem. But for k=1, the two-pointer + branch approach is O(n) time, O(1) space — far better than the DP approach for this special case.

        if (s[lo] != s[hi]) return 0;

/* Valid Palindrome II: at most one deletion. O(n) time, O(1) space. */
int valid_palindrome_ii(const char *s) {
    int lo = 0, hi = strlen(s) - 1;
    while (lo < hi) {
        if (s[lo] == s[hi]) {
            lo++; hi--;              /* match: advance both */
        } else {
            /* First mismatch: try deleting either side */
            return is_pal_range(s, lo + 1, hi) ||  /* skip s[lo] */

        }
    }
    return 1;   /* no mismatch found: already a palindrome */

Pattern 13 Filter Characters In-Place (Write Pointer)
① Background

Removing characters from a string in-place without extra space uses the write pointer (also called slow/fast pointer or read/write pointer) pattern. One pointer — the write pointer — tracks where the next "kept" character should go. Another pointer — the read pointer — scans through every character. When a character passes the filter (should be kept), copy it to the write position and advance both pointers. When it fails the filter (should be removed), only advance the read pointer.

At the end, the write pointer holds the new length. Write a null terminator at that position to terminate the modified string. The original characters after the null terminator are still in memory but irrelevant — they will be overwritten or ignored. This technique is O(n) time and O(1) space.

The same write-pointer pattern is used for removing duplicates from a sorted array (arrays.html P05), compressing run-length encoded data, and applying character-level transformations in streaming contexts. It is one of the most broadly applicable single-pass string operations.

Pattern 14 Longest Substring Without Repeating Characters
① Background

Find the length of the longest substring of s that contains no repeated characters. "abcabcbb" → answer is 3 ("abc"). This is the canonical variable-size sliding window problem. A window [left, right] expands right one character at a time. When a repeated character enters the window, shrink the window from the left until the repeated character is gone.

The window invariant is: at all times, every character in s[left..right] is unique. The right pointer advances unconditionally each step. The left pointer advances only when a repeat is detected. The answer is the maximum window size seen at any point.

Tracking character positions (not just counts) lets the left pointer jump directly past the previous occurrence of the repeated character, avoiding a redundant inner loop. The data structure is an int array of size 128 (ASCII) or 256, mapping character → last seen index. When a character at index right was last seen at some index ≥ left, the window must shrink to last_seen+1.

/* Longest substring without repeating characters. O(n) time, O(1) space. */
int length_of_longest_substring(const char *s) {
    int last[128];
    for (int i = 0; i < 128; i++) last[i] = -1;  /* -1 means not yet seen */

    int left = 0, max_len = 0;

    for (int right = 0; s[right]; right++) {
        int c = (unsigned char)s[right];

        /* If c was seen at or after 'left', it would repeat in the window */
        if (last[c] >= left)
            left = last[c] + 1;   /* jump left past the previous occurrence */

        last[c] = right;          /* always update: c is now at position 'right' */

        int len = right - left + 1;
        if (len > max_len) max_len = len;
    }
    return max_len;
}

Pattern 15 Minimum Window Substring
① Background

Given strings s and t, find the shortest window in s that contains all characters of t (including duplicates). "ADOBECODEBANC", t="ABC" → answer is "BANC". This is a variable-size sliding window with two conditions: expand right until the window covers all required characters, then shrink from the left as far as possible while keeping all characters covered.

The coverage condition is tracked with two frequency maps: need[c] (how many of each character t requires) and have[c] (how many the current window has). A counter formed tracks how many distinct characters are "satisfied" (have[c] ≥ need[c]). When formed equals the number of distinct characters in t, the window is valid.

The algorithm alternates between two phases: expand right (looking for validity) and shrink left (looking for the minimum valid window). When the window becomes invalid after shrinking, switch back to expanding. The answer is the smallest window that was valid at any point during shrinking.

/* Minimum Window Substring. O(|s| + |t|) time, O(1) space (fixed 128-char arrays). */
/* Returns start index into s and sets *len. Returns -1 if no window exists. */
int min_window(const char *s, const char *t, int *out_len) {
    int need[128] = {0}, have[128] = {0};
    int required = 0;   /* distinct chars in t */

    /* Build need[] and count distinct required chars */
    for (int i = 0; t[i]; i++) {
        if (need[(unsigned char)t[i]]++ == 0) required++;
    }

    int formed = 0;     /* how many chars in t are currently satisfied */
    int left = 0;
    int best_start = -1, best_len = INT_MAX;

    for (int right = 0; s[right]; right++) {
        int c = (unsigned char)s[right];
        have[c]++;
        if (need[c] > 0 && have[c] == need[c]) formed++;  /* newly satisfied */

        /* Shrink from left while window is valid */
        while (formed == required) {
            int window_len = right - left + 1;
            if (window_len < best_len) {
                best_len = window_len;
                best_start = left;
            }
            int lc = (unsigned char)s[left];
            have[lc]--;
            if (need[lc] > 0 && have[lc] < need[lc]) formed--;  /* no longer satisfied */
            left++;
        }
    }

    *out_len = (best_start == -1) ? 0 : best_len;
    return best_start;
}

Pattern 16 Longest Substring with At Most K Distinct Characters
① Background

Pattern 17 Count Substrings with Condition
① Background

Count the number of substrings satisfying some condition — for example, "count substrings with all unique characters" or "count substrings with at most K vowels." These counting problems share a common structure: instead of tracking the maximum window size, you count how many valid windows exist at each step.

The key insight is that when a window [left, right] is valid, ALL subarrays ending at right with left index in [left, right] are also valid. That means the count of valid substrings ending at right is right - left + 1. Add this to the total on every step. When the window becomes invalid, shrink left until it is valid again, then recount.

This "at most K" counting trick is especially powerful: count(at most K) - count(at most K-1) = count(exactly K). So for "exactly K vowels," compute the difference of two at-most calls. This transforms "exactly K" counting problems (which are harder to do directly) into two simple at-most computations.

Pattern 18 Longest Palindromic Substring (Expand Around Center)
① Background

Find the longest substring of s that is a palindrome. "babad" → "bab" or "aba" (length 3). The O(n²) expand-around-center approach works as follows: for each index i, treat it as the center of a palindrome and expand outward as long as the characters on both sides match. Try both odd-length centers (single character) and even-length centers (between two characters).

This is far simpler to implement than Manacher's algorithm (O(n)) and is the expected interview answer for most roles. For each of the 2n-1 centers, expansion takes O(n) worst case, giving O(n²) total. For strings up to length 1000, this is completely acceptable.

The key to the implementation is a reusable helper that takes (left, right) as the initial expansion boundaries and returns the longest palindrome found from that center. Then the main function calls this helper twice per index — once with (i, i) for odd-length and once with (i, i+1) for even-length — and tracks the best result.

/* Expand around center at (lo, hi) and return length of longest palindrome found. */
static int expand(const char *s, int lo, int hi, int n) {
    while (lo >= 0 && hi < n && s[lo] == s[hi]) {
        lo--;   /* expand left */
        hi++;   /* expand right */
    }
    /* After loop: lo and hi are one step outside the palindrome */
    return hi - lo - 1;   /* length of palindrome found */
}

/* Longest palindromic substring. Sets *start and returns length. O(n²). */
int longest_palindrome(const char *s, int *start) {
    int n = strlen(s);
    if (n == 0) { *start = 0; return 0; }

    int best_start = 0, best_len = 1;

    for (int i = 0; i < n; i++) {
        /* Odd-length: center at i */
        int len = expand(s, i, i, n);
        if (len > best_len) {
            best_len = len;
            best_start = i - (len - 1) / 2;
        }

        /* Even-length: center between i and i+1 */
        if (i + 1 < n) {
            len = expand(s, i, i + 1, n);
            if (len > best_len) {
                best_len = len;
                best_start = i - len / 2 + 1;
            }
        }
    }
    *start = best_start;
    return best_len;
}

Pattern 19 Count Palindromic Substrings
① Background

Count how many substrings of s are palindromes. "abc" has 3 (each single character). "aaa" has 6: "a","a","a","aa","aa","aaa". The expand-around-center approach from Pattern 18 applies directly — for each center, instead of tracking the maximum length, add 1 to the count for every successful expansion step.

Each expansion step reveals one palindrome: the outermost palindrome that the current lo/hi points to. So the count from center (lo, hi) is the number of times the while loop body executes. A single-character center contributes at least 1 (the character itself). An even center contributes 0 before any expansion (the empty string between characters is not a palindrome).

The approach is O(n²) time and O(1) space. For the harder variant "longest palindromic subsequence" (not substring), dynamic programming is needed instead.

Pattern 20 Palindrome Partitioning Check
① Background

Can a string be split into substrings where every part is a palindrome? "aab" → "a" | "a" | "b" — yes (every single character is a palindrome, so any string can trivially be partitioned). The harder question is: what is the minimum number of cuts needed? "aab" can be split as "aa"|"b" (1 cut) — and "aa" is a palindrome, so 1 cut suffices.

The minimum-cut palindrome partition is a classic DP problem: cut[i] = minimum cuts for s[0..i]. For each i, if s[0..i] is itself a palindrome, cut[i]=0. Otherwise, try every split point j: if s[j+1..i] is a palindrome, cut[i] = min(cut[i], cut[j]+1). The inner palindrome check uses the precomputed is_pal[i][j] table built with O(n²) expansion, and the DP itself is O(n²), giving O(n²) total.

The simpler version — "is a given partition valid?" — just checks each part individually with the two-pointer palindrome test. This is useful as a validator in backtracking solutions for LeetCode 131 (generate all palindrome partitions).

#include <string.h>
#include <limits.h>

/* Minimum cuts to partition s into palindromes. O(n²) time and space. */
int min_cut_palindrome(const char *s) {
    int n = strlen(s);
    /* is_pal[i][j] = 1 if s[i..j] is a palindrome */
    int is_pal[n][n];
    memset(is_pal, 0, sizeof(is_pal));

    /* Fill is_pal using expand-around-center */
    for (int c = 0; c < n; c++) {
        /* Odd-length palindromes centered at c */
        for (int lo = c, hi = c; lo >= 0 && hi < n && s[lo] == s[hi]; lo--, hi++)
            is_pal[lo][hi] = 1;
        /* Even-length palindromes centered between c and c+1 */
        for (int lo = c, hi = c + 1; lo >= 0 && hi < n && s[lo] == s[hi]; lo--, hi++)
            is_pal[lo][hi] = 1;
    }

    /* DP: cut[i] = minimum cuts for s[0..i] */
    int cut[n];
    for (int i = 0; i < n; i++) {
        if (is_pal[0][i]) { cut[i] = 0; continue; }  /* whole prefix is a palindrome */
        cut[i] = INT_MAX;
        for (int j = 1; j <= i; j++) {
            if (is_pal[j][i] && cut[j - 1] != INT_MAX)
                if (cut[j - 1] + 1 < cut[i]) cut[i] = cut[j - 1] + 1;
        }
    }
    return cut[n - 1];
}

Pattern 21 Reverse Words in a String
① Background

"the sky is blue" → "blue is sky the". The words reverse order, but each word stays intact. The in-place O(1) space trick uses two reversal passes: first reverse the entire string, then reverse each individual word. After the full reverse, the words appear in the right order but each is spelled backwards; the second pass fixes each word.

This "reverse the whole, then reverse each part" pattern appears in rotate-array problems too (arrays.html P25). The key insight is that reversing is its own inverse: applying it twice restores the original. Reversing the whole string brings words to their final positions, and reversing each word un-scrambles the characters within it.

Edge cases: leading/trailing spaces and multiple consecutive spaces. If the problem requires collapsing them (as in LeetCode 151), you need a two-pass clean-up: compact the spaces first, then apply the double-reverse. Alternatively, build the output word-by-word with a write pointer in a single pass.

/* Reverse a sub-range [lo, hi] in-place. */
static void rev(char *s, int lo, int hi) {
    while (lo < hi) { char t = s[lo]; s[lo++] = s[hi]; s[hi--] = t; }
}

/* Reverse words in a char array in-place. Assumes single spaces, no leading/trailing. */
void reverse_words(char *s) {
    int n = strlen(s);
    rev(s, 0, n - 1);      /* Step 1: reverse whole string */

    int start = 0;
    for (int i = 0; i <= n; i++) {
        if (i == n || s[i] == ' ') {   /* end of a word */
            rev(s, start, i - 1);       /* Step 2: reverse this word */
            start = i + 1;
        }
    }
}

/* LeetCode 151 variant: collapse multiple spaces, trim leading/trailing. */
int reverse_words_clean(char *s, char *out, int out_size) {
    int n = strlen(s), w = 0;
    /* Collect words right-to-left into out[] */
    int i = n - 1;
    while (i >= 0) {
        while (i >= 0 && s[i] == ' ') i--;   /* skip trailing space */
        if (i < 0) break;
        int end = i;
        while (i >= 0 && s[i] != ' ') i--;   /* find word start */
        int start = i + 1;
        if (w > 0 && w < out_size - 1) out[w++] = ' ';
        int wlen = end - start + 1;
        if (w + wlen >= out_size) wlen = out_size - w - 1;
        memcpy(out + w, s + start, wlen);
        w += wlen;
    }
    out[w] = '\0';
    return w;
}

Pattern 22 Custom atoi (String to Integer)
① Background

Converting a string like " -42" or "+1000" to an integer by hand exercises every corner of C string handling: skipping whitespace, reading the sign, accumulating digits, and handling overflow. The standard atoi has undefined behavior on overflow; strtol detects it via LONG_MAX/LONG_MIN. In interviews and embedded parsing, you often need to roll your own with explicit overflow guards.

The algorithm is: (1) skip leading whitespace, (2) read optional sign, (3) accumulate digits one at a time with result = result * 10 + digit, (4) stop at the first non-digit. Overflow is the subtle part: before multiplying, check whether result > (INT_MAX - digit) / 10. If so, clamp to INT_MAX or INT_MIN depending on the sign.

Implementing this correctly is a standard interview check for attention to detail. The LeetCode version (8) specifies exact behavior: clamp to INT_MAX/INT_MIN on overflow, stop at first invalid character after digits, return 0 if no digits found at all.

③ Building the Logic from Scratch

Step-by-step state machine:

Input: "  -42abc"

State 1 — skip whitespace:
  s[0]=' ', s[1]=' ' → advance. s[2]='-'

State 2 — read sign:
  s[2]='-' → sign=-1, advance. s[3]='4'

State 3 — accumulate digits (stop at first non-digit):
  s[3]='4': result = 0*10+4 = 4
  s[4]='2': result = 4*10+2 = 42
  s[5]='a': not digit → STOP

Apply sign: result = -1 * 42 = -42

  if result > (INT_MAX - digit) / 10  → clamp
  INT_MAX = 2147483647
  For "2147483648":
    after "214748364": result=214748364
    next digit=8: 214748364 > (2147483647-8)/10 = 214748363 → CLAMP to INT_MAX

④ Full Code Walkthrough
#include <limits.h>
#include <ctype.h>

int my_atoi(const char *s) {
    /* Step 1: skip leading whitespace */
    while (isspace((unsigned char)*s)) s++;

    /* Step 2: read optional sign */
    int sign = 1;
    if (*s == '-') { sign = -1; s++; }
    else if (*s == '+') { s++; }

    /* Step 3: accumulate digits with overflow guard */
    int result = 0;
    while (isdigit((unsigned char)*s)) {
        int digit = *s - '0';
        /* Check overflow before computing result*10 + digit */
        if (result > (INT_MAX - digit) / 10) {
            return sign == 1 ? INT_MAX : INT_MIN;  /* clamp */
        }
        result = result * 10 + digit;
        s++;
    }
    return sign * result;

Pattern 23 Integer to String (itoa)
① Background

Converting an integer to its decimal string representation without using sprintf. The algorithm: repeatedly take the number modulo 10 to get the last digit, divide by 10 to drop it, and write the digit character to a buffer. This builds the digits in reverse order (least significant first), so the buffer must be reversed before use.

Special cases to handle: zero (the loop never executes), negative numbers (record sign, negate before the loop, prepend '-' after reversal), and INT_MIN (-2147483648) which cannot be negated in a 32-bit int without overflow (negate to long long first or handle separately).

sprintf(buf, "%d", n) does this correctly and handles all edge cases — prefer it when available. Roll your own only when sprintf is unavailable (bare-metal embedded systems without libc) or when you need a specific base (hex, binary, base-N).

int my_itoa(int n, char *buf, int size) {

    int neg = (n < 0);
    long long v = neg ? -(long long)n : (long long)n;  /* handles INT_MIN */

    int i = 0;
    if (v == 0) {
        buf[i++] = '0';   /* special case: zero */
    } else {
        while (v > 0 && i < size - 1) {
            buf[i++] = '0' + (int)(v % 10);  /* least significant digit first */
            v /= 10;
        }

    buf[i] = '\0';

    int lo = 0, hi = i - 1;
    while (lo < hi) { char t = buf[lo]; buf[lo++] = buf[hi]; buf[hi--] = t; }

    return i;   /* length of the string (not counting '\0') */
}

Pattern 24 Run-Length Encoding
① Background

Run-length encoding (RLE) compresses consecutive repeated characters into (count, character) pairs. "aaabbbcc" → "a3b3c2" or "3a3b2c" depending on convention. It is effective when strings have long runs of repeated characters (e.g., black-and-white bitmaps, simple sensor data) and counterproductive on random data (each single character expands to two bytes).

The encoding pass scans with two pointers: a scan pointer advances through a run of identical characters, and the count is the distance traveled. When the character changes, write the (character, count) pair to output and reset. The decoding pass reads character-count pairs and expands them.

LeetCode 443 (String Compression) is the in-place version: use the write-pointer pattern to compress into the same array. The critical invariant is that the write pointer never overtakes the read pointer (you are always compressing, never expanding), so in-place is safe — except for count digits greater than 9, which take multiple characters and can break the invariant for runs of length 10+.

int rle_encode(const char *s, char *out, int out_size) {
    int w = 0;
    for (int i = 0; s[i]; ) {
        char c = s[i];
        int  count = 0;
        while (s[i] == c) { i++; count++; }   /* count the run */

        if (w < out_size - 1) out[w++] = c;   /* write character */

        /* Write count as digits */

            out[w++] = num[j];
    }
    if (w < out_size) out[w] = '\0';
    return w;
}

Pattern 25 Decode String (Stack)
① Background

"3[ab]2[c]" decodes to "ababab cc". The rule: a number k followed by a bracketed string means repeat that string k times. Brackets can nest: "2[3[a]b]" → "aaab aaab". The stack-based approach handles nesting naturally — push the current state when an opening bracket is encountered, and restore it when the closing bracket is encountered.

Two stacks are needed: one for repeat counts and one for the string built so far before the current bracket. When '[' is seen, push the current count and the current string onto their respective stacks, then reset both for the inner level. When ']' is seen, pop the count and previous string, repeat the current string count times, and append it to the previous string.

This is a classic stack simulation problem. The stack eliminates explicit recursion — each push/pop corresponds to entering/exiting a nesting level. The approach is O(n) where n is the length of the decoded output, since every character of the output is written exactly once.

char *decode_string(const char *s) {
    char  str_stack[MAX_DEPTH][MAX_LEN];  /* saved partial strings */
    int   cnt_stack[MAX_DEPTH];           /* saved repeat counts   */
    int   top = 0;

    char  cur[MAX_LEN]; cur[0] = '\0';    /* current working string */
    int   cur_len = 0;
    int   k = 0;                          /* current number accumulator */

    for (int i = 0; s[i]; i++) {
        char c = s[i];
        if (c >= '0' && c <= '9') {
            k = k * 10 + (c - '0');       /* build multi-digit number */
        } else if (c == '[') {
            cnt_stack[top] = k;            /* save repeat count */
            strcpy(str_stack[top], cur);   /* save current string */
            top++;
            cur[0] = '\0'; cur_len = 0;   /* reset for inner block */
            k = 0;
        } else if (c == ']') {
            top--;
            int repeat = cnt_stack[top];
            char prev[MAX_LEN];
            strcpy(prev, str_stack[top]);
            int prev_len = strlen(prev);
            /* append cur repeated 'repeat' times onto prev */
            for (int r = 0; r < repeat; r++) {
                strcpy(prev + prev_len + r * cur_len, cur);
            }
            prev_len += repeat * cur_len;
            prev[prev_len] = '\0';
            strcpy(cur, prev);
            cur_len = prev_len;
        } else {
            cur[cur_len++] = c;            /* plain character: append */
            cur[cur_len]   = '\0';
        }
    }

    char *result = malloc(cur_len + 1);
    strcpy(result, cur);
    return result;
}

Pattern 26 Roman Numerals to Integer
① Background

Roman numerals use seven symbols: I(1), V(5), X(10), L(50), C(100), D(500), M(1000). Normally symbols are additive left to right. But when a smaller symbol precedes a larger one, it is subtractive: IV=4, IX=9, XL=40, XC=90, CD=400, CM=900. The rule is simple: if the current symbol's value is less than the next symbol's value, subtract it; otherwise add it.

This single rule handles all Roman numeral conversion in one left-to-right pass. You never need to look back — just peek one position ahead. The right-to-left variant is equally clean: accumulate right to left, and if the current value is less than the running max, subtract it.

The inverse problem — integer to Roman — uses a greedy approach: from the largest symbol down, subtract as many times as possible and append the symbol each time. A lookup table of (value, symbol) pairs in descending order makes this mechanical.

int roman_to_int(const char *s) {

Pattern 27 Naive String Search O(nm)
① Background

Find the first (or all) occurrence(s) of a pattern string p inside a text string t. The naive approach: for each starting position i in t, check if t[i..i+m-1] matches p character by character. If every character matches, record a hit. If any character mismatches, move to position i+1 and try again.

The worst case is O(n*m) — for example, searching for "aaab" in "aaaaaaa…" — but for typical English text with short patterns, the average case is much better because mismatches are found after just 1–2 character comparisons. For most practical purposes (log search, command parsing, small pattern matching), the naive approach is fast enough and much simpler to implement and debug than KMP or Boyer-Moore.

The C standard library's strstr implements this (or a better algorithm internally). Use strstr when available. Roll your own naive search when you need to match against a pattern that is not a C string (e.g., a byte sequence with embedded nulls) or when you need to return all match positions rather than just the first.

#include <string.h>

/* Naive search: return index of first match, or -1. O(n*m). */
int naive_search(const char *text, const char *pat) {
    int n = strlen(text), m = strlen(pat);
    if (m == 0) return 0;        /* empty pattern matches at 0 */
    if (m > n) return -1;        /* pattern longer than text: no match */

    for (int i = 0; i <= n - m; i++) {
        int j;
        for (j = 0; j < m; j++) {
            if (text[i + j] != pat[j]) break;   /* mismatch: try next position */
        }
        if (j == m) return i;    /* all m chars matched */
    }
    return -1;
}

/* Find all matches — returns count and fills positions[]. */
int naive_search_all(const char *text, const char *pat, int *positions, int max_pos) {
    int n = strlen(text), m = strlen(pat), count = 0;
    if (m == 0 || m > n) return 0;

    for (int i = 0; i <= n - m && count < max_pos; i++) {
        if (memcmp(text + i, pat, m) == 0) {  /* memcmp: fast block compare */
            positions[count++] = i;
        }
    }
    return count;
}
