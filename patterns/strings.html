Pattern 01 Null Terminator and String Length
① Background

In C, a string is not a first-class type — it is a convention: a contiguous sequence of char values ending with a zero byte ('\0', ASCII value 0). Every standard library function that takes a string relies on finding this sentinel to know where the string ends. There is no hidden length field, no bounds checking, and no exception if the null terminator is missing — the function just keeps reading memory until it finds a zero byte or crashes.

strlen(s) counts bytes from s[0] until it hits '\0', then returns that count — not including the null byte itself. This is O(n). Calling strlen in a loop header (for (int i = 0; i < strlen(s); i++)) recomputes the length on every iteration — an O(n²) bug hiding in plain sight.

sizeof(arr) on a char array gives the total allocated bytes including the null terminator. On a char * pointer it gives the pointer size (4 or 8), not the string length. These two are frequently confused: char buf[10] = "hello" has sizeof(buf) = 10 but strlen(buf) = 5.

When you declare char buf[n] and want to store a string of length L, you need n ≥ L + 1 — one extra byte for '\0'. Forgetting the +1 is the root cause of countless off-by-one buffer overflows. After manual construction of a string in a buffer, always write buf[len] = '\0' explicitly.

② Where You See This
  • Any strlen call in a loop conditionrecomputes length O(n) per iteration; cache it before the loop
  • Embedded firmware string buffersfixed-size char arrays on the stack; must reserve the null byte or corrupt adjacent memory
  • Network packet parsingreading a C-string from a socket; must null-terminate the receive buffer before calling strlen
  • LeetCode 344 / 541 — Reverse Stringmodify char array in-place; null terminator marks the end so you know where to stop
  • Manual string buildersappending characters one by one into a buf[] — track index and always write '\0' at the end
  • UART / serial driver outputtransmit-until-null loops; a missing '\0' causes the driver to send garbage bytes indefinitely
③ Building the Logic from Scratch

How strlen works internally: it is just a pointer walk. Start at the beginning, advance until the byte is zero, return the distance traveled.

s = "hello"

Memory layout (6 bytes):
 index:  0    1    2    3    4    5
 char:  'h'  'e'  'l'  'l'  'o'  '\0'
 value:  104  101  108  108  111   0

strlen starts at index 0, walks right until value == 0.
Stops at index 5 (the '\0'), returns 5.
sizeof("hello") = 6  (the string literal includes the null byte)

The loop-condition bug:

WRONG — strlen called on every iteration:
for (int i = 0; i < strlen(s); i++)   /* O(n) per check → O(n²) total */

CORRECT — cache the length once:
int n = strlen(s);
for (int i = 0; i < n; i++)           /* O(1) per check → O(n) total */

Aha moment: strlen has no magic — it is a linear scan every time you call it. If the string does not change inside the loop, calling strlen once before the loop and storing the result is free speed.

sizeof vs strlen:

char arr[] = "hello";    /* compiler sets aside 6 bytes */
sizeof(arr)  == 6        /* total allocated bytes, compile-time constant */
strlen(arr)  == 5        /* bytes before '\0', runtime scan */

char *ptr = "hello";
sizeof(ptr)  == 8        /* pointer size on 64-bit — NOT the string length */
strlen(ptr)  == 5        /* still works: follows the pointer and scans */

int my_strlen(const char *s) {
    int n = 0;
    while (s[n] != '\0') n++;   /* stop when null byte found */
    return n;
}

/* Safe string builder: append chars one at a time into buf[size] */
int build_string(char *buf, int size, const char *src) {
    int i = 0;
    /* leave room for '\0': stop at size-1 */
    while (i < size - 1 && src[i] != '\0') {
        buf[i] = src[i];
        i++;
    }
    buf[i] = '\0';   /* always null-terminate, even if truncated */
    return i;        /* number of chars written (not counting '\0') */
}

Pattern 02 char* vs char[] — Pointer vs Array
① Background

char *p = "hello"; and char a[] = "hello"; look nearly identical but behave very differently. The pointer form makes p point to a string literal — a read-only block of memory placed in the program's data segment by the compiler. Attempting to write through p (like p[0] = 'H';) is undefined behavior on all modern systems, and on most it causes a segmentation fault.

The array form copies the literal's bytes into a writable char array on the stack (or in static storage, depending on where it is declared). a[0] = 'H'; is perfectly legal — you own those bytes. The key difference: char[] gives you a private, mutable copy; char * gives you a read-only view.

Function parameters that look like char arr[] are actually char * — the array decays to a pointer at the call site. Inside the function, sizeof(arr) gives the pointer size, not the original array size. This array-to-pointer decay is one of C's most pervasive implicit conversions.

When you want to modify a string passed into a function, the caller must pass a writable buffer (a char[] or heap-allocated memory), not a pointer to a string literal. Documenting whether a function modifies its argument is essential — const char * signals read-only, plain char * signals potentially writable.

② Where You See This
  • Function signature designconst char* for read-only input; char* or char[] for output/modification buffers
  • String literal segfault bugsassigning to char* then trying to modify — crashes on Linux/macOS, silent corruption on some embedded targets
  • Returning strings from functionsreturning a pointer to a local char[] is a dangling pointer; must return heap-allocated or static storage
  • LeetCode string problems in Cchar** parameters for arrays of strings; each element may be a literal (don't modify) or heap (safe to modify)
  • argv in main()argv[i] is char* pointing to OS-managed memory; modifying it is implementation-defined
  • ROM / flash strings in microcontrollersstring literals stored in flash (const); writing through char* pointer faults or silently fails
③ Building the Logic from Scratch

Memory layout comparison:

char *p = "hello";

  .rodata (read-only):          stack (p lives here):
  [ h | e | l | l | o | \0 ]   [ ptr ─────────────────┐ ]
                                                        ↓
                                          points into read-only memory
  Modifying p[0] = 'H' → SEGFAULT (writing to read-only page)

  [ h | e | l | l | o | \0 ]   ← writable copy on the stack
  a[0] = 'H' → OK, modifies the stack copy

Array decay at function call:

    sizeof(arr) == 8;        /* pointer size, NOT original array size */
}

char buf[20] = "hello";
f(buf);                      /* buf decays to &buf[0], a char* */

Aha moment: there is no "array type" in a function parameter list. char arr[] and char *arr are identical function parameter declarations. If you need the size, pass it as a separate argument.

④ Full Code Walkthrough
/* Demonstrates char* vs char[] safety */

void to_upper_safe(char *s) {    /* requires a writable buffer */
    while (*s) {
        if (*s >= 'a' && *s <= 'z') *s -= 32;   /* modify in-place */
        s++;
    }
}

int main(void) {
    char arr[] = "hello";   /* writable copy on stack */
    to_upper_safe(arr);     /* OK — arr is mutable */

    char *lit = "hello";    /* pointer to read-only literal */
    /* to_upper_safe(lit); ← would SEGFAULT — do not modify a literal */

    /* Safe pattern: if you receive char*, make a writable copy first */
    char buf[64];
    strncpy(buf, lit, sizeof(buf) - 1);
    buf[sizeof(buf) - 1] = '\0';   /* guarantee null terminator */
    to_upper_safe(buf);            /* safe — buf is a writable stack array */
    return 0;
}

Rule: If you need to modify the string, use char[]. If read-only is acceptable, const char * documents that intent and lets the compiler protect you.

Pattern 03 Safe String Copy
① Background

strcpy(dst, src) copies bytes from src into dst until it copies the null terminator. It does zero bounds checking. If src is longer than dst can hold, strcpy writes past the end of dst — a classic buffer overflow. In security contexts, this is a code execution vulnerability; in embedded systems, it silently corrupts adjacent variables on the stack.

strncpy(dst, src, n) was designed to fix this, but it introduces its own hazard: if src has n or more bytes before its null terminator, strncpy copies exactly n bytes and does NOT append a null terminator to dst. Calling strlen or printf on dst then reads garbage. The idiom is to always follow strncpy with dst[n-1] = '\0'; to guarantee termination.

The modern idiomatic safe copy in C is to use snprintf(dst, size, "%s", src) — it always null-terminates and returns the number of characters that would have been written, so you can detect truncation. Some codebases use strlcpy (BSD/macOS) which also always null-terminates, but it is not in the C standard library.

When you own both buffers and know the sizes, the cleanest pattern is: compute the copy length as min(src_len, dst_size - 1), use memcpy for that many bytes, then write the null terminator manually. This avoids strncpy's quirks entirely.

② Where You See This
  • Any code calling strcpy with user inputclassic buffer overflow; CWE-120; must use bounded copy
  • Embedded config string parsingreading a string field from EEPROM into a fixed char[32] buffer
  • LeetCode string manipulation problemscopying substrings into output buffers in C solutions
  • Network protocol field extractionextracting a hostname field from a packet into a local buffer with strncpy + force-null
  • File path constructionbuilding paths with snprintf to prevent truncated paths from writing to wrong locations
  • RTOS task name assignmenttask names are fixed-length char arrays; strncpy + null-terminate is standard pattern
③ Building the Logic from Scratch

What strcpy does (and why it is dangerous):

src = "hello world"   (11 chars + '\0' = 12 bytes)
dst = char[6]         (only 6 bytes allocated)

strcpy(dst, src):
dst[0]='h' dst[1]='e' dst[2]='l' dst[3]='l' dst[4]='o' dst[5]=' '
dst[6]='w' dst[7]='o' ...  ← past the end of dst! corrupts stack

Safe copy recipe:

dst_size = 6   (buffer capacity including null byte)
src_len  = strlen(src) = 11
copy_len = min(src_len, dst_size - 1) = min(11, 5) = 5

memcpy(dst, src, 5);   copies 'h','e','l','l','o'
dst[5] = '\0';         writes null terminator

result: dst = "hello"  (safely truncated, always terminated)

Aha moment: the "safe" in safe copy has two requirements — (1) never write past dst's end, and (2) always leave dst null-terminated. strncpy satisfies only the first. Every safe alternative must satisfy both.

④ Full Code Walkthrough
#include <string.h>
#include <stdio.h>

/* Safe copy: always null-terminates, never overflows dst. */
void safe_strcpy(char *dst, const char *src, int dst_size) {
    if (dst_size <= 0) return;           /* nothing to write */
    int i = 0;
    while (i < dst_size - 1 && src[i]) { /* leave 1 slot for '\0' */
        dst[i] = src[i];
        i++;
    }
    dst[i] = '\0';                        /* always terminate */
}

/* Using snprintf — idiomatic modern C */
void snprintf_copy(char *dst, int dst_size, const char *src) {
    int written = snprintf(dst, dst_size, "%s", src);
    if (written >= dst_size) {
        /* truncation occurred: written holds what would have been written */
    }
    /* dst is always null-terminated by snprintf */
}

/* The strncpy + force-null idiom (common in C89 codebases) */
void strncpy_safe(char *dst, const char *src, int dst_size) {
    strncpy(dst, src, dst_size - 1);   /* copy at most dst_size-1 bytes */
    dst[dst_size - 1] = '\0';           /* force null terminator */
}

⑥ Gotcha
⚠ Wrong: strncpy without forcing the null terminator
/* WRONG: if src >= dst_size chars, strncpy does NOT null-terminate */

/* dst = {'h','e','l','l','o'} — no '\0'! */

What breaks: strncpy copies exactly n bytes and pads with zeros only if src is shorter than n. When src is n or more bytes, the null terminator is never written. strlen and printf then walk past the buffer boundary.

/* CORRECT: force the null terminator after strncpy */
strncpy(dst, "hello world", sizeof(dst) - 1);
dst[sizeof(dst) - 1] = '\0';   /* always safe — last byte forced to null */

Rule: After strncpy, always write dst[n-1] = '\0'. Better yet, use snprintf which handles this automatically.

Pattern 04 String Comparison (strcmp)
① Background

strcmp(a, b) compares two C strings lexicographically — character by character using ASCII values. It returns a negative number if a comes before b, zero if they are equal, or a positive number if a comes after b. The exact magnitude of the non-zero return is implementation-defined; only the sign matters.

The most common beginner mistake is comparing strings with ==: if (s1 == s2) compares the two pointer values (memory addresses), not the string contents. Two equal strings stored in different arrays have different addresses and will compare as not-equal. This bug is silent — the code compiles without warning and runs without crashing, but gives the wrong answer.

Lexicographic order follows ASCII values: uppercase letters come before lowercase ('A'=65, 'a'=97). "Apple" < "apple" and "B" < "a". For case-insensitive comparison, use strcasecmp (POSIX) or roll your own with tolower on each character before comparing.

strncmp(a, b, n) compares at most n characters and is the bounded form — useful for checking a prefix or comparing fixed-length fields without requiring a null terminator in either string.

  • qsort comparator for string arraysqsort passes void* pointers; cast to char** and call strcmp on the dereferenced values
  • Command-line argument parsingif (strcmp(argv[i], "--verbose") == 0) — checking flags by value not address
  • Config file key lookupstrcmp to match keys against known strings in an if-else chain or switch-like dispatch table
  • LeetCode 242 — Valid Anagramone approach: sort both strings and strcmp; equal → anagram
  • Binary search on sorted string arraysuse strcmp as the comparator to find if a word is in a dictionary
  • Protocol command dispatchembedded UART command parser: strncmp(buf, "AT+RST", 6) to match fixed-prefix commands
③ Building the Logic from Scratch

How strcmp works: walk both strings simultaneously, comparing ASCII values. Stop at the first difference or when both reach '\0'.

strcmp("cat", "car"):
  i=0: 'c'=='c' → continue
  i=1: 'a'=='a' → continue
  i=2: 't' vs 'r'  →  't'(116) - 'r'(114) = +2  → return positive
  → "cat" comes AFTER "car" lexicographically

strcmp("dog", "dog"):
  i=0,1,2: all equal
  i=3: both '\0' → equal → return 0

strcmp("", "a"):
  i=0: '\0' vs 'a' → '\0'(0) - 'a'(97) = -97 → return negative
  → empty string comes BEFORE "a"

qsort comparator pattern:

int cmp_str(const void *a, const void *b) {
    return strcmp(*(const char **)a, *(const char **)b);
}
/* Usage: qsort(arr, n, sizeof(char*), cmp_str); */

Why *(const char **)a ?
  qsort passes pointers to the array elements.
  Each element is itself a char* (a string pointer).
  So a is char** — dereference once to get the char*.

Aha moment: strcmp returns the difference of the first differing characters (conceptually). The sign tells you the order; zero means equal. Never check strcmp(a,b) == true — that checks for return value 1, which is NOT what "equal" means. Always check strcmp(a,b) == 0 for equality.

④ Full Code Walkthrough
#include <string.h>
#include <stdlib.h>

/* Manual strcmp implementation */
int my_strcmp(const char *a, const char *b) {
    while (*a && *a == *b) {   /* advance while both match and not at end */
        a++; b++;
    }
    return (unsigned char)*a - (unsigned char)*b;  /* cast to avoid sign issues */
}

/* qsort comparator for an array of char* */
int cmp_strings(const void *x, const void *y) {
    /* x and y are pointers to elements; each element is a char* */
    return strcmp(*(const char **)x, *(const char **)y);
}

/* Case-insensitive comparison using tolower */
int strcasecmp_manual(const char *a, const char *b) {
    while (*a && tolower((unsigned char)*a) == tolower((unsigned char)*b)) {
        a++; b++;
    }
    return tolower((unsigned char)*a) - tolower((unsigned char)*b);
}

⚠ Wrong: using == to compare strings — compares pointers not content

Pattern 05 String Search and Scan (strchr, strstr)
① Background

strchr(s, c) scans s for the first occurrence of character c and returns a pointer to it, or NULL if not found. The character is passed as an int (the function predates char in C's type system) and compared against each byte. Using the returned pointer, you can find the position: strchr(s, c) - s gives the index.

strrchr(s, c) is the right-to-left version — it finds the last occurrence. Together, strchr and strrchr cover "find first" and "find last" for single characters, which covers most practical needs: locating a delimiter, finding a path separator, checking if a character is present.

strstr(haystack, needle) finds the first occurrence of the substring needle inside haystack. It returns a pointer to the start of the match, or NULL if needle is not found. Under the hood, most libc implementations use a variant of Boyer-Moore or similar; the worst case is still O(n*m) but average case is much better.

Manual scanning with a loop (checking each character against a set) is sometimes clearer than chaining multiple strchr calls. The pattern while (*s && !is_delim(*s)) s++; is idiomatic C for advancing a pointer past non-delimiter characters. Combining scan-forward with strchr for the delimiter position is the basis for most C tokenizers.

Pattern 06 Frequency Array int[26]
① Background

When a problem asks about letter frequencies in a string — how many 'a's, how many 'b's — the simplest and fastest data structure is a fixed-size integer array of length 26, one slot per lowercase letter. The mapping is freq[c - 'a']: subtract the ASCII value of 'a' (97) from the character to get an index between 0 and 25.

This is essentially a hash map with a perfect hash function for the English alphabet. There are no collisions, no dynamic allocation, no overhead — just a direct array index. Building the frequency table is O(n) and takes exactly 26*4 = 104 bytes regardless of string length.

For case-insensitive problems, convert to lowercase first with tolower(c) before indexing. For the full ASCII range (256 characters) or Unicode code points, increase the array size accordingly — int[256] covers all single-byte characters.

The frequency array shines in comparison problems: to check if two strings are anagrams, build freq tables for both and compare them (or build one, decrement for the second, check all zeros). This is O(n + m) time and O(1) space (the 26-slot array is constant size).

④ Full Code Walkthrough
#include <string.h>
#include <ctype.h>

/* Build frequency array for lowercase letters in s */
void build_freq(const char *s, int freq[26]) {
    memset(freq, 0, 26 * sizeof(int));  /* zero all 26 slots */
    while (*s) {
        if (*s >= 'a' && *s <= 'z')    /* only count lowercase letters */
            freq[*s - 'a']++;
        s++;
    }
}

/* Check if s and t are anagrams (same letters, same counts) */
int is_anagram(const char *s, const char *t) {
    if (strlen(s) != strlen(t)) return 0;  /* quick length check */
    int freq[26] = {0};
    while (*s) freq[*s++ - 'a']++;        /* increment for s */
    while (*t) freq[*t++ - 'a']--;        /* decrement for t */
    for (int i = 0; i < 26; i++)
        if (freq[i] != 0) return 0;       /* any mismatch → not anagram */
    return 1;
}

/* Find first unique character (index), or -1 if none */
int first_unique(const char *s) {
    int freq[26] = {0};
    int n = strlen(s);
    for (int i = 0; i < n; i++) freq[s[i] - 'a']++;   /* count all */
    for (int i = 0; i < n; i++)
        if (freq[s[i] - 'a'] == 1) return i;            /* first with count 1 */
    return -1;
}

Pattern 07 Anagram Detection
① Background

Two strings are anagrams if they contain exactly the same characters with exactly the same frequencies. "listen" and "silent" are anagrams; "hello" and "world" are not. The problem appears as-is in many interview questions and also as a building block in more complex problems (group anagrams, permutation in string, minimum window).

There are three main approaches. The sort approach: sort both strings alphabetically and compare with strcmp — equal sorted forms means anagram. O(n log n) time, O(n) space for the sorted copies. Clean and simple but not the fastest.

The frequency array approach: build a freq[26] table for one string, decrement for the other, check all zeros. O(n) time, O(1) space (26 slots are constant). This is the standard interview-optimal solution.

The prime product approach (conceptual): assign each letter a unique prime, compute the product of all character primes — anagrams will have the same product. Works in theory but overflows for realistic string lengths, so it's not practical in C without big-integer arithmetic.

Pattern 08 First Non-Repeating Character
① Background

Find the first character in a string that appears exactly once. This is a two-pass problem: you cannot know if a character is unique until you have seen the whole string. The first pass builds a frequency count; the second pass scans left-to-right and returns the first position where the frequency is 1.

The freq[26] array makes both passes O(n). The total space is O(1) since 26 integers is a fixed constant regardless of string length. You could do this in one pass with a hash map (storing position of first occurrence), but the two-pass approach is simpler and has better cache behavior for the common case of lowercase English letters.

A subtle variant: "first unique character in a stream" where characters arrive one at a time and you must report the current first unique character after each arrival. This requires a more complex data structure (doubly linked list + hash map) to support O(1) updates. The static two-pass approach does not generalize to streaming.

Two-pass approach:

Pass 1 — count frequencies:
l:1, o:2, v:1, e:4, t:1, c:1, d:1

Pass 2 — scan left to right, return first with freq==1:
i=0: s[0]='l', freq[l]=1 → return 0 ✓

s = "aabb"

Pass 2: a→2, a→2, b→2, b→2 → no unique → return -1

  else:             pos[c] = -2    (seen again — mark as duplicate)

After full scan: find minimum non-(-2) value in pos[].
That minimum is the index of the first unique character.

Aha moment: the two-pass approach is correct because you NEED the full count before you can label any character as unique. The second pass left-to-right guarantees you find the FIRST unique (by position), not just any unique.

④ Full Code Walkthrough
#include <string.h>

/* First unique character index. Returns -1 if none. O(n) two-pass. */
int first_unique_char(const char *s) {
    int freq[26] = {0};
    int n = strlen(s);

    /* Pass 1: count every character */
    for (int i = 0; i < n; i++)
        freq[s[i] - 'a']++;

    /* Pass 2: find leftmost with count == 1 */
    for (int i = 0; i < n; i++)
        if (freq[s[i] - 'a'] == 1) return i;

    return -1;   /* no unique character */
}

/* One-pass variant using first-occurrence positions */
int first_unique_onepass(const char *s) {
    int pos[26];
    for (int i = 0; i < 26; i++) pos[i] = -1;   /* -1 = unseen */

    for (int i = 0; s[i]; i++) {
        int c = s[i] - 'a';
        if (pos[c] == -1) pos[c] = i;   /* first occurrence: record index */
        else              pos[c] = -2;  /* seen again: mark as duplicate */
    }

    int result = INT_MAX;
    for (int i = 0; i < 26; i++)
        if (pos[i] >= 0 && pos[i] < result) result = pos[i];

    return result == INT_MAX ? -1 : result;
}

Pattern 09 Character Classification (isalpha, isdigit, tolower)
① Background

C's <ctype.h> provides a family of character classification functions: isalpha(c) (letter), isdigit(c) (0-9), isalnum(c) (letter or digit), isspace(c) (whitespace), isupper(c), islower(c), ispunct(c). Each returns a non-zero (true) or zero (false) int. They are locale-aware, which matters for international text but creates subtle bugs if you forget to cast the argument.

The critical casting rule: these functions expect an int with value in the range of unsigned char or the special value EOF. Passing a plain char when char is signed on the platform (GCC default on x86) means characters with values 128–255 (accented letters, etc.) become negative ints, which is undefined behavior. Always cast: isalpha((unsigned char)c).

tolower(c) and toupper(c) convert case. They return the converted character or the original unchanged if conversion does not apply. Same unsigned char casting rule applies. These functions are commonly used in two-pointer palindrome checks, case-insensitive comparisons, and filtering.

For ASCII-only code (common in competitive programming / embedded), the arithmetic approach is slightly faster: c >= 'a' && c <= 'z' for lowercase, c | 32 to force lowercase (works for ASCII letters only). The ctype.h functions are safer and more portable.

The unsigned char cast — why it matters:

On platforms where char is signed (GCC x86 default):
  char c = '\xe9';   /* 'é' in Latin-1 — value 233 */
  (int)c == -23      /* sign-extended negative int */
  isalpha(-23)       /* undefined behavior! negative, not EOF */

  (int)(unsigned char)c == 233  /* correct — in [0, 255] range */
  isalpha(233)       /* defined: checks locale for letter-ness */

Safe habit: always write isalpha((unsigned char)c)

Aha moment: the ctype.h functions look like they take char but technically take int. Passing a signed char that holds a high-bit byte silently produces undefined behavior. One cast fixes it forever.

Arithmetic vs ctype.h:

ASCII-only lowercase check:
  c >= 'a' && c <= 'z'          /* clear intent, portable for ASCII */
  (c | 32) >= 'a' && ...         /* bit trick, harder to read */
  islower((unsigned char)c)        /* locale-aware, always correct */

#include <ctype.h>
#include <string.h>

/* Count digits, letters, spaces in a string */
void classify_chars(const char *s, int *digits, int *letters, int *spaces) {
    *digits = *letters = *spaces = 0;
    while (*s) {
        unsigned char c = (unsigned char)*s;   /* safe cast */
        if (isdigit(c))       (*digits)++;
        else if (isalpha(c))  (*letters)++;
        else if (isspace(c))  (*spaces)++;
        s++;
    }
}

/* Convert entire string to lowercase in-place */
void str_tolower(char *s) {
    while (*s) {
        *s = (char)tolower((unsigned char)*s);   /* cast both ways */
        s++;
    }
}

/* Check if a string contains at least one digit */
int has_digit(const char *s) {
    while (*s)
        if (isdigit((unsigned char)*s++)) return 1;
    return 0;
}

Pattern 10 Reverse String In-Place (Two Pointer)
① Background

Reversing a string in-place is the foundational two-pointer operation on strings. Two indices start at opposite ends of the string and move toward each other, swapping characters at each step. When the pointers meet or cross, the reversal is complete. It uses O(1) extra space and O(n) time.

This exact same pattern — two pointers, start at ends, march inward — appears in palindrome checking (compare instead of swap), valid palindrome (skip non-alphanumeric), rotate array, and the "reverse words" problem (reverse the whole string, then reverse individual words). Mastering it mechanically frees you to focus on the logic of harder problems that use it as a subproblem.

In C, the function signature matters: you must pass a writable char array, not a pointer to a string literal. The function operates on indices (or pointer offsets) into the same buffer. No allocation is needed. The swap uses a temporary char variable — do not attempt to use the XOR swap trick on strings; it breaks when both pointers point to the same element (odd-length strings).

③ Building the Logic from Scratch

Pointer movement and swap:

s = "hello"
     01234

left=0, right=4

Step 1: swap s[0]↔s[4] → "oellh"   left=1, right=3
Step 2: swap s[1]↔s[3] → "olleh"   left=2, right=2
Step 3: left==right → stop (odd-length center stays in place)

Result: "olleh" ✓

Even-length: "abcd"  left=0, right=3
Step 1: swap s[0]↔s[3] → "dbca"   left=1, right=2
Step 2: swap s[1]↔s[2] → "dcba"   left=2, right=1
Step 3: left>right → stop

Result: "dcba" ✓

Aha moment: the loop condition is left < right, not left != right. For odd-length strings, when they meet (left == right) the center element is already in place and should not be swapped with itself. Both conditions handle even-length correctly too.

Reverse a subrange [lo, hi]: same code with parameters instead of 0 and n-1. This subrange version is the subroutine used in "reverse words" and "rotate array".

④ Full Code Walkthrough
/* Reverse a subrange of a char array in-place. O(n). */
void reverse_range(char *s, int lo, int hi) {
    while (lo < hi) {
        char tmp = s[lo];    /* standard three-variable swap */
        s[lo] = s[hi];
        s[hi] = tmp;
        lo++;
        hi--;
    }
}

/* Reverse entire string (null-terminated) in-place. */
void reverse_string(char *s) {
    int n = strlen(s);
    reverse_range(s, 0, n - 1);
}

/* Reverse words in a sentence in-place.
   "the sky is blue" → "blue is sky the"
   Strategy: reverse entire string, then reverse each word. */
void reverse_words(char *s) {
    int n = strlen(s);
    reverse_range(s, 0, n - 1);    /* "eulb si yks eht" */

    int start = 0;
    for (int i = 0; i <= n; i++) {
        if (i == n || s[i] == ' ') {          /* end of a word */
            reverse_range(s, start, i - 1);   /* reverse the word */
            start = i + 1;
        }
    }
}

⑥ Gotcha
⚠ Wrong: using XOR swap — corrupts when lo==hi
/* WRONG: XOR swap breaks when swapping an element with itself */
void reverse_xor(char *s, int lo, int hi) {
    while (lo < hi) {
        s[lo] ^= s[hi];   /* if lo==hi, this zeroes the byte! */
        s[hi] ^= s[lo];
        s[lo] ^= s[hi];
        lo++; hi--;
    }
}
/* For "abc" reversed to "cba": lo=0,hi=2 works.
   But if called with lo==hi (e.g. range of 1 element):
   s[lo]^=s[lo] → 0; s[lo]^=0 → 0; s[lo]^=0 → 0. Element destroyed. */

What breaks: XOR swap with the same variable (same address) zeros the value. The temp-variable swap is safe in all cases and clearer to read.

/* CORRECT: temp-variable swap — safe, clear, and optimal */
char tmp = s[lo]; s[lo] = s[hi]; s[hi] = tmp;

Rule: Always use a temp variable for swaps in string reversal. XOR swap is a micro-optimization that creates subtle bugs and is never worth it.
