Pattern 01 Prefix Sum: Range Query
① Background

Imagine you are a database analyst and your table has one million rows of daily sales figures. Your manager emails you five times a day asking "what were total sales between day 40 and day 200?" Each time, you loop through 160 rows and add them up. That is 160 operations per query. With 100 queries a day, you are doing 16,000 additions — for data that never changes.

Before prefix sums existed as a recognized tool, the naive approach was exactly this: for every query (l, r), loop from index l to r and accumulate. This is O(n) per query. If you have Q queries and N elements, the total cost is O(N × Q). For large datasets and many queries, this becomes completely unacceptable.

The prefix sum pattern solves this by doing a one-time O(n) preprocessing step that builds a "running total" array. Once that array exists, every range query costs exactly one subtraction — O(1). You are converting repeated work into a one-time investment. This is the classic space-time tradeoff: one extra array of size n buys you instant answers forever.

This pattern is everywhere in production systems. Database engines use it for range aggregations on indexed columns. Game engines use it for spatial queries — "how many enemies are in this bounding box?" GPS systems use it in elevation queries — "what is the total climb between checkpoint 3 and checkpoint 7?" Image processing uses 2D prefix sums (called summed-area tables) to compute the average pixel brightness of any rectangular region of an image in O(1), regardless of region size. Battery management systems in EVs use prefix sums to compute cumulative charge drawn over arbitrary time windows.

② Where You See This
  • Repeated range sum queries on a static array. The classic use case — build once, query many times.
  • Database aggregate queries on immutable time-series data. Same idea as an indexed column sum — precompute to avoid full-table scans.
  • Image processing: summed-area table. Extends to 2D — any rectangular region sum in O(1) using the 2D prefix formula.
  • Game development: spatial partitioning queries. Counting objects in axis-aligned regions without iterating every object each frame.
  • Embedded / BMS: cumulative energy counters. Querying total ampere-hours drawn between two timestamps on a fixed sensor log.
  • Subarray sum problems (equals K, at most K, etc.). Prefix sum + hashmap converts O(n²) subarray enumeration into O(n) lookup.
  • Counting problems: "how many subarrays have even sum?" Prefix sum parity — odd-count × odd-count pairs gives the answer instantly.
③ Building the Logic from Scratch

Let us start with just four elements: arr = [3, 1, 4, 2]. You want to answer: "what is the sum of elements from index 1 to index 3?" The dumb way loops: 1 + 4 + 2 = 7. Fine for one query. But what if I ask you for sum(0,3), then sum(1,2), then sum(0,1), then sum(2,3)? You are looping over the same data repeatedly.

What if we stored partial totals as we scan left to right? Let us write down after each element, the total so far:

arr: [ 3, 1, 4, 2 ] ↓ ↓ ↓ ↓ prefix: [ 3, 4, 8, 10 ] (3) (3+1)(3+1+4)(3+1+4+2)

Now notice something: prefix[3] = 10, which is the sum of everything from index 0 to 3. prefix[1] = 4, which is the sum from index 0 to 1. The key insight: sum(2, 3) = prefix[3] − prefix[1] = 10 − 4 = 6. We subtracted everything before index 2. Let us verify: arr[2] + arr[3] = 4 + 2 = 6. Correct.

Why does this work? prefix[r] includes everything from index 0 through index r. prefix[l−1] includes everything from index 0 through index l−1. Subtracting them cancels everything before index l and leaves exactly the range [l, r]. In plain English: total up to r minus total up to just before l.

There is one edge case we need to handle. What if l = 0? Then we would compute prefix[r] − prefix[−1]. There is no prefix[−1] — that would be out of bounds. The fix is simple: when l = 0, just return prefix[r] directly. Nothing to subtract because the range starts at the beginning. Alternatively, you can use a one-indexed prefix array of size n+1 where prefix[0] = 0 is a dummy sentinel. Then prefix[r+1] − prefix[l] works for all l ≥ 0 without any special case.

④ Full Code Walkthrough
PSEUDOCODE: build_prefix(arr, n): prefix[0] = arr[0] for i = 1 to n-1: prefix[i] = prefix[i-1] + arr[i] range_sum(prefix, l, r): if l == 0: return prefix[r] else: return prefix[r] - prefix[l-1]
#include <stdio.h>

/* Build the prefix sum array.
   prefix[i] will hold the sum of arr[0] through arr[i] inclusive. */
void build_prefix(int *arr, int *prefix, int n) {
    prefix[0] = arr[0];
    /* WHY: the running total for just the first element is the element itself */

    for (int i = 1; i < n; i++)
        prefix[i] = prefix[i-1] + arr[i];
    /* WHY: each prefix entry is the PREVIOUS running total plus this new element.
       We never recompute from scratch — we extend the total by one step. */
}

/* Answer a range sum query in O(1).
   Returns the sum of arr[l], arr[l+1], ..., arr[r]. */
int range_sum(int *prefix, int l, int r) {
    if (l == 0)
        return prefix[r];
    /* WHY: when the range starts at index 0, prefix[r] IS the answer.
       There is nothing to the left of index 0 to subtract. */

    return prefix[r] - prefix[l-1];
    /* WHY: prefix[r]   = sum of arr[0..r]
            prefix[l-1] = sum of arr[0..l-1]
            subtracting cancels arr[0..l-1], leaving exactly arr[l..r]. */
}

int main(void) {
    int arr[]    = {2, 3, 1, 5, 4};
    int n        = 5;
    int prefix[5];

    build_prefix(arr, prefix, n);

    printf("%d\n", range_sum(prefix, 1, 3)); /* 9  → 3+1+5 */
    printf("%d\n", range_sum(prefix, 0, 4)); /* 15 → whole array */
    printf("%d\n", range_sum(prefix, 2, 2)); /* 1  → single element */
    return 0;
}

⚠ The Mistake Everyone Makes: Forgetting the l = 0 edge case

Wrong code:

int range_sum(int *prefix, int l, int r) {
    return prefix[r] - prefix[l-1]; /* CRASH when l=0: reads prefix[-1] */
}

What goes wrong: When l is 0, l-1 is -1. In C, prefix[-1] reads memory before the array — undefined behaviour. On embedded targets it can silently return a garbage value; on desktops it may segfault.

Correct code (option A — explicit check):

int range_sum(int *prefix, int l, int r) {
    return (l == 0) ? prefix[r] : prefix[r] - prefix[l-1];
}

Correct code (option B — 1-indexed sentinel, cleaner for interviews):

/* Build: prefix[0]=0, prefix[i] = prefix[i-1] + arr[i-1]  (size n+1) */
/* Query: prefix[r+1] - prefix[l]  — works for ALL l including 0 */

Rule to remember: If your prefix array is 0-indexed and has no sentinel, always guard against l = 0. If you add a dummy prefix[0] = 0, you never need the guard.

Pattern 02 Prefix Sum: Running Total / Pivot Index
① Background

This is a focused variant of the prefix sum idea applied to a specific class of problem: find the index in an array where the sum of elements to the left equals the sum to the right. Before anyone thought of the running-total trick, the brute-force approach was to try every index, and for each candidate recompute both left and right sums from scratch — O(n) work per candidate, O(n²) total. For an array of 100,000 elements that means 10 billion operations.

The insight that makes this tractable is that you already know the total sum of the array. If you know the total, and you know everything to the left so far, then the right sum is trivially computable as: right = total − left − current. You never need to explicitly compute the right side at all. That reduces the algorithm to a single left-to-right pass.

This same "derive right from total minus left" idea appears in load balancing algorithms — find the cut point in a task list where the first half and second half have equal estimated cost. It appears in circuit board design when deciding where to split a bus into two equal-load segments. It appears in logistics when partitioning a delivery route so two trucks carry equal weight. The abstraction is the same every time: you know the whole, you are accumulating the left, and the right is implied.

A more subtle version of this pattern underlies the "contiguous array with equal 0s and 1s" problem (LeetCode 525), where you transform 0s to -1s and then ask for the longest subarray with sum 0. That is the same running-total structure with a hashmap added. Understanding the pivot-index pattern cleanly is the foundation for that harder variant.

② Where You See This
  • Find pivot index where left sum equals right sum. The canonical use case — O(n) with running left total.
  • Splitting an array into two halves with equal sums. Same logic — find the index where the split is balanced.
  • Load balancing: divide tasks between two workers with equal load. Find the cut point in a sorted task list; left worker takes left half, right takes rest.
  • Embedded systems: find the midpoint in a sensor log where cumulative readings balance. Running accumulator over a fixed buffer — no extra memory needed beyond the total.
  • Circuit design: find the optimal bus split point for equal current draw. Partition a list of load values where both halves sum to the same value.
  • Contiguous array with equal 0s and 1s (transform 0→-1, find sum=0). Extension of this pattern with a hashmap to track prefix sums.
③ Building the Logic from Scratch

Start with arr = [1, 4, 3, 2, 4] and ask: is there an index where the left sum equals the right sum? The brute-force approach checks every index:

Index 0: left=[], right=[4,3,2,4]=13 → 0 ≠ 13 Index 1: left=[1]=1, right=[3,2,4]=9 → 1 ≠ 9 Index 2: left=[1,4]=5, right=[2,4]=6 → 5 ≠ 6 Index 3: left=[1,4,3]=8, right=[4]=4 → 8 ≠ 4 Index 4: left=[1,4,3,2]=10, right=[] → 10 ≠ 0

No pivot in this example. That is fine — let us use arr = [1, 7, 3, 6, 5, 6] where the answer is index 3. The total sum is 1+7+3+6+5+6 = 28. Now, instead of recomputing both sides each time, notice: the moment I know left_sum = 11 (from 1+7+3) and I am standing at index 3 with value 6, the right side must be 28 − 11 − 6 = 11. I never iterated the right side. I derived it in one subtraction.

We need to be careful about timing: arr[i] belongs to neither side. It is the candidate pivot itself. So when checking index i, left_sum contains everything strictly to the left (indices 0 to i-1), and right_sum = total − left_sum − arr[i] contains everything strictly to the right (indices i+1 to n-1). We only add arr[i] into left_sum after the check fails and we move to the next index.

arr = [ 1, 7, 3, 6, 5, 6 ] total = 28 ──────────────────────────── i=0: left= 0 cur=1 right=27 → no then left+=1 → left=1 i=1: left= 1 cur=7 right=20 → no then left+=7 → left=8 i=2: left= 8 cur=3 right=17 → no then left+=3 → left=11 i=3: left=11 cur=6 right=11 → YES pivot at 3 ✓
④ Full Code Walkthrough
PSEUDOCODE: total = sum of all elements left_sum = 0 for each i from 0 to n-1: right_sum = total - left_sum - arr[i] if left_sum == right_sum: return i left_sum += arr[i] return -1
#include <stdio.h>

int pivot_index(int *arr, int n) {
    int total = 0;
    for (int i = 0; i < n; i++)
        total += arr[i];
    /* WHY: we need the grand total upfront so we can derive
       right_sum without ever iterating the right side explicitly. */

    int left_sum = 0;
    /* WHY: left_sum starts at 0 because nothing is to the left of index 0. */

    for (int i = 0; i < n; i++) {
        int right_sum = total - left_sum - arr[i];
        /* WHY: total = left_sum + arr[i] + right_sum, so rearranging gives
           right_sum = total - left_sum - arr[i]. This is O(1) per step. */

        /* We need this check BEFORE adding arr[i] to left_sum,
           because arr[i] belongs to neither the left nor the right side. */
        if (left_sum == right_sum)
            return i;

        left_sum += arr[i];
        /* WHY: only AFTER checking, the current element becomes part of
           the left side for the next candidate index. */
    }
    return -1;
}

int main(void) {
    int a[] = {1, 7, 3, 6, 5, 6};
    printf("%d\n", pivot_index(a, 6));   /* 3 */

    int b[] = {2, 1, -1};
    printf("%d\n", pivot_index(b, 3));   /* 0  (left=[], right=1+(-1)=0, arr[0]=2) */
    /* wait: left=0, right=1-1=0, arr[0]=2 → 0==0 ✓ */
    return 0;
}

⚠ The Mistake Everyone Makes: Adding arr[i] to left_sum too early

Wrong code:

for (int i = 0; i < n; i++) {
    left_sum += arr[i];                     /* WRONG: added BEFORE the check */
    int right_sum = total - left_sum - arr[i];

What goes wrong: Now left_sum already includes arr[i] when you compute right_sum. The formula is wrong — arr[i] gets subtracted twice, and the pivot will never be found (or a wrong one will be returned).

Correct: Always compute right_sum and do the check before adding arr[i] to left_sum. The current element is the pivot candidate — it belongs to neither side.

Rule to remember: At index i, left_sum contains indices [0, i-1]. Add arr[i] only after the check fails.

Pattern 03 Prefix Sum: 2D Matrix Range Sum
① Background

The 1D prefix sum solves range queries on arrays. But what happens when your data is a 2D grid — a matrix of values — and you need the sum of any rectangular subregion? The naive approach is to loop over every row and column inside the rectangle: for an r×c rectangle that is O(r×c) per query, and for a large grid with many queries this is completely impractical.

The 2D prefix sum (also called a summed-area table or integral image) generalizes the 1D idea. You build a table P where P[r][c] stores the sum of all elements in the rectangle from the top-left corner (0,0) to position (r,c). Once built, any arbitrary rectangle sum is answered with four lookups and three arithmetic operations — O(1) regardless of rectangle size.

The key mathematical tool used in the query is inclusion-exclusion. When you want the sum of a rectangle from (r1,c1) to (r2,c2), you start with P[r2][c2] (everything from top-left to bottom-right of your target). That is too much — it includes areas above the rectangle and to its left. You subtract those strips. But now you have subtracted the top-left corner region twice, so you add it back once. This is exactly the same principle as Venn diagram overlap: A∪B = A + B − (A∩B).

This pattern is foundational in computer vision. The Viola-Jones face detection algorithm (used in every digital camera since 2001) uses summed-area tables to compute Haar-feature sums over hundreds of rectangular windows per pixel in real time. Without 2D prefix sums, it would be several orders of magnitude too slow for real-time use. The same idea appears in GIS systems (sum population in a geographic bounding box), medical imaging (average pixel intensity in a scan region), and signal processing (running 2D convolution).

② Where You See This
  • Repeated rectangle sum queries on a static matrix. Build once O(n×m), answer each query O(1) — the direct 2D generalization of P01.
  • Computer vision: Viola-Jones face detection (Haar features). Computing thousands of rectangular feature sums per pixel per frame in real time.
  • Image processing: box blur and mean filter. Average over any rectangular region in O(1) using the 2D prefix sum.
  • GIS / mapping: total population or sensor readings in a bounding box. Spatial query on a rasterized grid answered without scanning the region.
  • Game development: fog-of-war visibility or lighting in tile maps. Sum of lit tiles in any rectangular area without per-tile iteration.
  • Embedded: 2D sensor arrays (e.g., pressure mats, IR grids). Aggregate readings over a subregion of a sensor matrix in constant time.
③ Building the Logic from Scratch

Start with a tiny 3×3 grid. We want to answer: what is the sum of the bottom-right 2×2 subgrid (rows 1-2, cols 1-2 in 0-indexed)?

grid (0-indexed): [ 1 2 3 ] [ 4 5 6 ] [ 7 8 9 ] Target rectangle: (r1=1,c1=1) → (r2=2,c2=2) = [5,6,8,9] = 28

Build the prefix table by making each cell store "total from top-left to here". We use 1-indexing so that row 0 and column 0 act as zero-filled borders — this eliminates boundary checks. So P[r][c] = sum of grid cells (0,0) to (r-1,c-1).

④ Full Code Walkthrough
PSEUDOCODE — Build: for r = 1 to rows: for c = 1 to cols: P[r][c] = grid[r-1][c-1] + P[r-1][c] + P[r][c-1] - P[r-1][c-1] PSEUDOCODE — Query (r1,c1)→(r2,c2) in 0-indexed: convert to 1-indexed: r1++, c1++, r2++, c2++ return P[r2][c2] - P[r1-1][c2] - P[r2][c1-1] + P[r1-1][c1-1]
#include <stdio.h>
#define MAXN 101

int P[MAXN+1][MAXN+1]; /* 1-indexed: P[0][*] and P[*][0] are 0 (zero border) */

void build_2d(int grid[MAXN][MAXN], int rows, int cols) {
    for (int r = 1; r <= rows; r++) {
        for (int c = 1; c <= cols; c++) {
            P[r][c] = grid[r-1][c-1]   /* WHY: the actual cell value (1→0 index shift) */
                    + P[r-1][c]         /* WHY: all cells directly above this column */
                    + P[r][c-1]         /* WHY: all cells to the left in this row */
                    - P[r-1][c-1];      /* WHY: top-left region was added twice above,
                                                subtract once to count it exactly once */
        }
    }
}

/* Query sum of rectangle (r1,c1)→(r2,c2), all 0-indexed. */
int query_2d(int r1, int c1, int r2, int c2) {
    r1++; c1++; r2++; c2++;
    /* WHY: shift 0-indexed coords to 1-indexed to use our 1-indexed P table */

    return P[r2][c2]
         - P[r1-1][c2]      /* WHY: remove everything above the rectangle */
         - P[r2][c1-1]      /* WHY: remove everything left of the rectangle */
         + P[r1-1][c1-1];  /* WHY: top-left corner was subtracted twice, add back once */
}

int main(void) {
    int grid[MAXN][MAXN] = {{1,2,3},{4,5,6},{7,8,9}};
    build_2d(grid, 3, 3);
    printf("%d\n", query_2d(1, 1, 2, 2)); /* 28  = 5+6+8+9 */
    printf("%d\n", query_2d(0, 0, 0, 0)); /* 1   = top-left cell only */
    printf("%d\n", query_2d(0, 0, 2, 2)); /* 45  = entire grid */
    return 0;
}

Pattern 04 Two Pointer: Sorted Array Pair Sum
① Background

The naive approach to finding two numbers in an array that sum to a target is the nested loop: for every pair (i, j) with i < j, check if arr[i] + arr[j] == target. This is O(n²). For 10,000 elements that means 50 million pair checks. It works, but there is a much better way when the array is sorted.

The sorted two-pointer technique exploits a property that only sorted data has: the array has a natural "direction" — values increase as you go right. This means moving the left pointer right always increases the available sum, and moving the right pointer left always decreases it. You can make informed decisions about which direction to move based purely on whether the current sum is too big or too small.

This idea was recognized in the context of merge algorithms and computational geometry in the 1970s and 1980s. It reduces the pair-sum problem from O(n²) to O(n) with no extra space — you need only two integer indices. The two pointers start at opposite ends of the sorted array and converge toward each other, eliminating large swaths of the search space with each step.

In practice this pattern appears when you already have a sorted input (which is common — sorted sensor readings, sorted timestamps, sorted distances). It is also the inner loop of Three Sum (P07), which sorts first and then runs this as a sub-routine. Competitive programmers use it to solve problems in O(n) that beginners solve in O(n²). It also generalizes to "two pointer on two separate sorted arrays" — for example, merging two sorted streams or finding the pair from two different arrays whose sum is closest to a target.

② Where You See This
  • Find pair in sorted array summing to target. Classic O(n) two-pointer after sorting — the template problem.
  • Three Sum: find all triplets summing to zero. Fix one element, run two-pointer on the rest — O(n²) total (P07).
  • Squares of sorted array: square each, produce sorted result. Largest squares come from both ends; converge two pointers inward.
  • Closest pair sum to a target in a sorted array. Same convergence — track minimum absolute difference during the sweep.
  • Embedded: matching send/receive packets by sequence number. Two sorted streams of packet IDs — converging two pointers finds paired entries.
  • Database join on sorted key columns. Sort-merge join is this pattern applied to two separate sorted lists.
  • Valid palindrome check on a string (char-by-char). Left and right pointers converging — same convergence logic, different termination.
③ Building the Logic from Scratch

Take arr = [1, 3, 6, 8, 11] and target = 9. The brute force checks all pairs: (1,3), (1,6), (1,8), (1,11), (3,6), (3,8), (3,11), (6,8), (6,11), (8,11). That's 10 checks. But do we need all 10?

Start left at index 0 (value 1) and right at index 4 (value 11). Sum = 12. That is too big. Can the pair (1, 11) ever work for a target of 9? No. Can any pair that includes 11? Only if the other element is negative — but the array has no negatives. Key insight: in a sorted array, when the sum is too big, the right element is the problem. Move right inward to get a smaller value.

arr = [ 1, 3, 6, 8, 11 ] target = 9 ↑ ↑ left=0 right=4 sum = 1 + 11 = 12 > 9 → move right inward arr = [ 1, 3, 6, 8, 11 ] ↑ ↑ left=0 right=3 sum = 1 + 8 = 9 == target → FOUND ✓

Symmetrically, when sum is too small, move left rightward to get a bigger value. When left and right meet, every pair has been considered. The total number of pointer moves is at most n−1, so the algorithm is O(n).

We need the condition to be left < right, not left <= right. When left == right, both pointers are pointing at the same element — you cannot use the same element twice in a pair (unless the problem allows it). The loop must stop before they collide.

④ Full Code Walkthrough
PSEUDOCODE: left = 0, right = n - 1 while left < right: sum = arr[left] + arr[right] if sum == target: return (left, right) if sum > target: right-- (too big, shrink right) if sum < target: left++ (too small, grow left)
#include <stdio.h>

int two_sum_sorted(int *arr, int n, int target, int *out_l, int *out_r) {
    int left  = 0;
    int right = n - 1;
    /* WHY: left starts at minimum value, right at maximum.
       Between them, every possible pair sum is reachable. */

    while (left < right) {
        /* WHY: when pointers meet, both would point to the same element.
           A pair needs two distinct positions, so we stop before they meet. */

        int sum = arr[left] + arr[right];

        if (sum == target) {
            *out_l = left;
            *out_r = right;
            return 1;
        }

        /* WHY for each branch:
           sum > target → right element is too large. Only fix: make right smaller.
                          Moving left right would make sum even larger. So: right--.
           sum < target → left element is too small. Only fix: make left larger.
                          Moving right left would make sum even smaller. So: left++. */
        if (sum > target) right--;
        else               left++;
    }
    return 0;   /* exhausted all candidates */
}

int main(void) {
    int arr[] = {1, 3, 6, 8, 11};
    int l, r;
    if (two_sum_sorted(arr, 5, 9, &l, &r))
        printf("indices %d and %d  (values %d+%d=9)\n", l, r, arr[l], arr[r]);
    /* indices 0 and 3  (values 1+8=9) */
    return 0;
}

Pattern 05 Two Pointer: Remove Duplicates In-Place
① Background

When working with sorted data, duplicates appear in consecutive runs. A classic problem is removing them in-place — without allocating a second array — and returning the new length. The naive approach would shift elements left every time a duplicate is found, giving O(n²) due to repeated copying. But there is an O(n) way that uses only two index variables: one for reading, one for writing.

This is called the slow-fast pointer or read-write pointer pattern. The write pointer marks the boundary of the "clean" de-duplicated region on the left. The read pointer scans through every element. When read encounters a value different from the last written value, it copies it to the write position and advances write. When read sees a duplicate (same as write's current value), it just moves on without writing anything. Write only moves when something new and unique is found.

The result is an in-place compaction in a single O(n) pass with O(1) extra space. This pattern is used in firmware when deduplicating sensor readings stored in a fixed buffer — you cannot allocate a new buffer on a microcontroller with 2 KB of RAM. It is also the core of database query engines that eliminate duplicates from a sorted intermediate result without materializing a copy. The Linux kernel uses the same concept when compacting page tables.

A generalization is "remove all instances of a given value" (LeetCode 27) and "allow at most k duplicates" (LeetCode 80). In both cases, the same read-write structure applies — only the condition that advances the write pointer changes.

② Where You See This
  • Remove duplicates from a sorted array in-place. The canonical use case — write advances only on new unique values.
  • Remove all instances of a specific value in-place. Same pattern — write advances whenever read's value doesn't match the target.
  • Allow at most k duplicates (LeetCode 80). Write advances when arr[read] != arr[write - k] — same skeleton, different condition.
  • Firmware: deduplicate a sorted sensor log buffer without extra allocation. Constrained memory — read-write pointer compacts in-place with zero extra bytes.
  • Database: eliminate duplicates from a sorted query result. Sorted intermediate results can be deduplicated in one pass during the scan.
  • Stream processing: compact a sliding window of sorted events. As new events arrive, old duplicates are overwritten in-place by the write pointer.
③ Building the Logic from Scratch

Start with arr = [1, 1, 2, 3, 3]. We want [1, 2, 3] in the first three positions, and we cannot use extra memory. Think about what "removing duplicates" means physically: we want to compress the unique elements toward the front.

What if we had two hands on the array? One hand (write) holds the position of the last unique element we have confirmed. The other hand (read) scans forward. The key insight: the write pointer never needs to look backward — it only holds one piece of state: the last unique value written. When read finds something different, write takes one step forward and copies it there.

Initial: [ 1, 1, 2, 3, 3 ] W=0 R=1 ↑ ↑ write read read=1: arr[1]=1 == arr[write=0]=1 → DUPLICATE, read moves on [ 1, 1, 2, 3, 3 ] W ↑R=2 read=2: arr[2]=2 != arr[write=0]=1 → NEW. write++, arr[1]=2 [ 1, 2, 2, 3, 3 ] W ↑R=3 read=3: arr[3]=3 != arr[write=1]=2 → NEW. write++, arr[2]=3 [ 1, 2, 3, 3, 3 ] W ↑R=4 read=4: arr[4]=3 == arr[write=2]=3 → DUPLICATE return write+1 = 3 → arr[0..2] = [1, 2, 3] ✓

Notice that the region arr[0..write] is always the correctly de-duplicated prefix. The region arr[write+1..read-1] is "garbage" — elements we have already read but don't need. The region arr[read..n-1] is still to be examined. These three regions never overlap, and their boundaries are maintained automatically.

④ Full Code Walkthrough
PSEUDOCODE: if n == 0: return 0 write = 0 for read = 1 to n-1: if arr[read] != arr[write]: write++ arr[write] = arr[read] return write + 1
#include <stdio.h>

int remove_duplicates(int *arr, int n) {
    if (n == 0) return 0;
    /* WHY: empty array has no first element to anchor write at index 0 */

    int write = 0;
    /* WHY: index 0 is always unique (nothing before it), so write starts there.
       arr[0] is already in the right place — no need to copy it. */

    for (int read = 1; read < n; read++) {
        /* WHY: start read at 1 — we already "accepted" arr[0] via write=0 */

        if (arr[read] != arr[write]) {
            /* WHY: a new unique value was found.
               We need to decide: is arr[read] different from the last accepted value?
               arr[write] always holds the last accepted unique value. */
            write++;
            /* WHY: advance write to the next slot BEFORE writing.
               write points to the current last-unique position; we need the NEXT slot. */
            arr[write] = arr[read];
            /* WHY: copy the new unique value into its final resting place. */
        }
        /* WHY when NOT entering the if: arr[read] is a duplicate.
           read will advance automatically (via for loop).
           write stays — we haven't found anything worth keeping. */
    }
    return write + 1;
    /* WHY: write is 0-indexed. If write=2, we have 3 unique elements at [0,1,2]. */
}

int main(void) {
    int arr[] = {1, 1, 2, 3, 3};
    int new_len = remove_duplicates(arr, 5);
    printf("length=%d, arr=[", new_len);
    for (int i = 0; i < new_len; i++)
        printf("%d%s", arr[i], i < new_len-1 ? "," : "");
    printf("]\n");  /* length=3, arr=[1,2,3] */
    return 0;
}

Pattern 06 Two Pointer: Move Zeros to End
① Background

Move-zeros-to-end is a small but important pattern: reorder an array so all zeros are at the back and all non-zero elements are at the front in their original relative order. No extra array is allowed. The naive approach — repeatedly finding the first zero and shifting all elements after it left — is O(n²) due to the shift cost. The two-pointer version is O(n) with a single pass.

This is the same read-write pointer skeleton as P05, but the condition is different: instead of "write advances when a new unique value is found", write advances when any non-zero value is found. The write pointer separates the "kept" region on the left from the "to be zeroed" region on the right. After the scan, anything from write to n-1 must be zeroed.

Alternatively, you can swap arr[write] and arr[read] instead of overwriting — this avoids the trailing fill step because zeros get swapped into the garbage region automatically. The overwrite version requires the fill; the swap version does not. Both are O(n), O(1) space.

In practice this pattern arises when filtering or partitioning arrays in-place — for example, moving all even elements to the front (LeetCode 905), or moving all elements less than a pivot to the front (partition step in quicksort). The underlying structure is identical: a write pointer that advances only on elements satisfying a predicate, with all "rejected" elements falling behind it.

② Where You See This
  • Move all zeros to the end, preserving non-zero order. The canonical problem — write pointer advances on non-zero, fill zeros at end.
  • Sort array by parity (evens first, odds second). Same skeleton — write advances when arr[read] is even.
  • Partition step in quicksort. Write advances when arr[read] <= pivot — same read-write structure.
  • Embedded: compact a DMA buffer by removing null/invalid frames. In-place compaction with no allocation — critical in constrained memory environments.
  • Remove all instances of a value from an unsorted array. Write advances when arr[read] != target — generalisation of this pattern.
  • Separating valid and invalid entries in a packet queue. Write pointer holds position for next valid packet; invalid ones left behind.
③ Building the Logic from Scratch

Take arr = [0, 1, 0, 3, 12]. We want [1, 3, 12, 0, 0]. We cannot allocate a new array. Think about the problem in terms of what we want: the non-zero elements should land at the beginning in their original order. The zeros just fill the rest.

If we only focus on the non-zero elements and where they need to go: 1 should be at index 0, 3 at index 1, 12 at index 2. That is exactly what a write pointer does — it marks the next available "destination" slot for a non-zero element. Read scans everything; when it finds a non-zero, write takes it.

arr = [ 0, 1, 0, 3, 12 ] R read scans, write starts at 0 W read=0: arr[0]=0 → zero, skip. read moves to 1. arr = [ 0, 1, 0, 3, 12 ] W=0, R=1 W R read=1: arr[1]=1 → non-zero! arr[W=0]=1, write=1. read moves to 2. arr = [ 1, 1, 0, 3, 12 ] W=1, R=2 W R read=2: arr[2]=0 → zero, skip. read moves to 3. read=3: arr[3]=3 → non-zero! arr[W=1]=3, write=2. arr = [ 1, 3, 0, 3, 12 ] W=2, R=4 read=4: arr[4]=12 → non-zero! arr[W=2]=12, write=3. arr = [ 1, 3, 12, 3, 12 ] W=3, scan done. The key insight: read always advances. Write only advances when it finds a non-zero to keep. The gap between write and read is exactly the number of zeros we have "skipped over" so far — those positions will be filled with zeros at the end.

#include <stdio.h>

void move_zeros(int *arr, int n) {
    int write = 0;
    /* WHY: write starts at 0 — first non-zero element should land at index 0.
       Unlike P05, there is no guaranteed "first good element" so write starts at 0
       unconditionally and read also starts at 0. */

    for (int read = 0; read < n; read++) {
        if (arr[read] != 0) {
            arr[write] = arr[read];
            /* WHY: copy this non-zero to the current write position.
               We are compacting all non-zeros to the front in original order. */
            write++;
            /* WHY: advance write to reserve the next slot for the next non-zero. */
        }
        /* WHY when arr[read]==0: skip writing. read will advance via the for loop.
           write stays behind — the zero is implicitly "deferred" to the fill phase. */
    }

    /* WHY this loop: everything at indices [write, n-1] should be zero.
       We never explicitly moved zeros — we compacted non-zeros over them.
       Now fill the tail. */
    while (write < n)
        arr[write++] = 0;
}

int main(void) {
    int arr[] = {0, 1, 0, 3, 12};
    move_zeros(arr, 5);
    for (int i = 0; i < 5; i++) printf("%d ", arr[i]);
    /* 1 3 12 0 0 */
    return 0;
}

Pattern 07 Two Pointer: Three Sum
① Background

Three Sum asks: find all unique triplets in an array that sum to zero. The brute force checks every combination of three indices: O(n³). For 1000 elements, that is one billion operations. A hash-set approach gets it to O(n²) time but requires O(n) extra space and complicated deduplication logic. The sort + two-pointer approach achieves O(n²) time with O(1) extra space and clean deduplication.

The core reduction is: once you fix one element arr[i], the remaining problem is "find two elements in the subarray [i+1, n-1] that sum to -arr[i]." That is exactly the pair-sum problem from P04, which we already know how to solve in O(n) on a sorted array. So Three Sum becomes: sort once O(n log n), then for each of n elements run a O(n) two-pointer scan — total O(n²).

The deduplication is the trickiest part. Because the array can contain repeating values, the same triplet can be "found" multiple times: once for each duplicate value of arr[i], and once for each duplicate value of arr[left] or arr[right] when a match is found. All three sources of duplicates need to be explicitly skipped.

This pattern generalizes directly to K-Sum for any K: sort first, then fix K-2 elements with nested loops, and use two-pointer for the final pair. Four Sum is O(n³), Five Sum is O(n⁴), and so on. Recognizing that any K-Sum reduces to a sorted two-pointer at its innermost level is a key insight for interview problems.

② Where You See This
  • Find all unique triplets in an array summing to zero. Sort + fix one + two-pointer inner loop — the canonical Three Sum.
  • Find triplet closest to a target (3Sum Closest). Same skeleton — track minimum absolute difference instead of exact equality.
  • Four Sum: fix two with nested loops, two-pointer for remaining pair. Direct generalization — O(n³) total, same deduplication logic at each level.
  • Pythagorean triplets in a sorted array. Fix hypotenuse c², find a²+b²==c² with two-pointer — same structure.
  • Triangle validity: find any triplet forming a valid triangle. Sort + fix longest side + two-pointer on remaining sides checking a+b > c.
③ Building the Logic from Scratch

Take arr = [-1, 0, 1, 2, -1, -4]. After sorting: [-4, -1, -1, 0, 1, 2]. We want all triplets summing to 0.

Fix arr[i] = -4 (index 0). We need two numbers from [-1,-1,0,1,2] summing to 4. Left pointer starts at index 1 (-1), right at index 5 (2). Sum = -1+2 = 1 ≠ 4. Since sum is too small, we need a bigger left value — left++. Continue... no pair found. Move to next i.

Fix arr[i] = -1 (index 1). We need two numbers summing to 1 from [-1,0,1,2]. Left=2(-1), right=5(2). Sum = -1+2 = 1 = target! Record [-1,-1,2]. Now we must skip duplicates: advance left past any more -1s, advance right past any more 2s, then move both. Next: left=3(0), right=4(1). Sum=1. Record [-1,0,1]. Move both. Now left≥right, stop this inner loop.

Why skip when arr[i]==arr[i-1]? Because the two-pointer sweep on subarray [i+1..n-1] will find exactly the same pairs as it did for i-1. Every triplet found for i=1 with arr[1]=-1 would be found again for i=2 with arr[2]=-1. The i>0 guard prevents the very first index from being skipped.

#include <stdio.h>
#include <stdlib.h>

int cmp_int(const void *a, const void *b) { return *(int*)a - *(int*)b; }

int three_sum(int *arr, int n, int result[][3]) {
    qsort(arr, n, sizeof(int), cmp_int);
    /* WHY sort: two-pointer only works on sorted data. Sort cost O(n log n)
       is dominated by the O(n²) outer loops. */

    int count = 0;

    for (int i = 0; i < n - 2; i++) {
        if (arr[i] > 0) break;
        /* WHY: sorted array — if arr[i] > 0, all remaining elements are also > 0.
           Three positives can never sum to 0. Safe to stop entirely. */

        if (i > 0 && arr[i] == arr[i-1]) continue;
        /* WHY: arr[i] is a duplicate of the previous fixed element.
           The two-pointer sweep would find the same triplets again → skip.
           i > 0 guard prevents skipping the very first element. */

        int left = i + 1, right = n - 1;

        while (left < right) {
            int sum = arr[i] + arr[left] + arr[right];

            if (sum == 0) {
                result[count][0] = arr[i];
                result[count][1] = arr[left];
                result[count][2] = arr[right];
                count++;

                /* WHY these while loops: skip duplicate left values before moving.
                   If arr[left] appears multiple times, each would produce the same triplet. */
                while (left < right && arr[left]  == arr[left+1])  left++;
                while (left < right && arr[right] == arr[right-1]) right--;

                left++;  right--;
                /* WHY: move past the values we just recorded */

            } else if (sum > 0) {
                right--;
                /* WHY: sum too large. Right element is biggest available.
                   Only shrinking the right can reduce the sum. */
            } else {
                left++;
                /* WHY: sum too small. Left element is smallest available.
                   Only growing the left can increase the sum. */
            }
        }
    }
    return count;
}

⚠ The Mistake Everyone Makes: Missing duplicate skipping → repeated triplets

Pattern 08 Two Pointer: Container With Most Water
① Background

Given n vertical walls with heights h[0]..h[n-1], find the two walls that enclose the most water. The water volume between walls at positions i and j is (j − i) × min(h[i], h[j]). Brute force checks all n×(n-1)/2 pairs — O(n²). The two-pointer technique reduces this to O(n) with a beautiful greedy argument.

The key insight is about what happens when we make a move. We start with the widest possible configuration: left at index 0, right at index n-1. This maximizes width. Now, to improve, we must move one pointer inward — reducing width by 1. The question is which one to move.

If we move the taller wall, width decreases and the limiting height (the shorter wall) can only stay the same or decrease — because the shorter wall is still there unchanged. So moving the taller wall is guaranteed to either keep area the same or make it worse. Moving the shorter wall is the only bet that can pay off: we accept a smaller width in exchange for a chance at a taller shorter-wall. This is the greedy proof: any optimal pair can be reached by always moving the shorter wall.

This pattern has applications beyond the literal water problem. In networking, you might want to maximize throughput between two endpoints where bandwidth is limited by the minimum of the two link speeds — moving the slower link to the next faster option follows the same logic. In distributed systems, the minimum of two latencies limits overall response time — you want to "move" the slower component first.

② Where You See This
  • Container with most water — maximize area between two heights. The canonical use case for this greedy two-pointer.
  • Finding the pair of points maximizing some width×height product. Same greedy argument whenever the product is bounded by the minimum of two values.
  • Networking: maximize throughput between two nodes limited by min link speed. Greedy: always upgrade the slower link first for best marginal gain.
  • Trapping rain water — different but related (needs both walls simultaneously). Related problem — uses prefix max arrays instead of two-pointer, but same reasoning.
  • Any problem with two endpoints + area/volume = distance × min-of-heights. Recognize the min(h[l], h[r]) × width formula → reach for this pattern.
③ Building the Logic from Scratch

Start widest: left=0 (h=1), right=8 (h=7). Area = 8 × 1 = 8. Now, which pointer to move? If we move right (the taller one, h=7), width becomes 7, and the cap is still h[0]=1 (since 1 is still there). Best possible area: 7×1=7 — worse. Moving the taller wall can only maintain or reduce the area. So we move the shorter wall (left, h=1).

The algorithm never misses the optimal pair. Here is the formal argument: if the optimal pair is (i, j) with i < j, the algorithm will have left=i or right=j at some point during the traversal. When it does, it will compute that area. The key is that we never "skip" any candidate we should have computed — every potentially-optimal pair gets evaluated.

#include <stdio.h>

int max_water(int *h, int n) {
    int left = 0, right = n - 1, max_area = 0;
    /* WHY start at extremes: widest possible configuration first.
       We never need to consider pairs with wider separation — these are all considered. */

    while (left < right) {
        int width  = right - left;
        int height = h[left] < h[right] ? h[left] : h[right];
        /* WHY min(h[left], h[right]): water spills over the shorter wall.
           Height is limited by the bottleneck wall, not the taller one. */

        int area = width * height;
        if (area > max_area) max_area = area;

        /* WHY move the shorter wall:
           Moving the TALLER wall → width decreases, min-height stays or decreases → area ≤ current.
           Moving the SHORTER wall → width decreases but min-height could increase → area might improve.
           Taller wall is "done contributing" as a bottleneck; shorter wall has upside potential. */
        if (h[left] < h[right])
            left++;
        else
            right--;
        /* WHY else (not else-if): when equal, either move is fine — moving right is arbitrary. */
    }
    return max_area;
}

Pattern 09 Sliding Window: Fixed Size Maximum Sum
① Background

Imagine you are monitoring a network switch and want to find the busiest consecutive five-second window in an hour-long traffic log. The naive approach recomputes the sum from scratch for every possible window position: that's O(n×k) operations, which for n=3600 seconds and k=5 still seems fine, but at millisecond granularity with millions of samples it becomes prohibitively slow.

The slow solution's flaw is that it discards the work it just did. When the window slides one step right, 4 of the 5 elements are identical to the previous window. We recompute their contribution for no reason. The fix is elegant: instead of recomputing the full sum, maintain a running total and make two O(1) adjustments — subtract the element that fell off the left edge, add the element that entered on the right.

This "slide by delta" idea appears everywhere signals and data streams are analyzed. Digital signal processing applies finite impulse response (FIR) filters this way — each output sample is the dot product of a fixed-length coefficient array with the last k input samples, and as the input stream advances the FIR filter just updates by one add and one subtract. Genomics tools scan for k-mers (substrings of length k) across DNA sequences using the same rolling-hash variation of this idea.

In embedded systems and firmware, circular-buffer designs often need the running sum of the last N ADC readings to compute a smoothed sensor value without storing the sum of all previous readings — the fixed-size window pattern maps directly onto that constraint. The pattern is deceptively simple but it is the foundation for all sliding-window reasoning: master it here before moving to the variable-size variant.

② Where You See This
  • Max/min/average over a rolling window of exactly k elements — any fixed-size aggregation query reduces to "build first window, slide by delta."
  • Network telemetry: peak throughput in any consecutive k milliseconds — the window size is fixed by the SLA measurement interval; you slide over the packet-count array.
  • Firmware smoothing: running average of last N ADC readings — embedded devices average sensor readings over a fixed history; the window slides as new samples arrive.
  • LeetCode 643 — Maximum Average Subarray I — textbook application; max average = max sum / k, same window arithmetic.
  • LeetCode 438 — Find All Anagrams in a String — uses a fixed-size frequency window and checks equality at each position.
  • FIR filters in DSP: output[i] = sum of coefficients × input[i..i+k-1] — the sliding-sum is the unweighted version; weighted sums follow the same O(n) sliding structure.
③ Building the Logic From Scratch

Start with a tiny array so you can see every step without arithmetic fatigue. Let arr = [2, 3, 4, 1, 5] and k = 3. We want the maximum sum over any three consecutive elements.

Step one: compute the first window by hand. Window [0..2] = 2 + 3 + 4 = 9. Write this down as window_sum = 9, max_sum = 9.

Step two: slide the window one position right. The new right element is arr[3] = 1. The element leaving is arr[0] = 2. Notice that we do not touch arr[1] or arr[2] at all — they stay inside the window and their contribution is already embedded in window_sum.

arr: [ 2 | 3 | 4 | 1 | 5 ] [←─── window ───→] out idx 1 2 3 window_sum = 9 - 2 + 1 = 8 (max stays 9)

Step three: slide again. New right = arr[4] = 5. Element leaving = arr[1] = 3.

arr: [ 2 | 3 | 4 | 1 | 5 ] [←─── window ───→] out idx 2 3 4 window_sum = 8 - 3 + 5 = 10 (max updates to 10)

The general formula when the right edge is at index i: subtract arr[i - k] (the element that just left), add arr[i] (the element that just entered). The leaving index is always exactly k positions behind the entering index.

Before writing any code, write the two-phase plain-English algorithm: (1) seed the sum with the first k elements; (2) for every subsequent index i, update window_sum = window_sum - arr[i-k] + arr[i], then check against max_sum.

PSEUDOCODE window_sum = sum(arr[0..k-1]) max_sum = window_sum for i from k to n-1: window_sum += arr[i] // right element enters window_sum -= arr[i - k] // left element exits max_sum = max(max_sum, window_sum) return max_sum
/* Maximum sum of any contiguous subarray of exactly k elements. */
int max_sum_window(int *arr, int n, int k) {
    int window_sum = 0;

    /* Seed the first window [0..k-1].
       We do this separately because the slide formula needs a previous
       window_sum to update — there is no "previous" for the first window. */
    for (int i = 0; i < k; i++)
        window_sum += arr[i];

    int max_sum = window_sum;
    /* The first window is a valid answer; initialise max_sum here
       so the slide loop only needs to check, not initialise. */

    for (int i = k; i < n; i++) {
        /* arr[i] is the new right element entering the window. */
        window_sum += arr[i];

        /* arr[i - k] is the element that was at the LEFT edge before this slide.
           After sliding right by 1, the new left edge is at (i - k + 1),
           so (i - k) just exited. Subtract it to keep the sum correct. */
        window_sum -= arr[i - k];

        /* Update the global best. */
        if (window_sum > max_sum)
            max_sum = window_sum;
    }
    return max_sum;
}

Pattern 10 Sliding Window: Variable Size (Shrink When Invalid)
① Background

The fixed-size sliding window from P09 works when the window length is given. But many problems ask for the shortest or longest subarray satisfying a condition — and you do not know the length in advance. A brute-force approach tries every possible start and end index, recomputing the aggregate each time: O(n²) or O(n²k) depending on what you're computing. That is too slow for n = 10⁵.

The key insight that makes the variable window work in O(n) is that the left pointer never needs to go backwards. Once an element is no longer part of any promising window, it can be permanently discarded. Think of a sliding rubber band: you stretch it right to include new elements, and when the rubber band encloses something invalid, you pinch the left end and slide it forward — never backward — until validity is restored. Every element enters the window exactly once (when right passes over it) and exits exactly once (when left passes over it), so the total work is O(n) regardless of how many shrink steps happen.

This pattern is not just for sums. The condition can be "at most K distinct characters," "product less than K," "no duplicate elements," or any property that becomes invalid as the window grows and becomes valid again as the window shrinks. The critical requirement is monotonicity: if the window is invalid, adding more elements on the right cannot fix it — only removing elements from the left can. That monotonicity guarantee is what lets both pointers stay O(n) total.

In real systems this pattern appears in rate limiters (find the shortest time window with more than K requests), memory allocators (find the smallest contiguous free block satisfying a size requirement), and TCP receive-buffer analysis (find the minimum window of packets that covers a required acknowledgment range).

② Where You See This
  • LeetCode 209 — Minimum Size Subarray Sum — textbook application: shrink while sum ≥ target, record minimum length.
  • LeetCode 3 — Longest Substring Without Repeating Characters — grow right until a character repeats; shrink left until the repeat is gone; track max length.
  • LeetCode 76 — Minimum Window Substring — variable window with a frequency-map condition; same grow-then-shrink skeleton.
  • Rate limiting: shortest interval containing more than K events — event timestamps are the array; shrink-while-condition finds the tightest window.
  • Embedded / RTOS: smallest consecutive sample window whose average exceeds a threshold — sensor data streams naturally map to arrays; fixed target with variable window size.
  • Network analysis: minimum consecutive packets whose total size covers a required byte count — packet sizes are the array; find the shortest burst window covering the SLA threshold.
③ Building the Logic From Scratch

Use arr = [2, 3, 1, 2, 4, 3] with target = 7 (minimum-length subarray with sum ≥ 7). There are 6 elements; let's trace what happens step by step.

Start with left = 0, window_sum = 0, min_len = ∞. The right pointer moves forward one step at a time. Each step, include arr[right] in the window.

right=0: window=[2] sum=2 (2 < 7, keep growing) right=1: window=[2,3] sum=5 (5 < 7, keep growing) right=2: window=[2,3,1] sum=6 (6 < 7, keep growing) right=3: window=[2,3,1,2] sum=8 (8 ≥ 7, condition met!)

Notice that now we try to shrink. Can we remove elements from the left and still have sum ≥ 7? Remove arr[0]=2: sum becomes 6. That's below 7, so we stop shrinking. We recorded length=4 before we shrunk. min_len = 4.

right=4: add arr[4]=4, sum=6+4=10 (10 ≥ 7, condition met again) shrink: remove arr[1]=3, sum=7, len=4 (min still 4) still ≥ 7! remove arr[2]=1, sum=6, len=3 → stop. min_len=3

Keep going for right=5. After all steps the answer is 2 (the window [4,3]).

The key realisation: the shrink step uses a WHILE loop, not an IF. At right=4, two shrink steps happened in a row. An IF would have missed the second, giving min_len=4 instead of 3.

/* Minimum length subarray with sum >= target.  Returns 0 if none. */
int min_subarray_len(int *arr, int n, int target) {
    int left       = 0;
    int window_sum = 0;
    int min_len    = INT_MAX;  /* sentinel: any real window length is smaller */

    for (int right = 0; right < n; right++) {
        /* Always expand: the right pointer never waits.
           Every element gets a chance to contribute to a valid window. */
        window_sum += arr[right];

        /* Shrink from the left for as long as the window is valid.
           Using WHILE (not IF): multiple shrink steps may happen at a single
           right-pointer position — each gives a potentially shorter valid window. */
        while (window_sum >= target) {
            int len = right - left + 1;       /* window is [left..right] */
            if (len < min_len) min_len = len; /* record before shrinking */

            /* Remove the leftmost element and slide left forward.
               After this, the window may no longer satisfy the condition,
               which is fine — we exit the while and let right advance. */
            window_sum -= arr[left];
            left++;
        }
    }

    /* INT_MAX means the condition was never satisfied. */
    return min_len == INT_MAX ? 0 : min_len;
}

/* Longest subarray of integers with all distinct values.
   Works for any integer values; uses a hash map simulated with an int array for chars. */
int longest_no_repeat(char *s, int n) {
    int freq[256] = {0};   /* frequency of each character in the current window */
    int left      = 0;
    int max_len   = 0;

    for (int right = 0; right < n; right++) {
        freq[(unsigned char)s[right]]++;    /* add right character to window */

        /* shrink from left until the duplicate is removed */
        while (freq[(unsigned char)s[right]] > 1) {
            freq[(unsigned char)s[left]]--; /* remove left character from window */
            left++;                         /* advance left boundary */
        }

        int len = right - left + 1;        /* current window length */
        if (len > max_len) max_len = len;
    }
    return max_len;
}

Pattern 12 Sliding Window: Minimum Window Substring
① Story First
You are looking for the shortest section of a newspaper that contains every word from a required list. You expand your reading window right until you've found all required words. Then you shrink from the left as much as possible while still having all words covered. Record the shortest valid window and repeat.
② The Insight

③ Step-by-Step Logic

  2. Initialize have[c] = 0, formed = 0 (how many chars in t are fully covered), required = distinct chars in t.
  3. Expand right: add s[right] to have[]. If have[c] == need[c], increment formed.
  4. While formed == required (window is valid): record window if it's the shortest so far. Shrink left: if removing s[left] makes have[c] < need[c], decrement formed. Then left++.
⑤ Annotated Code
#include <string.h>
#include <limits.h>

/* Find start index and length of minimum window in s containing all chars of t.
   Returns length; sets *start to the starting index. Returns INT_MAX if not found. */
int min_window(const char *s, const char *t, int *start) {
    int need[256] = {0};   /* required frequency of each char from t */
    int have[256] = {0};   /* current frequency of each char in the window */
    int required  = 0;     /* number of distinct chars in t that need to be satisfied */

    for (int i = 0; t[i]; i++) {
        if (need[(unsigned char)t[i]] == 0) required++;  /* new distinct char */
        need[(unsigned char)t[i]]++;
    }

    int left = 0, formed = 0;
    int min_len = INT_MAX;
    *start = 0;

    for (int right = 0; s[right]; right++) {
        unsigned char c = (unsigned char)s[right];
        have[c]++;                              /* add right char to window */
        if (need[c] > 0 && have[c] == need[c]) /* this char is now fully covered */
            formed++;

        while (formed == required) {            /* window contains all of t */
            int len = right - left + 1;
            if (len < min_len) { min_len = len; *start = left; } /* best so far */

            unsigned char lc = (unsigned char)s[left];
            have[lc]--;                         /* remove left char from window */
            if (need[lc] > 0 && have[lc] < need[lc])  /* lost coverage of this char */
                formed--;
            left++;
        }
    }
    return min_len;
}

① Story First

② The Insight

③ Step-by-Step Logic

  2. At each right: add arr[right] to the window state.
  3. Shrink left while the window violates the condition.
  4. Add right - left + 1 to the total count (all subarrays ending at right, starting from left..right).

/* Count subarrays with at most k distinct integers. */
int count_subarrays_at_most_k(int *arr, int n, int k) {
    int freq[20001] = {0};   /* frequency of values in current window */
    int distinct    = 0;     /* number of distinct values in current window */
    int left        = 0;
    int count       = 0;

    for (int right = 0; right < n; right++) {
        if (freq[arr[right]] == 0) distinct++;  /* new distinct value entered */
        freq[arr[right]]++;

        /* shrink until at most k distinct values in window */
        while (distinct > k) {
            freq[arr[left]]--;
            if (freq[arr[left]] == 0) distinct--;  /* that value is gone from window */
            left++;
        }

        /* every subarray ending at right, starting at left..right, is valid */
        count += right - left + 1;
    }
    return count;
}

/* Count subarrays with EXACTLY k distinct integers (common trick). */
int count_exactly_k(int *arr, int n, int k) {
    /* exactly(k) = atMost(k) - atMost(k-1) */
    return count_subarrays_at_most_k(arr, n, k)
         - count_subarrays_at_most_k(arr, n, k - 1);
}

int binary_search(int *arr, int n, int target) {

        int mid = lo + (hi - lo) / 2;   /* avoid overflow: do NOT use (lo+hi)/2 */

        if (arr[mid] == target)

        else if (arr[mid] < target)
            lo = mid + 1;               /* target must be in the right half */
        else
            hi = mid - 1;               /* target must be in the left half */
    }
    return -1;   /* lo > hi means target is not in the array */

    int lo = 0, hi = n - 1;

    while (lo < hi) {          /* loop until lo and hi converge */
        int mid = lo + (hi - lo) / 2;

        if (arr[mid] < arr[mid + 1]) {
            lo = mid + 1;   /* going uphill to the right: peak is to the right */
        } else {
            hi = mid;       /* going downhill (or flat) right: peak is at mid or left */
        }
    }
    return lo;   /* lo == hi: this is the peak index */
}

Pattern 19 Binary Search: Answer Space (Minimize/Maximize a Value)
① Story First
Instead of searching an array for a position, you binary search the space of possible answers. "What is the minimum speed at which I can finish?" Try a speed in the middle of all valid speeds. If it works, try lower. If it doesn't work, try higher. You are binary searching the answer, not the array.
② The Insight
When the feasibility of an answer is monotonic — "if speed X works, all speeds > X also work" — you can binary search the answer space [lo, hi]. Find the boundary where feasibility changes.
③ Step-by-Step Logic
  1. Identify the answer range: lo = minimum possible answer, hi = maximum possible answer.
  2. Write a feasible(mid) function that checks if answer = mid satisfies the problem constraints.
  3. Binary search: if feasible(mid), record mid as a candidate and search lower (hi = mid - 1). Else search higher (lo = mid + 1).
  4. Return the last valid candidate.
⑤ Annotated Code
#include <math.h>

/* Example: "Koko Eating Bananas" — find minimum eating speed k such that
   all piles can be eaten within h hours. */

/* Check: can we eat all piles at speed k within h hours? */
int feasible(int *piles, int n, int k, int h) {
    int hours = 0;
    for (int i = 0; i < n; i++) {
        hours += (piles[i] + k - 1) / k;  /* ceil(piles[i] / k) without floats */
    }
    return hours <= h;                     /* feasible if we finish in time */
}

int min_eating_speed(int *piles, int n, int h) {
    int lo = 1;            /* minimum possible speed: eat 1 banana/hour */
    int hi = 0;
    for (int i = 0; i < n; i++)
        if (piles[i] > hi) hi = piles[i]; /* maximum speed: eat largest pile in 1 hour */

    int result = hi;       /* worst case: maximum speed always works */

    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (feasible(piles, n, mid, h)) {
            result = mid;   /* mid works — record it, try to go slower */
            hi = mid - 1;
        } else {
            lo = mid + 1;   /* mid too slow — need to go faster */
        }
    }
    return result;
}

Pattern 20 Kadane’s Algorithm: Maximum Subarray Sum
① Story First
You're walking a path where each tile adds or subtracts points. At each tile you ask: "Is it better to carry my running score here, or to restart from zero at this tile?" If your running score went negative, it's dead weight — drop it and start fresh. Always extend if your running total is still positive.
② The Insight
At each index, either extend the previous subarray (current + arr[i]) or start a new one at arr[i]. Whichever is larger is the best subarray ending at i. Track the global maximum across all positions.
③ Step-by-Step Logic
  1. Initialize current = arr[0], max_sum = arr[0].
  2. For each i from 1 to n−1: current = max(arr[i], current + arr[i]).
  3. This means: if current + arr[i] < arr[i], the running sum is negative — restart at arr[i].
  4. Update max_sum: max_sum = max(max_sum, current).

⑤ Annotated Code
/* Return the maximum sum of any contiguous subarray.
   Works with negative numbers too. */

    int current = arr[0];   /* best sum of subarray ENDING at current index */
    int max_sum = arr[0];   /* global best seen so far */

    for (int i = 1; i < n; i++) {
        /* choice: extend current subarray, or start fresh at arr[i] */
        if (current + arr[i] > arr[i]) {
            current = current + arr[i];  /* extending is better: running sum was positive */
        } else {
            current = arr[i];            /* restart: running sum was negative, drag it off */
        }

        if (current > max_sum)
            max_sum = current;   /* update global best */
    }
    return max_sum;
}

Pattern 21 Kadane’s Variant: Maximum Product Subarray
① Story First
Just like Kadane's for sums, but products have a twist: a large negative number multiplied by another negative number becomes a large positive. So you cannot just track one running value — a very negative running product could become the best product in one multiplication. Track both the running maximum AND the running minimum at every step.
② The Insight
At each index, the new max could come from: (1) arr[i] alone, (2) prev_max × arr[i], or (3) prev_min × arr[i] (if arr[i] is negative, the minimum flips to become maximum). Always track both max and min.
⑤ Annotated Code
/* Maximum product of any contiguous subarray. */
int max_product(int *arr, int n) {
    int cur_max = arr[0];   /* max product of subarray ending here */
    int cur_min = arr[0];   /* min product of subarray ending here (could flip!) */
    int result  = arr[0];

    for (int i = 1; i < n; i++) {
        /* when we multiply by arr[i], max and min might swap if arr[i] is negative */
        int tmp = cur_max;

        /* new max is one of: arr[i] alone, extend max, or extend min (if arr[i]<0) */
        cur_max = arr[i];
        if (tmp     * arr[i] > cur_max) cur_max = tmp     * arr[i];
        if (cur_min * arr[i] > cur_max) cur_max = cur_min * arr[i];

        /* new min similarly */
        cur_min = arr[i];
        if (tmp     * arr[i] < cur_min) cur_min = tmp     * arr[i];
        if (cur_min * arr[i] < cur_min) cur_min = cur_min * arr[i]; /* recalc with new tmp */

        /* simpler: recalculate from saved tmp */
        int a = tmp * arr[i], b = cur_min; /* cur_min was just set to arr[i] above */
        cur_min = arr[i];
        if (a < cur_min) cur_min = a;
        if (tmp * arr[i] < cur_min) cur_min = tmp * arr[i]; /* already have a=tmp*arr[i] */

        if (cur_max > result) result = cur_max;
    }
    return result;
}

/* Cleaner version using a temp swap trick: */
int max_product_clean(int *arr, int n) {
    int hi = arr[0], lo = arr[0], ans = arr[0];
    for (int i = 1; i < n; i++) {
        int candidates[3] = {arr[i], hi * arr[i], lo * arr[i]};
        hi = candidates[0];
        if (candidates[1] > hi) hi = candidates[1];
        if (candidates[2] > hi) hi = candidates[2];
        lo = candidates[0];
        if (candidates[1] < lo) lo = candidates[1];
        if (candidates[2] < lo) lo = candidates[2];
        if (hi > ans) ans = hi;
    }
    return ans;
}

Pattern 22 Kadane’s Variant: Circular Maximum Subarray
① Story First
The array wraps around like a circular track. The maximum subarray can either stay within the linear array, or it can wrap around from the end to the beginning. Wrapping-around means: total sum minus the minimum subarray in the middle. So the answer is the larger of: (1) normal Kadane's max, (2) total − min_subarray.
② The Insight
A wrapping subarray = total_sum − (the minimum subarray in the non-wrapping part). Run Kadane's for max and also for min (by negating the array). Edge case: if all elements are negative, the circular answer would be 0 (empty), which is invalid — in that case return the normal max.
⑤ Annotated Code
/* Maximum sum subarray in a circular array. */
int max_circular(int *arr, int n) {
    int total   = 0;
    int cur_max = arr[0], max_sum = arr[0];
    int cur_min = arr[0], min_sum = arr[0];

    for (int i = 0; i < n; i++) {
        total += arr[i];               /* sum of entire array */

        /* Kadane's for maximum */
        cur_max = cur_max + arr[i] > arr[i] ? cur_max + arr[i] : arr[i];
        if (cur_max > max_sum) max_sum = cur_max;

        /* Kadane's for minimum (to find the middle chunk to remove) */
        cur_min = cur_min + arr[i] < arr[i] ? cur_min + arr[i] : arr[i];
        if (cur_min < min_sum) min_sum = cur_min;
    }

    /* if all elements are negative, max_sum < 0 and total - min_sum = 0 (invalid) */
    if (max_sum < 0) return max_sum;  /* all negative: best is the least negative */

    int circular = total - min_sum;   /* wrapping subarray = total minus the minimum chunk */
    return max_sum > circular ? max_sum : circular;
}

Pattern 23 In-Place: Cyclic Sort (1-to-N Values)
① Story First
You have numbered chairs 1 through N and students sitting in the wrong seats. You want each student in their correct chair without using extra space. Walk down the row: if the student in chair i is not student i, swap them into their correct chair. Keep swapping until chair i has the right student, then advance.
② The Insight
Value v (1-indexed) belongs at index v−1. If arr[i] != i+1, swap arr[i] with arr[arr[i]-1]. After sorting, any index where arr[i] != i+1 reveals a missing or duplicate number. Total swaps = O(n) because each swap places at least one element in its correct position.
③ Step-by-Step Logic
  1. Walk index i from 0 to n−1.
  2. While arr[i] is not in its correct position (arr[i] != i+1): swap arr[i] with arr[arr[i]-1].
  3. Only advance i when arr[i] == i+1 (the position is correct).
  4. After the loop, scan again: any i where arr[i] != i+1 means value i+1 is missing.

/* Cyclic sort: place each value v at index v-1 (values are 1..n). */
void cyclic_sort(int *arr, int n) {
    int i = 0;
    while (i < n) {
        int correct = arr[i] - 1;         /* where arr[i] should live (0-indexed) */
        if (arr[i] != arr[correct]) {      /* arr[i] is not in its correct place */
            int tmp      = arr[i];
            arr[i]       = arr[correct];
            arr[correct] = tmp;            /* swap arr[i] into its correct position */
            /* do NOT advance i: the swapped-in value might also be wrong */
        } else {
            i++;   /* arr[i] is correct (or we have a duplicate), move forward */
        }
    }
}

/* After cyclic_sort, find the first missing positive. */
int first_missing_positive(int *arr, int n) {
    cyclic_sort(arr, n);
    for (int i = 0; i < n; i++)
        if (arr[i] != i + 1) return i + 1;   /* value i+1 is missing */
    return n + 1;                              /* all 1..n present, missing is n+1 */
}

Pattern 24 In-Place: Dutch National Flag (3-Way Partition)
① Story First
Sort an array of red, white, and blue balls (values 0, 1, 2) in a single pass. Use three regions: "definitely 0s" (left of low), "unknowns" (between low and high), "definitely 2s" (right of high). A mid pointer walks through the unknowns and sorts each element into the correct region.
② The Insight
Three pointers: low (next 0 slot), mid (current element), high (next 2 slot from the right). When mid hits a 0, swap with low (both advance). When mid hits a 2, swap with high (only high shrinks, mid stays to check the swapped-in element). When mid hits a 1, just advance mid.
⑤ Annotated Code
/* Sort array containing only 0, 1, 2 in one pass. */
void dutch_flag(int *arr, int n) {
    int low  = 0;       /* everything before low is 0 */
    int mid  = 0;       /* current element being examined */
    int high = n - 1;   /* everything after high is 2 */

    while (mid <= high) {
        if (arr[mid] == 0) {
            /* 0 belongs at the low end: swap it there */
            int tmp = arr[low]; arr[low] = arr[mid]; arr[mid] = tmp;
            low++;   /* low region grows */
            mid++;   /* the swapped-in element from low was already checked (it was 1 or 0 we processed), safe to advance */
        } else if (arr[mid] == 2) {
            /* 2 belongs at the high end: swap it there */
            int tmp = arr[high]; arr[high] = arr[mid]; arr[mid] = tmp;
            high--;  /* high region grows from the right */
            /* do NOT advance mid: the swapped-in element (from high) is unknown */
        } else {
            mid++;   /* arr[mid] == 1: it is in the right place, just advance */
        }
    }
}

Pattern 25 In-Place: Rotate Array Right by K
① Story First
Rotating right by K means the last K elements jump to the front. [1,2,3,4,5] rotated by 2 becomes [4,5,1,2,3]. The trick: reverse the whole array, then reverse the first K elements, then reverse the rest. Three reversals, no extra space.
② The Insight
Reverse all → reverse [0..k-1] → reverse [k..n-1]. This is the "three reversal" trick. Works because reversing twice in different scopes cancels out except for the rotation effect.
⑤ Annotated Code
void reverse_range(int *arr, int lo, int hi) {
    while (lo < hi) {
        int tmp = arr[lo]; arr[lo] = arr[hi]; arr[hi] = tmp;
        lo++; hi--;
    }
}

/* Rotate array right by k positions in-place, O(n) time O(1) space. */
void rotate_right(int *arr, int n, int k) {
    k = k % n;              /* if k >= n, a full rotation brings us back to start */
    if (k == 0) return;

    reverse_range(arr, 0, n - 1);   /* step 1: reverse entire array */
    reverse_range(arr, 0, k - 1);   /* step 2: reverse the first k elements */
    reverse_range(arr, k, n - 1);   /* step 3: reverse the remaining n-k elements */
}

Pattern 26 In-Place: Reverse Segments
① Story First
Many in-place rearrangement problems (reverse words in a string, rotate an array, palindrome check) reduce to reversing a segment of an array or string. The two-pointer swap walks inward from both ends of the segment, swapping elements until the pointers meet.
② The Insight
Reversing a segment [lo..hi] is the atomic building block of dozens of in-place algorithms. O(hi−lo+1) time, O(1) space. No temporary array needed — swap in place.
⑤ Annotated Code
/* Reverse arr[lo..hi] in place. */
void reverse(int *arr, int lo, int hi) {
    while (lo < hi) {
        int tmp  = arr[lo];
        arr[lo]  = arr[hi];
        arr[hi]  = tmp;
        lo++;               /* move left pointer right */
        hi--;               /* move right pointer left */
    }
}

/* Reverse words in a null-terminated string (words separated by spaces).
   Two-pass: reverse whole string, then reverse each word. */
void reverse_words(char *s, int n) {
    reverse((int*)s, 0, n - 1);   /* conceptually; real code uses char swap */
    int start = 0;
    for (int i = 0; i <= n; i++) {
        if (s[i] == ' ' || s[i] == '\0') {
            /* reverse the word from start to i-1 */
            int lo = start, hi = i - 1;
            while (lo < hi) {
                char tmp = s[lo]; s[lo] = s[hi]; s[hi] = tmp;
                lo++; hi--;
            }
            start = i + 1;
        }
    }
}

Pattern 27 Sorting: Custom Comparator with qsort
① Story First
C's standard qsort takes a comparator function that defines the ordering rule. The comparator receives two void pointers (pointing to elements) and must return negative, zero, or positive to indicate which element is "less." Getting the casting right and understanding the return value convention is the key skill.
② The Insight
The comparator contract: return <0 if a should come first, 0 if equal, >0 if b should come first. Cast void* to the correct pointer type, dereference, and compare.
⑤ Annotated Code
#include <stdlib.h>

/* Sort integers ascending. */
int cmp_asc(const void *a, const void *b) {
    /* cast void* to int*, dereference to get the actual integers */
    int x = *(const int*)a;
    int y = *(const int*)b;
    /* return negative if x < y (x comes first), positive if x > y */
    if (x < y) return -1;
    if (x > y) return  1;
    return 0;
    /* WARNING: do NOT use (x - y) — it overflows if x is INT_MAX and y is negative */
}

/* Sort strings by length (shortest first). */
int cmp_by_length(const void *a, const void *b) {
    const char *sa = *(const char**)a;   /* a points to a char*, dereference to get string */
    const char *sb = *(const char**)b;
    int la = 0, lb = 0;
    while (sa[la]) la++;   /* manual strlen to avoid include */
    while (sb[lb]) lb++;
    return la - lb;         /* safe: lengths are non-negative, no overflow risk */
}

    const Point *pb = (const Point*)b;
    if (pa->x != pb->x) return pa->x - pb->x;   /* primary: sort by x */
    return pa->y - pb->y;                          /* tiebreak: sort by y */
}

    qsort(arr, 5, sizeof(int), cmp_asc);
    /* arr is now [1, 2, 5, 8, 9] */
    return 0;
}

Pattern 28 Sorting: Merge Overlapping Intervals
① Story First
You have a list of time slots on a calendar: [1,3], [2,6], [8,10], [15,18]. Slots [1,3] and [2,6] overlap, so they can be merged into [1,6]. Sort by start time first, then walk through: if the current interval overlaps the last merged one, extend it. Otherwise start a new one.
② The Insight
After sorting by start time, two consecutive intervals [a,b] and [c,d] overlap if and only if c ≤ b. Merge them into [a, max(b,d)]. No need to look further back because sorting guarantees all previous intervals are already non-overlapping.
⑤ Annotated Code
#include <stdlib.h>

typedef struct { int start, end; } Interval;

int cmp_interval(const void *a, const void *b) {
    return ((Interval*)a)->start - ((Interval*)b)->start; /* sort by start time */
}

/* Merge overlapping intervals. Returns number of merged intervals.
   result must be pre-allocated to size n. */
int merge_intervals(Interval *ivs, int n, Interval *result) {
    if (n == 0) return 0;

    qsort(ivs, n, sizeof(Interval), cmp_interval);   /* sort by start time */

    int k = 0;                /* count of merged intervals in result */
    result[0] = ivs[0];       /* first interval is always in the result */

    for (int i = 1; i < n; i++) {
        /* does ivs[i] overlap the last merged interval? */
        if (ivs[i].start <= result[k].end) {
            /* yes: extend the end of the last merged interval if needed */
            if (ivs[i].end > result[k].end)
                result[k].end = ivs[i].end;
        } else {
            /* no overlap: start a new interval in the result */
            k++;
            result[k] = ivs[i];
        }
    }
    return k + 1;   /* k is 0-indexed, total count is k+1 */
}

If a large interval completely contains the next one ([1,10] followed by [2,3]), ivs[i].end = 3 is smaller than result[k].end = 10. Writing just result[k].end = ivs[i].end would shrink the merged interval incorrectly. Always use max: only update end if the new interval extends further right.

Pattern 30 Greedy: Jump Game (Can You Reach the End?)
① Story First
You're jumping across platforms. Each platform shows the maximum number of steps you can jump from there. You don't need to plan ahead perfectly. Just keep track of "how far can I reach from everything I've visited so far?" If at any point you're standing on a platform you can't jump from (your max reach is behind you), you're stuck.
② The Insight
Track max_reach: the farthest index reachable from any visited position. For each index i, if i > max_reach, it's unreachable. Otherwise update max_reach = max(max_reach, i + arr[i]).
⑤ Annotated Code
/* Can you reach the last index? Returns 1 (yes) or 0 (no). */
int can_jump(int *arr, int n) {
    int max_reach = 0;   /* farthest index reachable from any position visited so far */

    for (int i = 0; i < n; i++) {
        if (i > max_reach)           /* current position is beyond what we can reach */
            return 0;                /* stuck — can't get here */

        int reach = i + arr[i];      /* farthest we can reach FROM position i */
        if (reach > max_reach)
            max_reach = reach;       /* update the global furthest reach */

        if (max_reach >= n - 1)     /* we can already reach the last index */
            return 1;
    }
    return 1;   /* reached end of loop without getting stuck */
}

Pattern 31 Greedy: Jump Game II (Minimum Jumps to Reach End)
① Story First
Same jumping platforms, but now you want the fewest jumps to reach the end. Think of it as BFS in disguise: each "jump" covers a range of reachable positions. From your current range, find the farthest you can reach in one more jump. When you exhaust your current range, you must take another jump.
② The Insight
Maintain a "current window" [current_start..current_end]. Walk through this window tracking the farthest next-jump reach. When you reach current_end, increment jump count and set the new window to [current_end+1..farthest_reach].
⑤ Annotated Code
/* Minimum number of jumps to reach the last index. Guaranteed reachable. */
int jump_min(int *arr, int n) {
    int jumps        = 0;   /* total jumps taken */
    int current_end  = 0;   /* farthest index reachable with 'jumps' jumps */
    int farthest     = 0;   /* farthest index reachable with 'jumps+1' jumps */

    for (int i = 0; i < n - 1; i++) {   /* don't need to jump FROM the last index */
        int reach = i + arr[i];
        if (reach > farthest) farthest = reach;   /* update best next jump */

        if (i == current_end) {     /* exhausted current jump range */
            jumps++;                /* must take another jump */
            current_end = farthest; /* new range is everything reachable in one more jump */
        }
    }
    return jumps;
}

The loop should run i < n - 1. If you loop to i < n, when i reaches the last index (n-1) and i == current_end, you increment jumps unnecessarily. You don't need to jump FROM the last index.

① Story First

② The Insight

⑤ Annotated Code
/* Find the starting gas station index for a complete circuit, or -1. */
int can_complete_circuit(int *gas, int *cost, int n) {
    int total_surplus = 0;   /* net gas over entire circuit (feasibility check) */
    int tank          = 0;   /* running gas in tank from current start candidate */
    int start         = 0;   /* current candidate starting station */

            tank  = 0;       /* reset the tank for the new start candidate */
        }
    }

}

Pattern 34 Matrix: Spiral Order Traversal
① Story First
Traverse a matrix like unwrapping the layers of an onion, starting from the outside and spiraling inward. Maintain four boundaries: top, bottom, left, right. Traverse the top row left-to-right, right column top-to-bottom, bottom row right-to-left, left column bottom-to-top. Then shrink each boundary inward and repeat.
② The Insight
Four boundary variables (top, bottom, left, right). After each edge traversal, shrink that boundary inward. Stop when top > bottom or left > right.
⑤ Annotated Code
/* Traverse matrix in spiral order. result must be pre-allocated to rows*cols. */
void spiral_order(int matrix[][100], int rows, int cols, int *result) {
    int top = 0, bottom = rows - 1;
    int left = 0, right  = cols - 1;
    int k = 0;   /* index into result array */

    while (top <= bottom && left <= right) {
        /* traverse top row: left to right */
        for (int c = left; c <= right; c++)   result[k++] = matrix[top][c];
        top++;    /* top row consumed, shrink top boundary down */

        /* traverse right column: top to bottom */
        for (int r = top; r <= bottom; r++)   result[k++] = matrix[r][right];
        right--;  /* right column consumed, shrink right boundary left */

        /* traverse bottom row: right to left (only if a row remains) */
        if (top <= bottom) {
            for (int c = right; c >= left; c--) result[k++] = matrix[bottom][c];
            bottom--;
        }

        /* traverse left column: bottom to top (only if a column remains) */
        if (left <= right) {
            for (int r = bottom; r >= top; r--) result[k++] = matrix[r][left];
            left++;
        }
    }
}

Pattern 35 Matrix: Set Row and Column to Zero
① Story First
If any cell in a matrix is zero, set its entire row and column to zero. The naive approach reads a cell, sees zero, sets the row/column, but now new zeros might be seen in later passes — wrong! ⑤ Annotated Code
/* Set entire row and column to 0 for every cell that contains 0.
   O(m*n) time, O(m+n) space for the flag arrays. */
void set_zeros(int matrix[][100], int rows, int cols) {

    int zero_cols[100] = {0};   /* zero_cols[j]=1 means col j should be zeroed */

    /* pass 1: find which rows and columns contain zeros */
    for (int r = 0; r < rows; r++)
        for (int c = 0; c < cols; c++)
            if (matrix[r][c] == 0) {
                zero_rows[r] = 1;   /* mark this row */
                zero_cols[c] = 1;   /* mark this column */

            for (int r = 0; r < rows; r++) matrix[r][c] = 0;
}

Pattern 36 Matrix: Rotate 90 Degrees In-Place
① Story First
Rotate an n×n matrix 90 degrees clockwise. No extra matrix allowed. The trick is a two-step process: first transpose the matrix (flip along the diagonal), then reverse each row. These two operations together produce a 90-degree clockwise rotation.
② The Insight
Clockwise 90° = transpose + reverse each row. Counter-clockwise 90° = transpose + reverse each column. Memorize this: it appears constantly in interview problems.
⑤ Annotated Code
/* Rotate n x n matrix 90 degrees clockwise in-place. */
void rotate_90(int m[][100], int n) {
    /* Step 1: Transpose — swap m[i][j] with m[j][i] */
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {   /* j starts at i+1 to avoid double-swapping */
            int tmp = m[i][j];
            m[i][j] = m[j][i];
            m[j][i] = tmp;
        }
    }

    /* Step 2: Reverse each row */
    for (int i = 0; i < n; i++) {
        int lo = 0, hi = n - 1;
        while (lo < hi) {
            int tmp = m[i][lo]; m[i][lo] = m[i][hi]; m[i][hi] = tmp;
            lo++; hi--;
        }
    }
}

Pattern 37 Matrix: Word Search (DFS on Grid)
① Story First
Search a grid for a word that can be spelled by moving to adjacent (up/down/left/right) cells, without revisiting a cell. Try each cell as a starting point. From there, do a depth-first search: mark the current cell as visited, recurse into neighbors matching the next letter, then unmark (backtrack) when done.
② The Insight
DFS + backtracking on a grid. Mark a cell visited by temporarily changing its value (e.g., to '#'), recurse, then restore it. This avoids needing a separate visited array.
⑤ Annotated Code
/* DFS helper: returns 1 if word[idx..] can be spelled starting at (r,c). */
int dfs(char board[][8], int rows, int cols, char *word, int idx, int r, int c) {
    if (word[idx] == '\0') return 1;   /* all characters matched — word found */
    if (r < 0 || r >= rows || c < 0 || c >= cols) return 0;  /* out of bounds */
    if (board[r][c] != word[idx]) return 0;    /* current cell doesn't match */

    char saved = board[r][c];
    board[r][c] = '#';    /* mark as visited: prevents revisiting this cell */

    /* try all 4 directions for the next character */
    int found = dfs(board, rows, cols, word, idx+1, r-1, c) ||
                dfs(board, rows, cols, word, idx+1, r+1, c) ||
                dfs(board, rows, cols, word, idx+1, r, c-1) ||
                dfs(board, rows, cols, word, idx+1, r, c+1);

    board[r][c] = saved;  /* backtrack: restore cell so other paths can use it */
    return found;
}

int word_search(char board[][8], int rows, int cols, char *word) {
    for (int r = 0; r < rows; r++)
        for (int c = 0; c < cols; c++)
            if (dfs(board, rows, cols, word, 0, r, c)) return 1;
    return 0;
}

⚠ Gotcha: Forgetting to restore the cell after backtracking

If you mark a cell visited but never restore it, a successful path in one branch will block other branches from using that cell. The restore step (board[r][c] = saved) after the recursive calls is mandatory. Without it, the first path explored "eats up" cells permanently.

Pattern 38 Hashmap: Two Sum (Single Pass)
① Story First
Find two numbers in an array that sum to a target. The brute force tries every pair (O(n²)). The hashmap trick: as you visit each number, check if its complement (target − current) was already seen. If yes, you found the pair. If no, store the current number in the map for future lookups. One pass through the array, O(1) lookup per step.
② The Insight
For every element x, its required partner is (target - x). Store each element in a hash map as you go. Before storing, check if (target - x) is already in the map. If yes — instant O(1) answer.
⑤ Annotated Code
/* Two Sum using a simple open-addressing hash map (for values 0..9999). */
#define MAP_SIZE 10007

typedef struct { int key; int val; int used; } Entry;
Entry map[MAP_SIZE];

void map_clear(void) { for (int i = 0; i < MAP_SIZE; i++) map[i].used = 0; }

/* Store key→value. Simple linear probing. */

    int h = ((unsigned)key) % MAP_SIZE;

}

Pattern 39 Hashmap: Subarray Sum Equals K (Prefix + HashMap)
① Story First
Count subarrays whose elements sum to exactly K. Two pointers won't work here because the array can have negative numbers. Instead, build running prefix sums. For each prefix sum P at index i, you need to know: how many earlier prefix sums equaled P−K? Because if prefix[j] = P−K, then sum(j+1..i) = K. Store prefix sum frequencies in a hashmap.
② The Insight
sum(j+1..i) = prefix[i] − prefix[j]. If this equals K, then prefix[j] = prefix[i] − K. Count how many times (prefix[i] − K) appeared as a prefix sum so far.
⑤ Annotated Code
/* Count subarrays with sum exactly equal to k. Works with negative numbers. */
int subarray_sum_k(int *arr, int n, int k) {
    /* Simple hash map for prefix sum frequencies: key=prefix_sum, value=count */
    /* For interview, assume prefix sums fit in a reasonable range. */
    /* Here we simulate with a fixed-size map for values -10000..10000 */
    #define OFFSET 10000
    #define RANGE  20001
    int freq[RANGE] = {0};

    freq[0 + OFFSET] = 1;   /* empty prefix (sum=0) has been seen once before starting */

    int prefix = 0;   /* running prefix sum */
    int count  = 0;

    for (int i = 0; i < n; i++) {
        prefix += arr[i];           /* extend prefix sum to include arr[i] */

        /* how many earlier prefixes equal (prefix - k)? */
        /* each one of those creates a valid subarray ending at i */
        int need = prefix - k;
        if (need + OFFSET >= 0 && need + OFFSET < RANGE)
            count += freq[need + OFFSET];

        freq[prefix + OFFSET]++;    /* record this prefix sum for future lookups */
    }
    return count;
    #undef OFFSET
    #undef RANGE
}

① Story First
Find the K most common elements. Count frequencies with a hashmap, then find the K largest counts. The clever trick is bucket sort: create an array of buckets where index i holds elements that appear exactly i times. Then scan from the highest-frequency bucket down until you collect K elements.
② The Insight
Frequencies are bounded: no element can appear more than n times. So bucket-sort by frequency gives O(n) — better than a heap-based O(n log k) approach.
⑤ Annotated Code
/* Top K frequent elements using bucket sort. Values assumed 0..9999. */
void top_k_frequent(int *arr, int n, int k, int *result) {
    int freq[10000] = {0};
    for (int i = 0; i < n; i++) freq[arr[i]]++;   /* count frequency of each value */

    /* Bucket sort: bucket[i] holds values with frequency exactly i.
       Using a simple 2D approach here. */
    int buckets[n + 1][n];    /* buckets[freq][index] = value */
    int bucket_size[n + 1];
    for (int i = 0; i <= n; i++) bucket_size[i] = 0;

    for (int val = 0; val < 10000; val++) {
        if (freq[val] > 0) {
            int f = freq[val];
            buckets[f][bucket_size[f]++] = val;  /* put val in bucket f */

        for (int i = 0; i < bucket_size[f] && count < k; i++) {
            result[count++] = buckets[f][i];
        }
    }

Pattern 43 Hard Classic: Trapping Rain Water
① Story First
Water trapped at position i equals: min(tallest wall to the left, tallest wall to the right) minus height[i]. If that min is less than height[i], no water is trapped (it spills over the shorter wall). Pre-compute "left max" and "right max" arrays, then walk through for the answer. Or use two pointers for O(1) space.
② The Insight
water[i] = max(0, min(left_max[i], right_max[i]) − height[i]). The limiting factor is always the shorter side. Two-pointer approach: the side with the smaller max is the binding constraint — process it.
⑤ Annotated Code
/* Trapping rain water with two pointers. O(n) time, O(1) space. */
int trap(int *h, int n) {
    int left = 0, right = n - 1;
    int left_max = 0, right_max = 0;
    int water = 0;

    while (left < right) {
        if (h[left] < h[right]) {
            /* left wall is shorter: it's the bottleneck for water at 'left' */
            if (h[left] >= left_max) {
                left_max = h[left];   /* new taller left wall, no water here */
            } else {
                water += left_max - h[left];  /* water fills up to left_max */
            }
            left++;
        } else {
            /* right wall is shorter (or equal): it's the bottleneck for 'right' */
            if (h[right] >= right_max) {
                right_max = h[right];
            } else {
                water += right_max - h[right];
            }
            right--;
        }
    }
    return water;
}

② The Insight

/* Largest rectangle area in histogram. O(n) with monotonic stack. */
int largest_rectangle(int *heights, int n) {
    int stack[n + 1];   /* stores indices; stack[0..top-1] */

    int max_area = 0;

        int h = (i == n) ? 0 : heights[i];   /* sentinel 0 at end flushes the stack */

            if (area > max_area) max_area = area;
        }
        stack[top++] = i;   /* push current index */

Pattern 45 Hard Classic: Median of Two Sorted Arrays
① Story First
Find the median of two sorted arrays combined, in O(log(min(m,n))) time — no merging allowed. Binary search on the partition point of the smaller array. A "partition" splits both arrays so that everything on the left is ≤ everything on the right. Adjust the partition until it's balanced.
② The Insight
Binary search on the smaller array to find the right partition. Once the partition satisfies: maxLeft1 ≤ minRight2 AND maxLeft2 ≤ minRight1, you've found the median. O(log(min(m,n))).
⑤ Annotated Code
#include <limits.h>

double find_median(int *a, int m, int *b, int n) {
    if (m > n) return find_median(b, n, a, m);   /* ensure a is the smaller array */

    int lo = 0, hi = m;
    int half = (m + n + 1) / 2;   /* number of elements in the left partition */

    while (lo <= hi) {
        int pa = lo + (hi - lo) / 2;   /* partition a: pa elements from a on the left */
        int pb = half - pa;             /* partition b: the rest come from b */

        int maxLeftA  = (pa == 0) ? INT_MIN : a[pa-1];
        int minRightA = (pa == m) ? INT_MAX : a[pa];
        int maxLeftB  = (pb == 0) ? INT_MIN : b[pb-1];
        int minRightB = (pb == n) ? INT_MAX : b[pb];

        if (maxLeftA <= minRightB && maxLeftB <= minRightA) {
            /* correct partition found */
            if ((m + n) % 2 == 1)
                return (double)(maxLeftA > maxLeftB ? maxLeftA : maxLeftB);
            int left  = maxLeftA  > maxLeftB  ? maxLeftA  : maxLeftB;
            int right = minRightA < minRightB ? minRightA : minRightB;
            return (double)(left + right) / 2.0;
        } else if (maxLeftA > minRightB) {
            hi = pa - 1;   /* too many from a: move partition left */
        } else {
            lo = pa + 1;   /* too few from a: move partition right */
        }
    }
    return 0.0;
}

Pattern 46 Hard Classic: Next Permutation
① Story First
Find the next lexicographically larger permutation of an array in-place. Example: [1,2,3] → [1,3,2]. If already the largest ([3,2,1]), wrap to smallest ([1,2,3]). Walk from right to left: find the first position where the sequence "dips" (a[i] < a[i+1]). Swap it with the smallest element to its right that is larger, then reverse the suffix to the right.
② The Insight
Three steps: (1) find rightmost "dip" at index i where a[i] < a[i+1], (2) find the smallest element in a[i+1..n-1] that is greater than a[i] and swap them, (3) reverse a[i+1..n-1] to make it the smallest suffix.
⑤ Annotated Code
void next_permutation(int *a, int n) {
    /* Step 1: find rightmost dip (a[i] < a[i+1]) */
    int i = n - 2;
    while (i >= 0 && a[i] >= a[i+1]) i--;

    if (i >= 0) {
        /* Step 2: find smallest element right of i that is greater than a[i] */
        int j = n - 1;
        while (a[j] <= a[i]) j--;   /* rightmost element > a[i] */
        int tmp = a[i]; a[i] = a[j]; a[j] = tmp;   /* swap */
    }

    /* Step 3: reverse suffix a[i+1..n-1] to get smallest arrangement */
    int lo = i + 1, hi = n - 1;
    while (lo < hi) {
        int tmp = a[lo]; a[lo] = a[hi]; a[hi] = tmp;
        lo++; hi--;
    }
}

① Story First
For each element, count how many elements to its right are smaller. Brute force is O(n²). The key approach: merge sort from right to left. During the merge step, when we pick from the right sub-array over the left sub-array, all remaining left elements are larger — increment their counts.
② The Insight

typedef struct { int val, idx; } Pair;
Pair tmp_buf[10000]; /* merge sort buffer */

void merge_count(Pair *arr, int lo, int hi) {
    if (hi - lo <= 1) return;
    int mid = lo + (hi - lo) / 2;
    merge_count(arr, lo, mid);
    merge_count(arr, mid, hi);

    int i = lo, j = mid, k = lo, right_count = 0;
    while (i < mid && j < hi) {
        if (arr[i].val > arr[j].val) {
            right_count++;        /* arr[j] (from right) is smaller than arr[i] (from left) */
            tmp_buf[k++] = arr[j++];

Pattern 49 Monotonic Stack: Next Greater Element
① Story First
For each element, find the first element to its right that is larger. A naive approach checks every element to the right: O(n²). The stack approach: maintain a stack of elements waiting to find their "next greater." When a new element arrives and it's larger than the stack top, the stack top has found its answer.
② The Insight
Maintain a monotonically decreasing stack of indices. When arr[i] > arr[stack.top()], pop the top and record arr[i] as its next greater element. Push i onto the stack. Elements never popped have no next greater (answer = -1).
⑤ Annotated Code
/* For each element, find the first element to its right that is strictly greater.
   result[i] = -1 if no such element exists. */
void next_greater(int *arr, int n, int *result) {
    int stack[n];   /* stores indices, not values */
    int top = 0;

    for (int i = 0; i < n; i++) result[i] = -1;  /* default: no next greater */

    for (int i = 0; i < n; i++) {
        /* while the stack has elements AND arr[i] is greater than the top element */
        while (top > 0 && arr[stack[top-1]] < arr[i]) {
            result[stack[--top]] = arr[i];  /* arr[i] is the next greater for the popped index */
        }
        stack[top++] = i;   /* push current index: still looking for its next greater */
    }
    /* indices remaining in stack have no next greater — they stay -1 */
}

arr = [4, 1, 2, 3] i=0: stack empty → push 0 stack=[0(4)] i=1: 1 < 4 → no pop, push 1 stack=[0(4),1(1)] i=2: 2 > 1 → pop 1: result[1]=2; 2 < 4 → push 2 stack=[0(4),2(2)] i=3: 3 > 2 → pop 2: result[2]=3; 3 < 4 → push 3 stack=[0(4),3(3)] remaining: indices 0,3 → result[0]=-1, result[3]=-1 result = [-1, 2, 3, -1] ✓
⚠ Gotcha: Storing values instead of indices in the stack

If you store values in the stack, you can compute arr[i] > stack_top correctly, but you lose the ability to write to result[j] for the popped element's original index. Always store indices in the stack and use arr[index] when comparing.

Pattern 50 Monotonic Stack: Daily Temperatures
① Story First
For each day, how many days must you wait until a warmer temperature? Same pattern as Next Greater Element, but instead of recording the value, record the distance (i − popped_index).
② The Insight
Exact same monotonic decreasing stack. When you pop an index j because arr[i] > arr[j], the answer for j is i − j (the number of days waited). The only change from Next Greater Element is storing the gap instead of the value.
⑤ Annotated Code
/* How many days until a warmer temperature? result[i]=0 if no warmer day exists. */

        }
        stack[top++] = i;
    }
}

Pattern 51 Bit Manipulation: Single Number (XOR Trick)
① Story First
Every number in an array appears twice except one. Find the unique number without extra space. XOR (exclusive or) has a magic property: X ^ X = 0 (any number XORed with itself is 0), and X ^ 0 = X. XOR all numbers together. Pairs cancel out to 0, and the lone number remains.
② The Insight
XOR is commutative and associative. All duplicate pairs cancel: (a^a) = 0. The single element paired with all the zeros equals itself. One pass, no extra space.
⑤ Annotated Code
/* Find the element that appears exactly once (all others appear twice). */
int single_number(int *arr, int n) {
    int result = 0;
    for (int i = 0; i < n; i++)
        result ^= arr[i];   /* XOR accumulates: pairs cancel, single survives */
    return result;
}

/* Extended: find two numbers that appear once (all others appear twice).
   XOR all → get a^b. Find any set bit → split array into two groups. */
void single_number_III(int *arr, int n, int *x, int *y) {
    int xor_all = 0;
    for (int i = 0; i < n; i++) xor_all ^= arr[i];  /* xor_all = x ^ y */

    /* find the rightmost set bit (a bit where x and y differ) */
    int diff_bit = xor_all & (-xor_all);

    *x = 0; *y = 0;
    for (int i = 0; i < n; i++) {
        if (arr[i] & diff_bit)
            *x ^= arr[i];   /* group 1: elements with this bit set */
        else
            *y ^= arr[i];   /* group 2: elements with this bit clear */
    }
}
⑥ Dry Run
arr = [4, 1, 2, 1, 2] XOR: 0^4=4, 4^1=5, 5^2=7, 7^1=6, 6^2=4 result = 4 ✓ (4 appears once; 1 and 2 cancel themselves)
⚠ Gotcha: Thinking XOR only works for exactly two of each duplicate

XOR cancels any number of pairs: if a number appears 2, 4, 6... (even) times it cancels. If it appears an odd number of times it survives. The basic single-number problem requires all duplicates to appear exactly twice. If duplicates appear 3 times, XOR doesn't work — you'd need a different approach (counting bits modulo 3).

Pattern 52 Bit Manipulation: Missing Number
① Story First
Given n distinct numbers from 0 to n, find the one that's missing. Two approaches: (1) expected sum minus actual sum = missing number. (2) XOR all indices 0..n and all elements — the missing index will not have a matching element to cancel it.
② The Insight
Sum approach: expected = n*(n+1)/2, actual = sum of array. Difference is the missing number. XOR approach: XOR(0..n) ^ XOR(all elements) = missing number (same cancellation trick as Single Number).
⑤ Annotated Code
/* Find missing number in array containing n distinct values from [0, n]. */
int missing_number(int *arr, int n) {
    /* Math approach: sum of 0..n minus sum of array */
    int expected = n * (n + 1) / 2;   /* Gauss formula: sum of 0+1+2+...+n */
    int actual   = 0;
    for (int i = 0; i < n; i++) actual += arr[i];
    return expected - actual;

    /* XOR approach (avoids potential overflow for large n):
    int result = n;   // start by XORing with n itself
    for (int i = 0; i < n; i++)
        result ^= i ^ arr[i];   // XOR index i and element i
    return result;
    */
}
⑥ Dry Run
arr = [3, 0, 1], n=3 expected = 3*4/2 = 6 actual = 3+0+1 = 4 return 6-4 = 2 ✓
⚠ Gotcha: Integer overflow for large n with the sum approach

n*(n+1)/2 overflows a 32-bit int when n is around 65536. Use long long for large inputs, or use the XOR approach which never overflows (XOR works bit by bit, no addition).

Pattern 53 Divide & Conquer: Count Inversions (Merge Sort)
① Story First
An inversion is a pair (i,j) where i < j but arr[i] > arr[j] — out of order. Count them all in O(n log n) using merge sort. During the merge step, whenever we pick from the right half, all remaining left-half elements are larger than it — they ALL form inversions with this right element.
② The Insight
During merge of two sorted halves [L] and [R]: when we pick R[j] because L[i] > R[j], all of L[i..end] are also > R[j] (L is sorted). So we add (mid - i) inversions at once — an O(1) count per element.
⑤ Annotated Code
long long merge_count_inv(int *arr, int *tmp, int lo, int hi) {
    if (hi - lo <= 1) return 0;   /* single element: no inversions */
    int mid = lo + (hi - lo) / 2;

    long long count = merge_count_inv(arr, tmp, lo,  mid)
                    + merge_count_inv(arr, tmp, mid, hi);

    int i = lo, j = mid, k = lo;
    while (i < mid && j < hi) {
        if (arr[i] <= arr[j]) {
            tmp[k++] = arr[i++];   /* left element is smaller: no inversion */
        } else {
            /* arr[j] < arr[i], and all of arr[i..mid-1] > arr[j] (left is sorted) */
            count  += (mid - i);   /* all remaining left elements form inversions with arr[j] */
            tmp[k++] = arr[j++];
        }
    }
    while (i < mid) tmp[k++] = arr[i++];
    while (j < hi)  tmp[k++] = arr[j++];
    for (int x = lo; x < hi; x++) arr[x] = tmp[x];

    return count;
}

long long count_inversions(int *arr, int n) {
    int tmp[n];
    return merge_count_inv(arr, tmp, 0, n);
}

Pattern 54 Difference Array: Range Update in O(1)
① Story First
You need to add a value to every element in a range [l, r] — repeatedly, many times. Doing it naively updates O(r−l+1) elements each time. The difference array trick: only mark the start and end of each range update. Then reconstruct the actual values with a prefix sum at query time.
② The Insight
Store diff[l] += val and diff[r+1] -= val. Each range update is O(1). After all updates, the actual array is the prefix sum of diff[]. Then queries are O(n) but amortized over many updates.
⑤ Annotated Code
/* Difference array for multiple range updates.
   After all updates, call build() to get the final array values. */
int diff[10001] = {0};

/* Range update: add val to every element in arr[l..r] */
void range_update(int l, int r, int val) {
    diff[l]     += val;    /* range starts here: begin adding val */
    diff[r + 1] -= val;    /* range ends here: stop adding val */
}

/* Reconstruct final array by prefix-summing the difference array. */
void build(int *result, int n) {
    int running = 0;
    for (int i = 0; i < n; i++) {
        running   += diff[i];   /* running sum accumulates all active range additions */
        result[i]  = running;
    }
}

/* Example: corporate flight bookings — seats booked per flight segment */
int max_seats(int bookings[][3], int nb, int n) {
    for (int i = 0; i <= n + 1; i++) diff[i] = 0;
    for (int i = 0; i < nb; i++)
        range_update(bookings[i][0], bookings[i][1], bookings[i][2]);
    int result[n], max_val = 0;
    build(result, n);
    for (int i = 0; i < n; i++) if (result[i] > max_val) max_val = result[i];
    return max_val;
}

The subtraction must go at index r+1, not r. You want val to be added for all positions l through r (inclusive). If you subtract at r, position r itself won't get val. The diff array requires diff[r+1] -= val so the prefix sum includes r but not r+1.
