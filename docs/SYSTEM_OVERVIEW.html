Section 01

The Big Picture — Cell to Cloud

Strip away all the complexity and a BMS does exactly one thing repeatedly, forever: measure → think → act. Everything else — CAN frames, Kalman filters, FET drivers — is just detail inside those three words. Here is the full pipeline from raw electrons to a cloud dashboard in nine stages.

The one thing to remember: The BMS never "knows" the battery state perfectly. It estimates it — using voltage, current, temperature, and a mathematical model. Every design decision in chapters 1–10 is about making that estimate more accurate, more reliable, and faster to react.
MEASURE (Stages 1–3)
Cells generate voltage. Sensors capture it. AFE digitises every cell every millisecond with ±1mV accuracy. This raw data is the foundation of everything.
THINK (Stages 4–5)
Filter removes noise. Kalman filter fuses coulomb counting + voltage model → SoC ±2%. DCIR trend → SoH. This is the intelligence layer.
ACT (Stages 6–9)
Protection state machine decides. FETs execute in <500µs. CAN tells the inverter. NVM logs every event. Cloud visualises. System reacts.
Section 02

Real Operation Flow — What Happens From Power-ON

This is not theory. This is what the MCU firmware actually runs, step by step, the moment you connect power. The BMS is a state machine with a deterministic boot sequence. If you understand this sequence, you understand the entire embedded system.

Why pre-charge? The inverter/load has large input capacitors (100–1000µF). Without pre-charge, closing the DSG FET directly creates a current spike of I = C × dV/dt — easily hundreds of amps for microseconds. This welds the FET contacts or destroys the gate driver. The 10Ω pre-charge resistor limits inrush to safe levels during cap charging.
Section 03

Signal Flow — Data Moving Through the System

Three real examples. Each one shows a single physical event — an overvoltage, a temperature spike, a low SoC — and traces exactly how that event propagates from the cell through every layer of hardware and firmware until it reaches an output. This is the muscle memory of BMS debugging.

EXAMPLE A — OVERVOLTAGE EVENT

Total time from Vcell hitting threshold to charging physically stopping: <1ms (SW) + <500µs (HW) = under 1.5ms. The cell never sees more than +10mV above limit.

EXAMPLE B — OVERTEMPERATURE (OTP)

Key insight: the 5°C hysteresis band prevents the FET from cycling on/off rapidly near the threshold. The 30-second clear timer (30 ticks × 1 tick/s) prevents re-entry unless temperature is genuinely stable.

EXAMPLE C — LOW SoC WARNING → DEEP DISCHARGE PROTECTION

For a UPS, the inverter must be told before the BMS trips the DSG FET — otherwise loads drop for the milliseconds it takes to switch to mains. CAN warning at 25% SoC gives the inverter ~10 minutes to initiate a graceful grid transfer. See Ch 7 for the full UPS protocol.

Section 05

The Embedded View — How Firmware Actually Runs This

If you're writing BMS firmware, everything so far is "what". This section is "how" — the scheduler, the task structure, the input-output loop. This is what the MCU is actually doing, tick by tick.

Task Scheduler — Visual Timeline

Firmware Input → Processing → Output Loop

/* ═══════════════════════════════════════════════════════════════
   BMS MAIN LOOP — conceptual structure (runs every 10ms)
   Based on 16S1P reference design, STM32G474, MISRA-C compliant
   ═══════════════════════════════════════════════════════════════ */

/* ── INPUTS (read from hardware) ──────────────────────────────── */
void BMS_ReadInputs(BmsData_t *d) {
    AFE_ReadAllCells(d->vcell);          /* 16× voltage via I²C    */
    AFE_ReadTemperatures(d->temp);       /* 5× NTC via AFE ADC     */
    d->ibat = AFE_ReadCurrent();         /* shunt, signed A        */
    d->vbat = AFE_ReadPackVoltage();     /* sum of 16 cells        */
}

/* ── PROCESSING (think) ───────────────────────────────────────── */
void BMS_Process(BmsData_t *d) {
    Filter_IIR_All(d);                   /* α=0.1 low-pass filter  */
    d->soc = Kalman_Update(d->vcell,     /* EKF: CC + OCV fusion   */
                            d->ibat);
    d->soh = SoH_EstimateDCIR(d->soc,   /* DCIR trend → capacity  */
                               d->ibat);
}

/* ── DECISION (protection state machine) ─────────────────────── */
void BMS_Decide(BmsData_t *d) {
    d->prot_state = APP_ProtSM_Tick(d); /* 6-state machine        */
    FET_ApplyState(d->prot_state);       /* CHG/DSG FET control    */
    BAL_Tick(d->vcell);                  /* balancer if ΔV>10mV   */
}

/* ── OUTPUTS (communicate) ───────────────────────────────────── */
void BMS_Output(BmsData_t *d) {
    CAN_BuildAndSend(d);                 /* 0x351–0x359 frames     */
    UART_SendDebugLine(d);               /* human-readable log     */
    NVM_MaybePersist(d->soc, d->faults); /* write if changed >1%  */
}

/* ── MAIN SCHEDULER LOOP ────────────────────────────────────────
   Triggered by SysTick every 10ms via flag, NOT blocking delay  */
void main(void) {
    HAL_Init(); AFE_Init(); CAN_Init(); NVM_Restore(&g_bms);
    while (1U) {
        if (g_10ms_flag) {
            g_10ms_flag = 0U;
            BMS_ReadInputs(&g_bms);
            BMS_Process(&g_bms);
            BMS_Decide(&g_bms);
            BMS_Output(&g_bms);
        }
        /* ISR independently kicks IWDG every 1ms */
    }
}
Why not use RTOS tasks? For a single-core MCU doing one job reliably, a bare-metal super-loop with a 10ms SysTick gate is more predictable than FreeRTOS preemption. RTOS adds value when you have multiple independent peripherals with different timing requirements. For a BMS where everything shares the same data, a super-loop gives you deterministic worst-case timing — critical for MISRA-C certification.
Section 06

The Intuition — What Is The BMS Really Doing?

Forget the registers for a second. Here is what the BMS is doing at the highest level, in plain language. These four verbs are the soul of the system.

👁
WATCHING
Every 10ms:
— Is any cell above 3.65V?
— Is any cell below 2.8V?
— Is current above 1C?
— Is any sensor above 55°C?

The BMS never sleeps. It is always watching. 100 times per second.
🧠
PREDICTING
Every 10ms:
— What is SoC right now?
— How much energy remains?
— How healthy is this pack?
— When will this cell hit UVP?

The Kalman filter is an educated guess engine. It never knows — it estimates.
🛡
PROTECTING
When threshold crossed:
— Trip FET in <500µs
— Log with timestamp
— Notify inverter via CAN
— Apply hysteresis before reset

Protection is the BMS's immune system. It should rarely fire — but when it does, it must be instant.
⚡
CONTROLLING
Every 100ms:
— Tell inverter max charge current
— Tell inverter min cell voltage
— Balance cells if ΔV > 10mV
— Throttle load at low SoC

The BMS is not just reactive — it actively shapes how the battery is used.
The mental model in one sentence:
A BMS is a real-time measurement system wrapped around a state estimator wrapped around a protection system wrapped around a communication protocol — all running on a microcontroller that must never crash, never drift, and never miss a deadline.
Section 07

Mini Scenario — Full Charge Cycle Walkthrough

One complete event, traced across the entire system. The scenario: a home ESS pack at 30% SoC starts charging from solar. We follow the data from the first electron to the inverter's dashboard. This is what it feels like to understand the system end-to-end.

t=0s — Solar ramp begins. Ibat goes positive.

Solar inverter starts pushing current into pack. Ibat = +12A detected by shunt. CC2 coulomb counter begins integrating. Kalman filter receives new I measurement. Ch4 — Shunt sensing Ch5 — Kalman update

t=10ms — First AFE read. Vcell[0..15] = 3.28–3.30V. SoC = 30.2%

All 16 cells sampled via I²C. IIR filter applied. OCV model cross-checked against CC estimate. Kalman blend: SoC_kalman = 30.2%. No threshold breach — state stays NORMAL. Ch4 — AFE Ch5 — EKF

t=100ms — First CAN frame sent. Inverter receives SoC=30%.

0x355 frame: SoC=30, SoH=98. 0x351 frame: max cell V=3.65V, max charge A=56A. Inverter reads this and knows it can push up to 56A. It decides on 12A (solar limited). Ch6 — CAN builder Ch7 — PYLON protocol

t=2h — SoC reaches 80%. Cells now 3.35V average.

Kalman confidence high — CC and OCV agree within 1%. SoC=80.3%. Balancer detects cell #11 at 3.38V vs average 3.35V → bypass resistor activates for cell #11. Ch3 — Balancer Ch5 — SoC

t=3h20m — Cell #11 hits 3.63V. Approaching OVP threshold (3.65V).

Protection state machine enters WARN state. CAN 0x351 updated: max_charge_A drops to 20A. Inverter sees the new limit and reduces solar charge current. Cell #11 slows its rise. Ch9 — Protection SM Ch7 — Ichrg control

t=3h45m — Cell #11 still rising. Hits 3.65V. OVP TRIP.

State machine: NORMAL → WARN → OVP_TRIP. CHG FET opens in 500µs. Charging stops entirely. CAN 0x359 fault bit set. NVM writes event: OVP cell#11 3.652V Ibat=+8A T=27.3C ts=2026-04-06T14:22:11. Ch9 — OVP trip Ch6 — NVM log

t=3h45m + 30s — Hysteresis clears. SoC = 96%.

Cell #11 relaxes to 3.638V (30s open circuit). OVP clear threshold = 3.64V → met after 3s. But protection SM requires 30 consecutive clear ticks before re-enabling. After 30s: CHG FET re-closes. Ch9 — Hysteresis

t=4h — SoC = 100%. Inverter switches to float mode.

BMS sends 0x351 with max_charge_A = 0 (SoC ≥ 99%). Inverter stops charging. Pack enters FLOAT: tiny trickle current to compensate self-discharge. Cloud dashboard shows SoC=100%, SoH=98%, all cells balanced within 8mV. Ch7 — Float charging Ch10 — Cloud / dashboard

Notice what just happened: The BMS never needed to be "told" anything by a human. It measured, estimated, protected, and communicated autonomously for 4 hours. The inverter adjusted based on CAN data. The cells stayed safe. The logs captured everything. That is the complete system working as designed.

System Design Principles — The 10 Non-Negotiables

NEVER GUESS
Always estimate with confidence bounds. Kalman > open-loop CC.
HARDWARE FIRST
HW OVP fires in 500µs. SW is backup, not primary protection.
LOG EVERYTHING
Every fault needs a timestamp. NVM must survive power loss.
HYSTERESIS
No chattering FETs. 5°C band. 30s clear timer. Always.
DETERMINISM
Worst-case timing is the only timing that matters. No malloc.
COMMUNICATE
Tell the inverter before tripping. CAN warning saves load uptime.
BALANCE
ΔV > 10mV means one cell takes all the stress. Balance continuously.
PERSIST STATE
SoC must survive a power cut. Write NVM on every 1% change.
WATCHDOG
If firmware hangs for 200ms → both FETs off. No exceptions.
KNOW YOUR CELL
DCIR table, OCV curve, capacity — your algorithms are only as good as your characterisation data.
